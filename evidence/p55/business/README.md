# S9 四臂受控任务返工

在原 NovelFactory `55d8979b5361a4837701d762feacd83036096b11` 上，四组使用同一份 PostgreSQL 17.11 数据和工件快照，按预登记顺序各跑四次。每次取回三件实际 writer 候选，并按预登记的事实逐件验收。业务时间包含初稿、共同世界变更、判定、实际返工和读取最后采用的候选。有效吞吐按验收有效件数除以对应总秒数计算。[预登记与代码](https://github.com/SKYdayDUCK/NovelFactory/tree/ea4880e17416f6e610341abd5e4697d1ba454a5c/evidence/p55/business) · [Actions 原始运行](https://github.com/SKYdayDUCK/NovelFactory/actions/runs/43043290680)

A 对任何分支头变动均要求重做。B 检查对象写范围交集。C 检查依赖证书。D 同时检查证书与 S9 已记录的语义读依赖。A 在四轮中重做四个独立件。B、C 各保留四个因事实前置条件失效而过时的件。D 保留独立件，取回的十二件均符合这个固定金标。

初始三件 writer 任务物理执行一次，随后复制相同的 PostgreSQL 和对象存储状态，为十六个独立数据库分配同样的起点。按每一臂使其可单独部署所需的成本，表中的各轮均计入这三件的初始耗时和 token，分臂合计不能用作物理调用总数。物理调用为三个初始任务加二十八个实际返工任务，均经 NF prepare、ContextCompiler、AgentGateway 和幂等回放，交叉核对持久化的成功 attempt 与产物。四组共享的初始链路单次为 1.532418 秒。计时排除数据库克隆、迁移和账本验后比对。

原判定基准以相同应用 SHA 单独运行，每场景十二次判定延迟采样，九项原 S9 PostgreSQL 回归通过。新实验独立金标仍为三项，四轮旋转顺序仅为计时重复。合成 token 由固定本地规则对实际发送消息和收到的 JSON 计数。模型供应商外部请求为零，供应商 token、账单金额与文学质量均未测。该实验未发布任何正文。原始运行的 ZIP SHA-256 为 `f1939d1c14b18d35553a82e3ad858e67dc621fd8cfbc4e38902b9de74f2cf41a`。[Actions 原始 artifact](https://github.com/SKYdayDUCK/NovelFactory/actions/runs/43043290680/artifacts/13866896251)

分支的 `receipts/` 保存原始 `business.json`、`original-guard.json`、`regressions.xml`、`subject-sha.txt`、`registration.json` 和 `SHA256SUMS`。在该目录运行 `sha256sum -c SHA256SUMS` 可验证逐文件摘要。
