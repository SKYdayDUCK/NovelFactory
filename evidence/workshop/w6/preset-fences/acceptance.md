# Preset switching, admission limits and message revocation

An initially empty PostgreSQL 17.11 cluster was migrated through w006 and then w007. The final regression uses the current schema head. With Redis 8.0.2 available, run `python -m pytest tests -q` from workshop. The stored JUnit covers 38 tests, including the real stdio and Redis transport cases. Five cases exercise preset switching, reused and stale preview receipts, operator-owned staff, bounded provisioning, unresolved delegation holds and message origin revocation. One of these initializes w002 in an isolated schema with pre-existing addressed mail, upgrades through w006 and verifies that the immutable message, durable delivery and original employee tenure remain present. Legacy mail has no reliable connection digest. The new reader marks it unavailable while retaining the message and its delivery evidence.

Use `aw_preset_preview` followed by `aw_preset_apply` with the same SHA, expected revision and a stable operation ID. Removing a slot parks its original tenure. Re-entering that preset reactivates only a tenure previously parked by the preset engine. Independent employees, independently reassigned staff and existing cost holds remain in place. An employee reporting to an outgoing supervisor must be reassigned before applying the preview.

Set organization admission policy using `python -m agent_workshop.presets ORG EMPLOYEE_CEILING HELD_DELEGATION_CEILING ROLE_TEAMS_JSON_FILE`. The JSON file maps permitted role IDs to arrays of permitted team IDs within the registered organization's scope. These are operator controls. Decreasing the ceilings only limits new registrations or reservations. An unresolved held reservation continues to occupy a slot. No synthetic provider traffic or text quality judgment is attributed to these tests.
