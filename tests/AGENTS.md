# Tests 局部规范

本文件继承 [根规范](../AGENTS.md)，测试用于证明不变量与已知风险边界。

- 区分单元、契约、PostgreSQL 集成、故障、端到端场景和文学评测，报告实际覆盖层次。
- 继承的场景 ID 和 v2 新场景见研发计划；新增用例关联需求、失败模式与可观察结果。
- 并发、行锁、唯一约束、事务重试与恢复必须用目标 PostgreSQL 验证，内存测试不能代替。
- 时间采用显式故事时间与可控时钟；故障通过明确注入点重现，避免依赖不稳定的 sleep。
- 优先覆盖越权、丢回执、重复提交、过期代际、宏微重复效果、不同分支和未推进状态。
- 角色信息隔离要检查正文、证据、计数、错误与缓存命中，不只检查成功返回字段。
- 文学评测保存文本版本、评审证据和编辑裁决；不要把单个模型分数设为普遍质量真理。
- 不为纯文字更正补机械测试，也不为绿灯删除失败断言或未经解释修改黄金答案。
- 真实模型及外部调用成本明确受控；普通单元测试默认不依赖外部网络。
- 本包先运行 `python validation/validate_package.py` 和 `python -m unittest discover -s experiments -p 'test_*.py'`。
- 实施阶段再增加实际项目测试入口；不得把设计包检查报告为完整系统验收。

- R1案例A–H与37个验收检查见validation/r1_case_matrix.json；有限模型和负载算术通过不等于数据库并发或端到端通过。

参考：[11 测试计划](../docs/11_研发路线与测试计划.md)、[v1.1 场景](../baseline/v1_1/09_压力测试与端到端案例.md)。
