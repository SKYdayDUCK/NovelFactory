# R1 有限机制实验

## 范围与运行

[test_r1_mechanisms.py](test_r1_mechanisms.py) 是独立标准库参考模型，按可控顺序插入变更来检查有限失败模式；正式项目不得导入它。执行：

```bash
python -m unittest discover -s experiments -p 'test_r1_mechanisms.py' -v
```

模型只包含一个保留历史的线性分支、标量快照、单调 scope token、任务代际、不可变资格证书和命令回执。解释/活动计划变化可不产生世界 revision，但递增相应守卫。guarded 接受允许证书签发后发生无关 HEAD 前移；回执区分原 base、validation、实际 parent 和新 world_ref。STRICT_HEAD 作为对照仍检查精确 base。

## 17 个 probe 与反例

| 编号 | 检查内容 | 实验能排除的局部失败 |
|---|---|---|
| 01–02 | 两个互不相关命令共享 base 和资格采样点；guarded 都接受，strict 拒绝第二个 | 把无关 HEAD 前移一律当语义冲突 |
| 03 | 同一资源改变后旧资格停止接受 | 最后写入者覆盖已改变状态 |
| 04 | 两人分别离岗，共享“至少一人留守”约束 token | 只检查写实体造成 write skew；并列展示错误最终状态 |
| 05 | 空查询后新增桥上守卫，负向谓词范围变化 | 空结果没有行版本，错误证明“仍然不存在” |
| 06 | 注册项删除、重建，旧局部版本号可重复而 token 不归零 | ABA 导致旧资格误判有效 |
| 07–08 | 取消旧代禁止新提交；已成功原命令重试仍取原回执 | 迟到输出新生效、丢回执后重复效果 |
| 09 | 旧事实与旧 token 同切面冻结；变更后停止接受 | 展示“旧判断＋新 token”会误通过的 TOCTOU 反例 |
| 10–11 | 解释版本/当前计划选择改变阻断旧资格，固定旧计划仍可读 | WorldRef 未变便忽略解释和活动选择变化 |
| 12 | one-pin 批量与逐项 latest 对照 | 拼出任何历史快照都没有出现过的状态组合 |
| 13 | 排他过程前沿与固定旧 revision | 等待新接受后偷换 FIXED 所指世界 |
| 14 | 缓存保留内容时立即撤权 | 把缓存命中当作当前授权 |
| 15–16 | 批量内部仍检查角色 profile、GRAPH_READ 和平面 | 用外层 query_batch 绕过图权限或 ACTOR 的 BELIEF 限制 |
| 17 | 新 R1 青霜剑 D20 借改赠，保留旧 D25；D35 角色误信仍与 WORLD 分离 | 修订覆盖旧版或用客观盗窃自动更新人物认知 |

第 17 项仅保留“持有者”认知命题；借改赠影响的所有权认知、下游章节与计划失效仍需完整依赖服务处理，不能从这一项推断已经实现。青霜剑采用新夹具 D1 制造、D10 赠 P、D20 借 F、D30 被 V 盗走、D40 销毁，不混用基线 D12 夹具。

## 证据等级与未覆盖范围

本组可以观察这些有限输入及显式交错下的预期行为，不证明所有并发交错正确。作用域由可信测试夹具手工给出；未证明生产模板能推导完整正向/负向读集、约束组、实际写影响和消息通道覆盖。单分支整数序号只是本模型的祖先关系；真实服务仍要检查作品、分支、历史 epoch、版本 DAG、批准与证书来源。

没有 PostgreSQL、进程并发、锁等待、真实事务原子性、数据库崩溃、网络分区、MCP Host、外部模型或文学质量测试。缓存与授权只演示检查顺序，不替代角色/实体/时间/任务 grant 隔离验收。保留回执只在内存中观察，不证明持久 exactly-once；实际目标仍是幂等重试与一次正式状态效果。

全部业务案例 A–H 仍需按 [15 压测与验收](../docs/15_并发压测与端到端验收.md) 在服务实现后验收。本实验未提供 R1 业务种子数据，也未达到任何 Agent 并发规模、RPS、P95/P99 或成本目标。unittest 的运行耗时只用于确认实验执行结束，不作容量指标。
