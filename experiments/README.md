# 独立机制实验

这是设计阶段的有限状态模型与反例检查，**不是正式小说工厂实现**。正式模块不得导入本目录。它只使用Python标准库；实际运行记录见[验证报告](../validation/REPORT.md)。

在项目根目录运行：

```bash
python -m unittest discover -s experiments -p 'test_*.py'
```

## 两组模型

原 [test_mechanisms.py](test_mechanisms.py) 保留 18 项；新增 [test_r1_mechanisms.py](test_r1_mechanisms.py) 有 17 项。统一命令本轮运行 35 项全部通过。新增项、反例及限制见 [R1_NOTES](R1_NOTES.md)，涵盖依赖守卫、证书采样、批量切面、权限缓存和动态历史。正式业务与数据库测试仍待实施。

## 原模型检查的问题

- 同一命令丢回执反复重试是否只产生一次效果；同key不同payload是否拒绝。
- 候选处理失败是否保持所有观察到的内存状态不变；它只说明copy-on-commit模型，不证明数据库崩溃原子性。
- 旧代际、旧head和空查询范围变化是否使新的接受失败；已成功命令回执是否仍可取回。
- fork如何继承效果覆盖，多次文学呈现如何不再次扣资源。
- 三方意图6种到达顺序形成同一密封集合；负对照“先返回者赢”产生不同胜者。这并不证明真实语义裁决模型具有置换不变性。
- 排他frontier的相等端点、未知通道、后台影响如何阻断相关推进。
- 宏微终态相同但中间认知不同为什么不能判等效。
- 有界发生时间在区间内部不能伪造确定答案；角色未知响应不能回显隐藏事实。
- 中文、emoji、CRLF、组合字符的证据切片和规范化哈希是否按契约处理。

## 限制

TinyLedger无数据库、锁、磁盘、网络、完整权限策略或通用事件模型。取消、超时、Retcon和未知输出是有限夹具，有些检查仅展示必要不变量。所有这些结果都不能替代P1真实PostgreSQL双连接并发、进程中断和恢复，不能替代P2真实Host、模型调用和小说完整阅读。

实际语义裁决可能受意图排列影响，应在P2/P3单独做排列/重采样对照；本实验固定裁决输入集合，没有测量任何语言模型的质量或费用。
