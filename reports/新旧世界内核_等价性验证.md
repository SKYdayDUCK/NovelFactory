## 如何比较

原始代码由独立 Python 进程从冻结 Git 工作树导入。运行前核对原始 `src/`、`migrations/` 和模块来源，两个工作树中的新增测试文件逐字相同。B 执行前还比对 GitHub 上该提交的 79 个应用源码、迁移和依赖锁文件 Blob。每个执行臂先从同一 PostgreSQL 服务器上的迁移后空模板复制独立数据库，通过正式服务入口创建相同场景。冻结和 B 使用两个各自隔离、设置一致的 17.11 实例。两者启用页校验、fsync 和同步提交。没有在生产库上执行故障注入。

输入固定包括每个模块的 UUID 序列、测试凭据、任务时钟和 Python 哈希种子。任务租约、审批、证书与提交回执中的业务时钟相同。数据库分配事务、处理锁等待、触发约束并执行提交，outbox 使用真实数据库投递时钟。对 35 张应用表按主键排序，计算包含全部列和嵌套 JSON 的逐行长度前缀 SHA-256。由数据库记录的 `created_at`、`updated_at`、`processed_at`、`delivered_at` 四个物理时间列比较空值与非空值，其余时间和业务 payload 内的时间逐值保留。服务返回在序列化后直接散列，包含内部对象全部字段。错误比较 code、safe_message、retryable 和 recovery。

## 覆盖与反例

| 验收项 | 正例和拒绝反例 |
|---|---|
| 1. 世界状态与哈希 | 每个生成的 Revision 的完整 snapshot、state_hash、manifest_hash 参与逐表比对；修订推广调用完整重建并验证。 |
| 2. 世界身份与事件选择 | 比较 work/branch/revision、父指针、不可变历史、selection 和 revision_events 映射。两个不同地区的动作在同一故事时刻并发接受，保留实际父节点与原始基线。 |
| 3. 正式事件与效果组 | 比较原始事件、内容哈希、occurrence/event/effect_group/representation 身份。历史替换保留 occurrence 和 effect group；带重复效果键的替换被拒绝。 |
| 4. 角色认知及秘密 | 同一角色不同任务和故事时间的证据可见性、不可见与不存在的响应、缓存命中后撤销 grant、角色对旧证据的访问均有反例。 |
| 5. 资源守恒 | 三个独立 Agent 同时尝试从同一 100 单位账户转出 80，固定第一个持锁并观测另两个 PostgreSQL 后端确实阻塞，只接受一个。逐行比较全体资源、资源历史和正式回执。 |
| 6. 所有权与持有权 | 审核后的借予改赠与、历史事实、角色信念及随后持有权分别核对；同一物品竞争时后提交者得到依赖冲突。 |
| 7. 时态关系 | 同时发生的独立事件和较晚提交的较早故事事件均经正式请求；替换早期权属将破坏后续借出先决条件时拒绝推广候选。 |
| 8. 任务代际 | 完整比较 task_inputs、任务、执行、代际和 context 绑定；取消后旧请求不能提交或复用旧授权上下文。 |
| 9. Scope 与负向依赖 | 空 blocked_by 范围读到版本 0；另一事务插入 blocker 后原证书失效。比较全部 scopes、失效记录、持久化依赖和证书 token。 |
| 10. 证书、审批和解释器 | 比较审批主体、有效期、epoch、证书全部 payload 与准备响应；测试过期/未签发证书、兼容解释版本升级和旧证书拒绝。 |
| 11. 正式提交回执 | 比较接受返回及持久化回执，包括版本、事件引用、原始基线、验证切面、实际父节点及证书和提案引用。 |
| 12. 幂等与故障 | 在 nf_commits 安装测试触发器让 PostgreSQL 返回 P0001，检查事务前后全部 35 表。移除故障后成功；另在 after_commit 注入响应丢失并取回原回执。 |
| 13. Retcon 与发布保护 | 修复分支、独立审批、因果重审和推广完整执行。已发布跨卷引用受替换影响后要求对相关两卷重审，旧版发布物及原始引用保留。 |
| 14. 历史查询及因果影响 | 比较旧/新版本固定查询、compare 和 impact 返回。检查旧证据仅保留历史出处，被替换的 occurrence 版本不能成为新事实证据。 |
| 15. 派生可见性 | 先消费新消息再消费旧消息，水位不倒退；验证索引未到达时的 INDEX_PENDING、STALE，以及完成后的 READY、CURRENT 和授权复查。 |

三开关同时开启时，窄列查询命中 9 次、派生源元数据命中 4 次、修订审核元数据命中 3 次，稀疏 Scope 命中 78 次。76 次受控重放调用中有 23 次命中单事件后缀；其余 53 次回退包括未证明父版本 38、历史替换 6、非单追加 4、故事时间不严格递增 3，以及解释或规则上下文不匹配 2。这些是正确性测试的覆盖计数。业务负载上的命中率和收益需要使用 D 阶段数据。

## 复现

以下命令从候选工作树运行。环境需要可执行的 PostgreSQL 17、项目锁定的 Python 3.12 环境和完整 Git 提交历史。输出目录使用绝对路径，以便两个工作树共享比较结果。

```bash
set -eu
base=2c28acba6e1932657162c6e55b3288365ce3ea23
candidate_root=$(pwd)
results=$(mktemp -d)
frozen="$results/frozen-worktree"
testfile=tests/integration/test_scion_differential.py
export PYTHONHASHSEED=2411
git worktree add --detach "$frozen" "$base"
cp "$testfile" "$frozen/$testfile"
(
  cd "$frozen"
  PYTHONPATH="$frozen/src" NF_SCION_DIFF_FROZEN=1 NF_SCION_DIFF_EVIDENCE="$results/oracle" \
    python scripts/with_postgres.py --log-dir "$results/old-pg" -- python -m pytest "$testfile" -q
)
PYTHONPATH="$candidate_root/src" NF_SCION_DIFF_ORACLE="$results/oracle" \
  NF_SCION_DIFF_EVIDENCE="$results/candidate" python scripts/with_postgres.py \
  --log-dir "$results/candidate-pg" -- python -m pytest "$testfile" -q
```

原始冻结运行 6/6，通过用时 23.60 秒。候选内部同时执行全关与全开并读取外部冻结结果，6/6 通过，用时 44.49 秒。开发夹具曾在同一已推进分支上再次用旧 HEAD 准备严格请求，原始路径按预期返回 HEAD_CONFLICT；已将独立场景分配不同作品后重跑全部三臂。提交成功响应丢失与数据库事务回滚均保留为有效反例。

这些实验能够证明给定输入、可控顺序及所列字段的等价性，无法穷举全部未来模板、解释器版本、机器故障或任意事件组合。未知解释器、复杂因果、历史改写和无法证明前缀的输入继续依赖完整重放。默认开启任何开关仍需独立代码审查与单项性能对照。
