# B3 冷启动与命中率分析

B3 保持显式启用。未指定环境变量时，提案和接受沿用完整重放。部署 `NF_SCION_REPLAY=1` 可选择第一轮后缀算法，同时设置 `NF_SCION_REPLAY_LAZY=1` 可选择本轮实验策略。两个环境变量均在创建 Kernel 时读取，回退后需重启对应服务进程。

## 已定位的成本

第一轮的 1000 事件对照中，全量、三个开关全启的首写提案分别耗时 1593.78、2745.84 ms，连续接受则分别为 2589.28、898.30 ms。全启数值同时包含 B1/B2，不能单独归因。第一轮独立 HTTP 服务进程的容量实验中，普通混合 200 的后缀命中为 0/61，其中 41 次父证明不可用、20 次新增时间未严格晚于既有前缀。混合 500 为 0/151，其中 101 次父证明不可用、50 次时间不晚。只读压力没有调用该重放入口。[第一轮服务计数](Scion思路_并发优化实验.md)

实际服务的提案和提交分别从数据库读取权威的完整历史。原 B3 先检查完整前缀，再计算上下文、各事件内容摘要以及排序后的前缀摘要。缓存未命中时仍须运行原 reducer，随后还为提案的假设结果计算整个投影摘要并写入缓存。其他工作者无法继承本进程的证明。许多并发提案绑定同一旧父版本，同故事时刻的接受必须完整重放，三者共同限制真实命中。

## 本轮改动与边界

- 冷提案在完成原形状和时间审查后，先在至多 256 个固定长度证明中查找匹配的父投影摘要。没有候选就直接运行原 reducer，省去这次证明的事件摘要、排序和结果登记；若摘要可能匹配，仍要核对完整上下文、全部选中事件正文及父投影摘要。
- 新策略只在接受路径登记纯 reducer 结果。有效同刻或乱序新增仍完整重放；完整重放已经成功时，可以记住这次结果，在下一次严格晚于整个前缀的新增中再检查证明。Retcon、复杂因果、身份碰撞和跨边界效果仍走保守路径。登记发生在数据库提交前，回滚留下的纯内容摘要无法充当已提交事实；后续命中仍须从权威父版本独立读取、核验其全部输入。
- 进程重启或容量驱逐导致冷缺失。缓存不含事件体、快照、授权、收据或请求。数据库的授权、证书、固定 WorldRef、范围、解释版本和父快照哈希验证沿用既有业务路径。`replay_proof.cold_proposal_skipped` 与 `replay_proof.full_replay_seed` 是诊断计数，不加入 `replay.hit` 或重放调用分母。

## 正确性与恢复

26 个单元断言用例和 5 个真实 PG 集成用例通过。两种 B3 设置分别检查正文与投影篡改、时间并列/回退、规则和解释纪元、身份冲突、复杂因果及 Retcon。PG 用例验证同刻与早到的合法独立写先完整重放、之后严格递增才能命中，新的 Kernel 冷启动、历史证明被挤出后再向旧固定版本提案、提交前回滚与幂等重试，并用完整 reducer 对照持久化的实际快照。额外两个历史长度（20、100）分别用两对全量与本轮 PG 流程执行历史修订和随后带因果的追加；各自提案和接受均完整重放，收据、WorldRef、投影及 manifest 的配对结果一致。

复用冻结 dump 时旧任务租约可能已经过期。基准现从该固定任务的数据库记录读取 updated_at、lease_expiry、deadline，以 updated_at 和最早截止时间的中点作为两臂共同业务时刻。真实数据库、原时限字段、授权及过期检查照常执行。该时钟只存在于基准夹具，生产代码无时钟替换。

## 可复现入口

`benchmarks/scion_long_history.py --probe --b3-comparison off` 对照完整重放，`--b3-comparison legacy` 对照第一轮 B3，两个对照都关闭列与 Scope 优化。`--checkpoints 20 500 1000 --repetitions 3` 重复主序列，`--repair --checkpoints 20 100 --repetitions 2` 重复修订对照。`--profile-proofs` 独立记录证明摘要、条件审查、单事件后缀的时间；带计时包装的行单独处理。运行前用 `scripts/with_postgres.py` 启动 PostgreSQL 17，传入相同的 seed dump、两份代码目录、源码标识和独立结果目录。冷暖主序列对照、仪表分项及原始证据见 [S3 证据索引](../evidence/scion_round2/s3/summary.json)。

当工作负载主要由顺序、同一进程处理的长历史追加组成，可按单项开关试用。通用混合部署保留默认关闭。混合 200（一个 API 进程）与 500（两个 API 进程）的本轮实测命中与请求/Agent 完成率统一以 S5 配对服务矩阵为准；开放到达和长稳只读场景的直接 B3 调用分母为零。

## S3b 重复访问同一冷父版本

后续候选增设 `NF_SCION_REPLAY_PRIME=1`，同时依赖 `NF_SCION_REPLAY=1`、`NF_SCION_REPLAY_LAZY=1`。第一次遇到可严格追加、但未有证明的父版本，仍重放完整候选。后续再次遇到同父提案时，服务才尝试重放父版本的全部选中事件。原始正文必须与权威 selection 一一对应。父快照的事件摘要只用于还原生成父投影时的输入顺序；重放得到的完整结构和未经变换的摘要均须与数据库父快照及其 state_hash 精确相等。父证明还绑定原规则、解释版本、分支/历史纪元、创世输入及所有选中事件正文。任何精确匹配或可选计算失败都退回原完整 reducer。第一次取得证明并执行后缀仍支付一次完整父重放，之后命中已有证明才能真正省去一次全重放。

每个 Kernel 的缓存保存至多 256 条父提示，另有至多 2 个正在验证的父版本。同一父版本只允许 1 个验证者；其他提案直接走原路径，不等验证者。测试同时覆盖缓存驱逐期间的并发、数据库拒绝篡改不可变记录、真实 SELECT 返回自洽哈希但无法由原事件重放的异常投影、原错误优先级和意外异常释放验证名额。最终保护版本 41 项 B3 专项测试通过。

### OS 进程强杀、原请求接管与单条缓存驱逐

对完整重放、lazy、lazy+prime 各取同一数据库模板的独立副本。每个旧 Kernel 先正式提交第 4 笔，再对下一笔请求完成事务内业务写入；当实际执行进入 `before_commit`，控制进程发送 SIGKILL 并核对退出状态 −9。不同 PID 的新 Kernel 接管同一 PostgreSQL 数据库和同一对象目录。开始时证明、建证提示均为空。已提交请求返回原收据；第 5 笔尚未提交的事务已回滚。新进程用原证书和原幂等键重试后恰好新增 1 笔，再次重试返回同一收据。三臂的原请求摘要、两份收据摘要、最终 WorldRef、manifest、完整 reducer 对照出的持久状态以及随后 7 个固定版本提案的返回摘要分别相同。

每个 Kernel 的证明容量固定为 **1**。新进程先重试第 5 笔，在现在的版本提案一次，再对第 4 笔的固定版本提案 3 次，最后回到第 5 笔版本提案 3 次。仪表在实际证明表写入时读取被替换的键。对 prime 来说，两个版本的第二个提案都需要重新建立证明，各淘汰一个不同的旧证明；回到当前父版本时可观察到一次完整回退、一次付费建证和一次直接复用。旧进程在被杀前也观察到一次淘汰，但未提交结果未成为重启后的事实。

| 恢复进程 | 完整 reducer 调用 / 输入事件合计 | 未证实父完整回退 | 付费建证 / 直接复用 | 真实淘汰 | 计量操作合计墙钟 / CPU ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 完整重放 | 8 / 44 | 不启用缓存 | 0 / 0 | 0 | 447.34 / 282.60 |
| lazy | 4 / 20 | 4 | 0 / 4 | 0 | 351.49 / 251.40 |
| lazy + prime | 5 / 25 | 3 | 2 / 3 | 2 | 463.54 / 272.88 |
