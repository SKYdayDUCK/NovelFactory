# NovelFactory P1 独立审计收尾修复与 P2 前交接

日期：2026-11-10。**范围仅 P1 收尾修复**，不实现 P2。历史设计、`baseline/v1_1/`、正式事件协议、数据库迁移及原 P0/P1 报告均保留原貌。此文件用于新的代码审计，不能替代当次 Actions 测试日志。

## 审计风险、复现与修复

| 风险 | 修复前可观察失败 | 修改与回归目标 |
|---|---|---|
| A1 跨任务证据泄漏 | 同一 grant 曾收到任意 ContextBundle 的全文 artifact，会被 `Kernel.get_artifact(principal, work, ref)` 放行。原方法无任务代际/知识切面参数。 | `Kernel._check_artifact_read` 现在要求非 ADMIN 提供当前 `task_id + generation + context_bundle_id + world_ref + story_time + knowledge_cut`，精确匹配不可变 task input 和 context/read_cut，并校验任务活性、租约、授权 epoch、角色、actor 与 known_at。对象读取前后重复检查，以阻断撤权和取消后的迟到交付。管理员保持原受 `READ` 和 work 约束的只读能力。 |
| A2 状态查询额外载入事件全文 | 原 `_sample()` 无论 STATE/图查询/上下文编译，均查询选中历史所有事件的 `payload`。9000 条合成选中历史的测试记录到错误事件读取。 | 只对 `WORLD`/`SIMULATION` 的 `TIMELINE` 且包含 `FACT` 需求的查询或批次读取事件正文。状态/图/关系时间线/计划/角色认知和 Context 编译只读取固定 `revision.snapshot`；仍检查原有 `max_scan` 限额。多查询项共用一个固定 read_cut。 |
| A3 慢速请求体占据连接 | 请求体分块 `receive()` 没有总体时限；攻击者可持续发小块并占用 ingress slot。 | 增加默认 5 秒绝对 body deadline（不能用持续涓滴续期）、1024 分块上限（可调）、408 `REQUEST_TIMEOUT` 脱敏错误、异常路径释放 ingress。保持 `max_body_bytes`、origin 限制、请求量背压/速率、DB 短事务/连接预算。环境变量：`NF_BODY_READ_TIMEOUT_SECONDS`、`NF_MAX_BODY_CHUNKS`。 |
| A4 缺少持续集成 | 原项目没有 `.github/workflows/`。 | `p1-integrity.yml` 两个独立 job：设计 Schema/单元及 HTTP 边界；PostgreSQL 17 + Alembic + `pg_dump`/`pg_restore` + 全量真实集成/并发/故障/恢复测试，自动上传 JUnit、JSON、原始日志和恢复证据。 |
| A5 开发交接不明确 | 根 README/AGENTS.md 保留早期“只有设计，无实现”的历史描述。 | 更新真实 P0/P1 工程状态、阶段边界、测试和 CI 入口；历史设计正文作为显式归档材料保留。 |

## 可核对的本地证据

执行环境：Debian 13 amd64，Python **3.13.5**；该临时容器没有 Python 3.12 和 PostgreSQL 17 二进制，且无法解析外部包仓库 DNS。因此本地只进行了可执行的纯 Python 测试；**不能声称本地验证了 PostgreSQL 17 或 Python 3.12 的正式构建**。CI 工作流由 GitHub 托管环境分别运行正式 Python 3.12 和 PostgreSQL 17。结果必须以本次 CI 的实际 jobs/status 为准。

- 修改前：`PYTHONPATH=src python -m pytest tests/unit/test_audit_artifact_security.py tests/unit/test_audit_http_boundary.py tests/unit/test_audit_query_history.py -q`；**8 failed / 1 passed**（未具备安全绑定/慢 body deadline/按需事件加载）。原始失败记录 [`audit_pre_fix_9_regressions.log`](evidence/audit_pre_fix_9_regressions.log)。
- 修改前现有单元+契约：`PYTHONPATH=src python -m pytest tests/unit tests/contracts -q`；**126 passed**。日志 [`p1_baseline_unit_contract.log`](evidence/p1_baseline_unit_contract.log)。
- 修改后上述新增反例：**9 passed**。日志 [`audit_post_fix_9_regressions.log`](evidence/audit_post_fix_9_regressions.log)。
- 修改后单元+契约（包含新增反例）：**135 passed**。日志 [`audit_local_unit_contract.log`](evidence/audit_local_unit_contract.log)。另含 admission 入口时为 **142 passed**，日志 [`audit_local_unit_contract_admission.log`](evidence/audit_local_unit_contract_admission.log)。

**大历史性能验证口径**：9000 条合成 selected IDs 时，STATE 与仅 `STATE_ASSERTION` 的时间线及对应 batch 均观测为 **0 次 `events` 完整正文读取**；需要 FACT 的时间线/批次仍**精确执行 1 次**版本事件加载。该合成测试是调用路径/SQL 数量的确定性验证，不是 9000 条正式 PostgreSQL 已接受事件的吞吐测量。真实 PostgreSQL 用新 `tests/queries/test_audit_regressions.py` 对状态/时间线/批次的返回值等价性与 SQL 路径检查；历史 FACT 仍由原 `tests/queries/test_history_queries.py` 回归。

## 与原 P1 基线的边界

- 不修改 `contracts/` 原始 Schema 正反例；`Kernel.get_artifact` 不是外部 HTTP 工具，调用签名新增可选的上下文证明参数；对于非管理员，这些参数变为必需，属于有意收紧的应用服务访问契约。
- 不修改领域 reducer、WorldRef/时间语义、正式提交 `STRICT_HEAD`/`DEPENDENCY_GUARDED`、事务/幂等键、数据库 schema/迁移和外部 HTTP 接口输入 DTO。
- 原 `main` P1 实现提交和历史设计永久保留。当前修复提交作为新的 **P1 收尾完成检查点**，下一会话应从该 SHA 继续开发，不应直接修改原基线提交。

## 仍需独立审核与 P2 前风险

1. 需要检查 GitHub Actions 当次运行确实成功，尤其在 PG17 版本/授权、恢复子流程、跨进程并发测试等方面；不能把仅有 workflow YAML 当作验证通过。
2. `max_scan` 和完整 JSONB 快照仍使极大版本受存储体积限制，本次只移除了无关事件正文载入，不声称 9k 已接受事件的数据库吞吐已通过；P2 前可按目标作品负载追加真实性能档位。
3. HTTP 请求体超时是应用层 ingress 限时，部署仍应设置反向代理连接/首字节速率保护、Uvicorn 连接数及请求头上限。没有实施分布式边缘代理或 Host SDK。
4. GitHub Actions artifacts 保留 90 天；重要审计记录应另行归档，不依赖长期可访问的 CI 临时附件。

**准入判断**：只有当前修复的 GitHub Actions 全量 Schema、单元及真实 PostgreSQL 集成/并发/恢复 job 都成功，才能把本轮收尾标为 PASSED。P2 在本次任务中始终保持 NOT_STARTED。
