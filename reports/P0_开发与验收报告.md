## 3. 技术决策

### 契约维护与兼容

选择 Schema-first，原 JSON Schema 是唯一维护源。Pydantic 类型从同一 Schema 构造，入口同时执行完整 Schema 条件校验；wheel 内携带生成包，不依赖外网解析引用。该选择与原 README 建议的未来 Pydantic-first 有差异，已写明原因：避免迁移时丢失 oneOf、条件必填、禁止额外字段与版本规则。原 2.0 / 2.1 载荷保持不变，旧 strict 接口不会被悄悄升级为 guarded。

新增 `kernel.schema.json`、`commands.schema.json`、`http.schema.json` 只封闭本轮实现所需的命题/输入清单、命令与传输包装，复用原 WorldRef/Event/StoryPoint 等定义。`python -m novel_factory.contracts.generate --check` 必须与维护源逐字生成结果一致。数据库 JSON 记录保留版本及内容哈希，领域对象通过明确映射读取，不由 ORM 自行造另一套公共类型。

### 时间、修订和读取

故事点使用整数 tick 与 phase，拒绝浮点和越出 JSON 安全范围的整数；关系使用半开区间。`world_revision_id` 表示编辑修订，不是故事发生时刻；`branch_seq` 仅在分支内排序。BOUNDED/UNSPECIFIED 原契约保留，不推定 earliest 就是真实时间。无法证明高影响效果生效边界时拒绝。

固定读取在一个不可变 WorldRef 上回答；latest 仅在开始解析一次；KnowledgeCut 另控制 WORLD/BELIEF/PLAN、人物和获知截止。未知、已知无值、未求值、不适用、索引落后分别保留。角色权限取数据库当前 grant 与原角色 profile 的交集；调用者输入视角并不授予访问权。初始化全知控制面使用显式 control_operator，不扩大原 chief_editor 或 character_actor 权限。

### 作用域与并发边界

正式写路径以分支 HEAD 为原子提交点。服务登记实体、负向谓词范围、资源约束、规则、授权、解释、覆盖及封闭控制面冲突组依赖。P0 不声称已证明任何高级守卫安全；P1 的证书、并发竞争和反例有独立实际验收。世界后台跨区演化、任意自由语义依赖和联合行动裁决保留为后续范围。

负载模型严格区分：逻辑 Agent 数、HTTP 工具请求每秒、SQL 语句每秒、成功世界 revision/事件/效果每秒。10/50 Agent 是本轮初步服务负载，不代表需要 10/50 数据库连接。默认 API 池 8、worker 池 4、维护预留 16，总预算 28；测试 PostgreSQL max_connections=60。每个池 overflow=0，启动时校核总进程预算。思考/模型等待不得持有事务或连接。

## 4. 实际环境与证据

```bash
uv sync --locked
.venv/bin/python scripts/clean_install_check.py
```

## 6. 问题、限制与阶段结论

环境启动曾因 Unix socket 权限与会话网络隔离失败，改用同会话 TCP 数据库后验证通过。初始 editable 安装早于源码产生，已重装并以独立 wheel 检查排除路径偶然性。

原青霜剑与 R1 剑例有不同时间线，分别保留，未为了统一测试而改写 D12 与 D20。白桥初始粮运 100 袋保留，额外储备账户和岗哨明确标为并发约束测试的合成扩展。原全部 60+37 业务矩阵仍是设计基线，不在 P0 批量改成 PASSED。

P0 八项要求已满足，可以进入 P1。Docker 执行、外部真实模型 Host 和大规模长期性能尚未验证，不影响本阶段环境与契约基线结论，也不能作为已具备能力宣传。
