# P5-05 角色自主行动与有限滚动计划

集成用例以三个分别授权的角色进入同一场宴会。A 因自己的动机选择缺席，B 等待已获准的消息，C 独立行动。三份意图密封入库，联合裁决产生候选变化。Kernel 正式接受后产生一个位置关系事件，卷纲由与该次世界接受绑定的屏障唤醒。重新领取卷纲任务时冻结的是该屏障对应的 WorldRef。

管理员可通过 RollingPlanning.enable 为一卷选定原始参考线与未来 K 场（1 至 32）。角色决策不能写入参考线。卷纲根据已接受的事件请求 ChangePoint，独立规划任务提交 WindowPlan，总编根据精确的 ChangePoint、候选修订与窗口写入同意或退回。采纳事务重新检查任务租约、grant、策略与最新审核，只替换本卷当前规划指针，并保留原始引用。未来窗口以现有计划中的已排期节点为界，禁止更改槽位和窗口外节点。

授权的 MCP 连接分别提供 nf_change_point_request、nf_rolling_window_submit 和 nf_change_point_review。具体可见工具取决于当前任务的角色、冻结技能和服务端 grant。规划提交或批准均不增加世界事件。已绑定规划的工作在重领或重试时会重新验证已有约束。

## 复验

在 Python 3.12 依赖已安装、PostgreSQL 17 工具可用时运行：

```bash
uv run --no-sync python scripts/with_postgres.py -- python -m pytest -q tests/integration/test_p5_rolling.py tests/integration/test_workflow_plan_fence.py
```

[机器回执](../evidence/p5/story/banquet.json)记录原始引用、窗口、ChangePoint、总编意见与正式接受的 WorldRef。宴会中的行动与文学选择为确定性验收输入，调用数按实际测试通道记录。该用例在有限重规划采纳处取样，表内仍为 RUNNING 的测试任务不是活跃模型进程数。
