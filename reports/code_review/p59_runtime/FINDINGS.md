# Runtime extension review register

The baseline is the product published by PR #32 at `434840593179e6c1faa6b7aeca3d7d747644506d`. All seven prior fixes were present. Previous issue IDs, implementation paths, immutable audit history and the focused regression runs are in the [entrypoint review](entrypoints.md) and [baseline record](BASELINE.md).

| Scope and classification | Trigger and effect | Disposition, evidence and rollback boundary |
| --- | --- | --- |
| Role tools, P2 confirmed | A local static-role caller could enter a basic tool below the adapter's frozen tool ceiling. Unbounded stdio submissions could also exceed available workers. | Bound local agent, MCP and CLI calls share authorization, domain errors, use cases and audit scope. HTTP continues to use the same domain/query services with its own wire authentication. Concurrency is bounded per binding. Direct entrypoint and cancellation tests cover both behaviors. See [EXT-ENTRY findings](entrypoints.md). |
| Task claim and wake, P1 confirmed | Narrowing a grant to one branch could leave older queued work eligible. Suspending a task after a semantic read could lose the observation when a new generation claimed it. | Recheck the grant and its branch under lock, preserve semantic observations at wake and claim, and reject conflicting work as STALE. Keep the checks in the transaction when reverting unrelated scheduling changes. See [SCHED-01 and SCHED-03](SCHEDULER.md). |
| Execution and provider resources, P2 confirmed | Parking a dependency could retain the old dispatch slot. Empty pools retained their last thread target, a transient SQL failure could end the loop, and repeated pre-send quota losses could immediately compete again. | Release only the matching slot. Shrink quiescent workers, reconnect with bounded backoff and drain on stop. Record a bounded cooldown for repeated, proven-unsent refunds. Lease, amount, cancellation and UNKNOWN fences retain separate authority. Migration 0022 rejects a downgrade while a live timer protects a task. See [scheduler report](SCHEDULER.md). |
| EXT-DB-01, P1 measured | In a 2,000-task mixed queue on PG17 the first supervisor claim exceeded the original 15 s statement timeout. PG could combine jobs with grant policy/epoch peers before equating each job's task PK. Even adding a redundant scope guard left both repeated trials above 15 s. | Keep the zero-or-one job lookup correlated with its primary-key task. The candidate completed the same prepopulated selection in 296.994 and 391.768 ms. The 100-task ABBA test selected the same task four times and showed no consistent small-queue latency improvement. This SQL change can be reverted independently of the cooldown filter. [Plans and timed observations](../../performance/p59_runtime/raw/dispatch/) · [Selector equivalence](workflow-load-review.md) |
| EXT-DB-02, P3 measured | Every fresh reservation performed four aggregates over the same indexed Attempt history while task and budget locks were held. Static role-tool discovery also reread the same task/grant/input rows within one transaction. | The reservation query now calculates money and tokens in one snapshot, with identical refusal order. Discovery reuses the validated rows inside the transaction. The scoped reductions were 15 to 12 and 19 to 9 SQL statements per operation respectively. Each query optimization is separately reversible. [Reservation A/B](../../performance/p59_runtime/RESERVATIONS.md) · [Role discovery](entrypoints.md) |
| HTTP batches, P3 measured hypothesis, rejected | Repeated contract validation in an HTTP batch appeared to inflate service time. An alternate path reduced measured validation time but did not improve the complete request under the paired workload. | Retain the current path. The candidate patch, schema tests and alternating timings are preserved for independent reproduction. [Batch experiment](../../performance/p59_runtime/http-batch/README.md) |
| Native platform, P1/P2 confirmed | POSIX-only imports blocked Windows startup, POSIX file modes could not enforce a private ACL, process cleanup depended on the root PID remaining alive, and normal Git Windows checkout altered frozen migration inputs. An idle loopback client could delay shutdown on WinSock. | Use verified handle ownership and ACLs, NTFS publication and file locking, job ownership of children, checkout attributes and an explicit socket-reader wake. Native Windows and Linux receipts include real failures preceding the fixes. [Platform register](PLATFORM.md) |
| Formal authority and cross-service recovery, reviewed | Context sampling, delivery checks, accepted changes, Workshop delegation and human review each protect different versions or trust relationships. Removing a repeated check across two transactions could admit revoked knowledge or settle an obsolete delegation. | The common boundary is the use case. Keep external Workshop authentication and response witnesses, final dependency validation, and durable idempotency receipts. The independent upgrade, replay, Redis outage and paired recovery runs exercise both databases. [Workshop receipts](raw/workshop/README.md) · [Recovery matrix](RECOVERY_MATRIX.md) |
| World/history and object storage, P3 architectural risks | A deep `DynamicAgentService.history` traverses linked revisions and objects, and historical queries, bundle construction and pipeline advancement can pay verification/serialization costs. An accepted write still serializes its scope/version changes in its original transaction. | Retain the historical multi-scope batch upsert, fixed read cuts, final delivery checks and immutable revisions. The cold/warm HTTP phase traces record sampling, delivery, query and replay separately. No generalized replay cache or mutable cross-role cache was introduced. Scion's separate draft remains independently scoped. [Prior and current review](entrypoints.md) · [Measurement definitions](../../performance/p59_runtime/METHOD.md) |
| Scheduling beyond tested fairness and throughput, open risk | A branch ticket can remain eligible after its supervisor exits. Global selection, per-budget locks, DB and storage demand, aggregate independent process pools and slow synchronous providers can dominate a larger installation. Priority inheritance, arbitrary event callbacks and general preemption have no implementation. | Existing durable weighted arbitration was exercised at two levels under a restart, and two live books were exercised under backlog. No claim of bounded wait under arbitrary competing arrivals or automatic replay of a sent provider attempt. [Fairness and recovery](RECOVERY_MATRIX.md) · [5,000-agent scope](../../performance/p59_runtime/METHOD.md) |

The immutable world timeline, generation, execution lease, logical result and provider Attempt remain distinct. The leased result of an agent does not publish a world change by itself. A read stability run exercises service lifetime and authenticated queries; a workflow drain exercises task creation, admission, sleep/wake and durable output. Original HTTP overload remains an independently failing historical gate tracked by [Issue #13](https://github.com/SKYdayDUCK/NovelFactory/issues/13).
