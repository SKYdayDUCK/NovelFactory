# Durable dispatch and recovery audit

A project supervisor uses NF's existing PostgreSQL task, workflow wait/edge, execution lease, runtime permit and Attempt tables. A committed event wakes the scheduler through LISTEN or the Redis transport. A new listener begins with a scoped SQL reconciliation. A lost hint delays scheduling until the next scan. The provider response stays attached to the original Attempt.

| Finding | Reproduction and impact on the P5.9 baseline | Change and evidence |
| --- | --- | --- |
| SCHED-01, P1 | An already running task reads the sword lifecycle, releases its lease to wait for another task, then the sword is destroyed. A wake or later claim could issue a new generation and discard that semantic observation before a scanner created a conflict case. | Reuse the semantic dependency guard at wake and again when claiming a woken task. A conflicting generation becomes STALE. Tests exercise both orders without an intervening conflict scan. |
| SCHED-02, P2 | In a work limited to one dispatch slot, the worker durably parks on a dependency while its supervisor slot retains the old expiry. The ready producer cannot use the slot until release or expiry. | Delete only the parked execution's exact slot in the same transaction. The existing deletion trigger notifies other supervisors. The guard against unresolved PREPARED, SENT and UNKNOWN calls still runs before parking. |
| SCHED-03, P1 | Ordinary kernel claim qualified the grant for the work but selected queued tasks by principal/grant without applying the grant's current branch list. A legitimate branch narrowing left old queue entries eligible. | Authorize under a locked grant and use its branch scope before queue ordering. The contract fixture queues two previously permitted branches and selects the branch still assigned. Woken jobs also recheck the wait's grant epoch before issuing the next generation. |
| SCHED-04, P2 | Adaptive admission held its last target after an idle interval and retained the entire executor. On native Windows, Linux-only memory sampling made every adaptive resource sample unavailable. | Zero backlog and inactivity across two sample periods relinquish slots. A quiescent used executor shuts down its native workers. Fresh submissions allocate workers on demand. Windows reads native memory and CPU counters; the platform-gated test has a separate Windows result. |
| SCHED-05, P2 | The service reconnected its psycopg listener but an operational exception from the SQLAlchemy scan/future could terminate the daemon. Service shutdown also had no drain signal for already sent provider work. | Reconnect with bounded backoff after SQLAlchemy operational/pool errors, rescan durable state, and retain admitted work. A normal stop allows sent requests to finish and fences new admissions at the next scheduler iteration. |
| SCHED-06, P3 | Model backlog telemetry excluded every task with a previous Attempt. Quota races with a refunded, proven-unsent reservation already allow re-enrollment. The monitor hid those eligible jobs. | Use the dispatcher's durable unsent exemption in the backlog estimate. Late quota clamp, refund, capacity reopening and exactly one actual send are exercised on PG17. |

The initial assertions for both SCHED-01 interleavings, SCHED-02, and idle target shrink failed on the baseline. The final verification uses real PG17, separate connections, lease generation fencing, a synthetic HTTP provider and the daemon's normal serve loop. The cases and timings are in [claim and wait results](raw/scheduler-claims.xml), [service results](raw/scheduler-service-linux.xml) and [spending and quota results](raw/scheduler-spend-linux.xml). The sets overlap.

## Runtime boundaries

| Condition | Persistent state and recovery |
| --- | --- |
| Agent dependency | A bounded AND/OR group parks at BLOCKED with no active lease or dispatch slot. Completed events must identify the accepted predecessor and its current generation. Recovery deduplicates messages in Inbox and checks the grant epoch, plan guard, semantic observations and unresolved Attempts. |
| Review waiting on a person | The existing WAITING_REVIEW and editorial decision records hold the result. Explicitly authorized acceptance or rejection decides the outcome. The review does not hold a model slot while awaiting that decision. |
| Local or provider quota | PostgreSQL admission, work/role limits and runtime permits control eligibility. A proven unsent reservation can be retired without charging. Provider limits and budget are checked again before the external send. |
| Crash after send | The ledger retains SENT or UNKNOWN. Lease recovery fences the old worker. Provider reconciliation can resolve the original Attempt. A missing reply alone does not issue another attempt. |
| Expired dependency or cancelled prerequisite | The existing terminal propagation uses the dependency mode and task deadline. Repeated notifications remain idempotent. |
| Service restart | A listener subscribes before scanning. PostgreSQL retains the durable task/wait/Attempt state; Redis signals cannot create authority. A listener failure or transient database operational error after startup retries in at most five seconds between failed connection attempts, in addition to connection/statement timeout. |
| Graceful service stop | SIGINT, SIGTERM on Unix and console SIGBREAK on Windows stop scheduling and drain admitted work. A hard kill on either platform uses lease-based recovery. Startup authentication and database configuration errors still fail explicitly. |

The existing queue weights and eligibility algorithm were retained for this change. The default project executor has two execution slots. An operator can enable adaptive scheduling with `--adaptive --workers N` (up to the processor's ceiling). `--db-pool-size` controls the parent pool independently, defaults to five and allows 1–20 connections; small pools can exert backpressure. Count one extra session per LISTEN process and one per spawned compute worker when budgeting the whole installation. Model wait uses a bounded executor slot while a synchronous provider request is outstanding. Cooling an idle pool does not interrupt a host or settle its Attempt. A Windows supervisor can receive Ctrl+Break through its console process group; Windows process termination APIs perform a hard stop.

General arbitrary external-event matching, a universal persisted delayed-retry timer, provider callback resumption and priority inheritance are outside the implemented wait types. The stored AND/OR graph detects cycles on insertion and exposes closed or expired prerequisites. Resource admission distinguishes an eligible queue, an executing lease and a sent provider request. The bounded service tests here establish task semantics, separately from system capacity.
