## Findings and changes

| ID / severity / class | Trigger, location and effect | Decision and evidence |
| --- | --- | --- |
| EXT-ENTRY-01 / P2 / confirmed authorization inconsistency | Basic `McpRuntime` methods already checked grant, lease, context, generation and dynamic assignments. Their static path relied on the stdio adapter for the role/skill tool ceiling. An in-process host had no common contract for invoking a bound tool, recording its result or identifying a failed call. | Added `application.bound_tools.invoke_bound_tool` and used it from MCP and a one-shot local CLI. Every basic role operation now intersects the frozen tools and capabilities in its own transaction for static and dynamic assignments. Existing operation receipts still own idempotency. The same provisioned character queried a fixed BELIEF cut through HTTP, MCP and local calls, replayed one candidate through local, CLI and MCP, and received matching task-cancel errors. |
| EXT-ENTRY-02 / P2 / measured SQL overhead | `McpRuntime.available_tools` reloaded the same immutable TaskSpec and AGENT_INPUT rows and requalified the same live grant twice in one transaction on the ordinary static-role path. | Discovery reuses rows already checked in that transaction. External Workshop authority is refreshed outside the transaction and revalidated on return for dynamic roles. No cross-request authority cache. Two 20-call batches per version returned all four expected tools every time. Each baseline discovery issued 19 SQL statements, each candidate issued nine. |
| EXT-ENTRY-03 / P2 / confirmed resource limit omission | The former stdio adapter submitted every concurrent discovery or invocation to a thread pool with an unbounded submitted-work queue. The database pool capped connections downstream. | Each binding permits up to two operations, bounded by its pool. A saturated call returns `BACKPRESSURE`. An SDK cancellation retains the slot until the worker finishes. A deterministic one-slot test held a worker across client cancellation, observed pressure on the second request, and verified capacity recovery on completion. |
| EXT-ENTRY-04 / P3 / confirmed resource lifetime | Failed authentication during `runtime_from_config` constructed a DB pool outside the server's eventual close scope. | `interfaces/bindings.py` closes the pool on failed runtime construction. Successful callers continue to own and close their runtime. |
| EXT-ENTRY-05 / P2 / confirmed resource lifetime | An independently hosted stdio MCP binding held the startup authentication connection in its pool while waiting indefinitely for input. Multiplying independent processes multiplied idle database sessions. | An event-loop deadline retires checked-in connections after 30 idle seconds by default. The dedicated process arms one deadline at startup and extends it when its last operation finishes. Active operations retain their admission slots through cancellation. The callback only disposes an exclusively owned engine when there are zero checked-out connections. Embedded servers leave the shared Kernel pool with its owner. |

The standalone MCP SDK regression observed one authenticated child using PostgreSQL 17.11 with a one-second test idle period. Its startup session and each later hot session disappeared from `pg_stat_activity`. After each of three reconnects, four hot calls reused the same backend PID. A grant revocation during the final idle period produced `VIEW_DENIED` on the next call. Two executions measured median reconnect/hot round trips of 152.15/66.42 ms and 54.27/24.83 ms. Each sampled three reconnects and 12 hot calls under shared machine load. The full entrypoint group passed 12 cases on the second execution, including the embedded-owner and checked-out connection guards. ## Traced paths and retained decisions

| Path | Authority, transaction or transport decision |
| --- | --- |
| HTTP, local kernel, and MCP role query | HTTP authenticates Bearer credentials and applies ingress, auth and operation budgets. Both the general HTTP query and the narrower role operation call `WorldQueryService.batch`. A bound role also verifies lease, frozen manifest, knowledge plane and authorized lookup set. Distinct payload shapes carry these different caller rights. |
| Local CLI, local agent and MCP | The CLI reads a private server binding and arguments from stdin. It invokes the same application tool dispatcher as MCP. The original wire schemas still match all 98 registered interfaces and examples. Business receipts and audit scope come from the application. The audit channel distinguishes local and MCP invocations. No additional server or loopback HTTP request is involved. |
| Workshop to NF | Workshop authentication joins enabled installation, binding and expiry. A delegation records organizational commitment before contacting the peer. `workshop/reconcile.py` durably fences the operation, contacts the authenticated peer between local transactions, and validates its receipt before settlement. NF's `workshop_skills.py` rechecks delegation, task generation, principal and grant against the returned witness. These are distinct service/database authorities. |
| Creative Harness | Frozen context and plan/review authority are checked in the use case. `creative_review.py:decide` binds decisions to the reviewed draft, evidence and generation. `review_independence.py` uses an independent reviewer commitment from Workshop. The tool dispatcher cannot turn model output into an accepted world change. |
| Query, dependency and world writes | `queries.py` authorizes the fixed task and revision on sample and again on delivery. The existing guarded acceptance test covers ordered scope changes plus replay. Moving checks outside that final transaction would change their meaning. |
| Scion compatibility | Inspected compatibility commit `75276a791294d4b17035aead4e33352e865e01aa`. Its optional `ReplayProofs` caches bounded reducer digests with interpreter, genesis and revision witnesses. Separate column/scope options affect different operations. These changes would touch world acceptance and replay outside the measured discovery bottleneck. No Scion implementation was imported. |

Historical PERF-01 remains open. `DynamicAgentService.history` reads the linked event and revision chains, checks each object, and returns the complete history. SQL, object verification, response size and read-transaction duration still grow with chain length. A bounded paging contract needs a pinned head and tests across concurrent version changes. The discovery benchmark contains no measurements of this operator history endpoint. [Original issue and scope](https://github.com/SKYdayDUCK/NovelFactory/blob/1de471076b8fb4240f95ff8033c60db34c187404/src/novel_factory/application/dynamic_agents.py#L628)

## Repeating the frozen Linux full suite

The audit runner starts two independent PostgreSQL 17 instances and a private Redis server in the same process namespace as pytest. It sets the NF and Workshop admin URLs to distinct PG clusters, exposes the checkout's own environment to subprocesses, and writes JUnit, S6 results and service logs beneath the selected output directory. Supply the runner from this revision when measuring an older checkout. Its `--redis-server` option accepts the installed server executable. For the extracted Redis 8.0.2 Debian packages used here, `--redis-root` accepts the directory containing `usr/bin/redis-server` and `usr/lib/x86_64-linux-gnu`. A focused run against frozen main exercised the S6 engineering comparison successfully through this runner in 33.75 seconds. [Linux audit runner](raw/native_full.py)

Run these commands from each target checkout. The locked environment is per checkout because the real SDK launches child Python processes that import the installed runtime. The root suite is under `tests`. The independent Workshop suite has its own qualification receipts.

```sh
uv sync --locked --group dev
uv pip install --python .venv/bin/python --no-deps ./workshop
.venv/bin/python "$AUDIT_RUNNER" --pg-bin "$PG_BIN" \
  --redis-server "$REDIS_SERVER" --output "$RESULT_DIRECTORY"
```
