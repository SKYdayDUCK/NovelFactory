## 2. 建议独立审核顺序

1. **先确认交付身份。** 连接器读取 PR 与不可变提交，核对父链、Tree、关键源码；确认 Draft 状态和目标分支。把下一步测试实际使用的 SHA、环境、依赖锁和命令另行记录。
2. **核对证据来源。** 打开对应 Actions，确认 workflow、event、head SHA、attempt、job 结论及 Artifact 身份；下载原始 Artifact，与 GitHub 提供的 ZIP digest 和仓库索引比较。不能只对同一个本地文件自算哈希后宣布来源可信。
3. **先查可信内核反例。** 对照下节源码与测试，重点审权限/故事时间、原子接受、效果身份、旧回执、来源引用和恢复。运行 Schema/单元/契约，再运行完整 PostgreSQL 回归；不能因业务夹具结果正确而省略反例。
4. **独立重跑容量。** 保留原逻辑任务数、正式效果数、读写比例、热点、到达目标、5次/30秒重试、2秒队列等待及总池8。分别看首试、实际发送、最终业务和重复回执；失败退出与背压均保留。
5. **实际恢复再审升级。** 执行隔离 PITR，核对目标提交、排除后续提交、对象和原回执，再验证 UNKNOWN/代际。随后审兼容包和模型路由的权限、CAS、证据损坏与并发幂等反例。
6. **单独决策合并范围。** 有限工程能力、未达到的容量目标、真实模型与文学评价分开签结论。若先接受工程能力，PR 描述必须保留容量失败和适用边界；本轮不替审核者批准合并。

**备份/恢复连接配置有明确的兼容性收紧：** URL必须给出单一TCP host、显式port、user和database；仅允许单值`sslmode/sslrootcert/sslcert/sslkey`查询选项。省略端口、socket/多host、连接串形式database或不支持参数会被拒绝；存在`PGHOSTADDR`、`PGSERVICE`、`PGSERVICEFILE`环境路由时返回`BACKUP_TARGET_AMBIGUOUS`。这是为了确保Python校验目标与libpq实际工具目标相同，不是P0/P1世界语义变化；服务不会静默修改父进程环境。一般Database连接不因此整体改为该有限接口。[24项连接目标反例与33项联跑证据](../evidence/p3_p4/backup_target_validation.json)

在线备份在数据库切面之前固定运行时代码/Schema/权限资产的整个成员集合和哈希，结束复核；部署变化会拒绝COMPLETE。恢复前准备与备份对应的代码/资产，空数据库和空对象目录，恢复期间停止入口与消费者。内部TaskService结算/恢复方法不是新的公开鉴权对账API；真实供应商证据不足时保持UNKNOWN/PAUSED。[可操作手册](../docs/implementation/P4_02_恢复与升级运行手册.md)

## 8. 未验收范围与下一轮优先实验

**当前需要继续解决的工作：** 200正常业务恢复在最新远程仍18/21；热点首试及开放到达未达；500业务仅17/51；1000实际供给不足；长篇事件全量重放/2000上限；多小时混合增长和故障恢复；远程对象/生产规模恢复；真实模型与商业Host；作者完整独立阅读。跨卷服务最多100卷、2000条记忆及一次2MB原文审核；宏微证明最多200个选中事件、64微步骤、256效果、1024边界。超过有限协议应拒绝或另行设计，不能宣称已获得通用仿真或无限长篇能力。

下一轮应按以下顺序形成单变量、可否证的实验：

1. **复现最新200未完成。** 在固定硬件与同原任务规模重复正常/热点，追踪那类propose/certificate耗尽的服务入队、锁拥有者、持锁工作和重试期限；保留首试与最终业务两层指标，不单纯增加超时/连接数。
2. **校准独立到达供给。** 使用独立负载主机或明确CPU隔离，分别记录计划时间、客户端真正HTTP发送、服务接收/完成及响应验证；先证明客户端能供应目标，再测服务器容量。
3. **定位大世界成本与锁链。** 对JSONB字节、反序列化、验证、哈希、完整重放、依赖和锁持有分段剖析。固定WorldRef、权限、证据与守卫，比较元数据/批量读取等有限优化；缓存或增量投影须证明撤权、Retcon、解释器变化和恢复等价后才能进入正式实现。
4. **提出独立P3流式准备/接受实验。** 保持500/1000业务规模与公平性，有界在途工作，避免原全量准备节奏使早期证书老化；原300秒证书和P2容量门槛不改，新实验不能替代原失败记录。
