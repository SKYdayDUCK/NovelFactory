# P5 成本、性能与故障恢复

| 观测对象 | 实测结果 | 解释边界 |
|---|---|---|
| 同场 3 名角色、1 个独立通知、裁决、卷纲和两级规划 | 8 个模型任务、8 个不同 Thread/Turn、每任务 1 次供应商请求、8 份角色或岗位上下文、1 个正式世界事件；重启为空闲。 | `codex-text` 路由、原生 Codex 和回环 HTTPS 端点。其他角色工具路由有独立的执行成本。 |
| 同场等待 | B 在前置行动和通知之前无模型请求，卷纲在正式接受前无模型请求；结束后活跃 Host 为 0。 | 夹具端点每轮固定报 11 个输入、7 个输出 Token；8 轮共报 88/56。实际付费 Token 和费用未知。 |
| 提示大小 | 八轮输出契约由逐处内联的 35,195 字节降至 31,637 字节，减少 3,558 字节（10.1%）。优化后八轮系统和用户消息正文合计 119,626 个 UTF-8 字节。 | 同一批冻结契约、同一组消息。仅将重复定义改为文档内引用，若内联更短则保留。单元测试逐种岗位展开后和原约束深度相等；真实模型遵循度未测。 |
| 编译与恢复 | 公共输出 Schema 按契约名、版本缓存；角色材料和上下文不进入此缓存。样例核对八个执行任务的八个不同 ContextBundle；重复登记、恢复与结束后取证均无额外供应商调用。 | 本次没有长期多作品的缓存命中率测量。 |
| 通知与持续空闲 | 专项观察 45 秒，连接池 SQL 0，挂起事务 0，新任务 0，模型调用 0。登记至产物 0.316 秒；强制断开监听连接后，5.309 秒内完成第二个任务。 | 低频复核设为 60 秒。一轮短测不能外推生产 P99 或多小时空闲。 |
| CLI 覆盖作者操作 | 原生 app-server 调 MCP，先 status，再连续两次 resume。三次均返回 READY 1、WAITING 1、RUNNING 0，两次均 awakened 0 / recovered 0 / closed_waits 0，共 0 个模型轮次。 | 本机的 X11 显示服务被拒；另在 GitHub runner 用 Xvfb 启动真实桌面及同一官方 VSIX，完成两轮中文对话。项目侧两次 awakened 为 1、0。UI 的合成推理与作品侧模型调用分别计数。[原生桌面取证](https://github.com/SKYdayDUCK/NovelFactory/actions/runs/42982135338) |
| 物理恢复 | PG 17.11，fsync、同步提交和数据校验开启；校验基本备份后恢复，核对 45 张表和 19 个对象，校验耗时 1.221 秒。目标前提交丢失 0，刻意排除目标后的提交 1，UNKNOWN 1、预留 0.5 均保留；旧 worker 被拒绝，原提交回执相等。 | 隔离数据库，未访问生产数据。该时延为此夹具恢复至服务就绪的时间。 |

原始记录包括[八轮请求大小和账本](../evidence/p5/final/prompt-sizes.json)、[空闲及断线](../evidence/p5/scheduler/idle.json)、[原生恢复](../evidence/p5/final/native-resume.json)、[物理恢复](../evidence/p5/final/pitr.json)和[模型端点预检](../evidence/p5/final/model-preflight.json)。本次没有配置 NovelFactory 外部供应商端点、模型与 API 凭据；真实供应商费用、真实多轮推理与文学质量为 BLOCKED_ENVIRONMENT。

## 故障注入与可恢复结果

| 故障时点 | 持久状态和重启判据 | 可复验用例 |
|---|---|---|
| 领取后失去 worker | 过期回收升代，旧代结果不被接受；已有计划守卫的工作按原协议置为 STALE。 | tests/reliability/test_tasks.py，tests/integration/test_workflow_plan_fence.py |
| HTTP 已发且结果未知 | 已发调用保留 UNKNOWN 和预算预留；恢复不发第二次。 | tests/integration/test_p5_supervisor.py 的 process_death 与 unknown_after_send 用例 |
| 已有供应商结算，交付未完成 | 只有已保存且与任务绑定的一致材料可交付；已结算、缺少结果的任务不会重发。 | 同文件 settled_call_without_delivered_result |
| 候选保存或密封中断 | 重读候选与同代回执，对账后交付；错误候选保留待审。 | tests/integration/test_p5_actor_handoff.py |
| Kernel 接受后、外围事务提交前抛错 | 控制任务、审查候选和世界接受同事务回滚；重启只接受一次。 | tests/integration/test_p5_joint_handoff.py 的 primary |
| 监听连接、消费通知中断 | 重连后从持久任务、Outbox/Inbox 复核；通知重复、丢失或先到均不代表产生新业务效果。 | tests/integration/test_p5_scheduler_admission.py 和 tests/reliability/test_workflow.py |

原容量门槛和工作流继续独立运行。以上局部时延与小规模实际角色并行不能替代 200/500/1000 Agent 的原压测结论。
