# P5 连续场景与跨卷推进验收

接管时 `register_scene` 能从一次管理员登记运行到角色意图、联合裁决、正式接受、卷纲审核和有限重规划。上级编辑的回执是该链的终点。原跨卷用例由夹具创建下卷任务，模型返回后再由夹具保存窗口。R4 把下一场的建立和下卷规划候选的保存接回服务端正常入口。

| 验收边界 | 状态 | 观察 |
|---|---|---|
| F 同卷连续场景 | DONE，有限预授权 | 第一场无重大偏离时直接接续。重大偏离通过上级审批后按新选中计划接续。两个场景有独立角色、控制、裁决和审核任务，第二场使用第一场已接受后的 WorldRef。 |
| 重放、失配及停止 | DONE，确定性模型 | 带原幂等键重复登记、为下一步重建 Supervisor、末次重复运行均没有多发模型请求。故意替换授权触发器时只完成第一场，回执记录 `STOPPED / ADVANCE_BLOCKED`。 |
| L 已批准的连续性发布至下卷规划 | DONE，指定卷和预算 | 发布前调度空闲。前卷释放后又发生了已接受的位置变化。独立审核通过的连续性快照按新世界版本发布后，两次并发调度仅建立一个下卷任务。模型获得按权限裁剪的上卷材料和标明用途的最初参考目标，服务独立保存一个 DRAFT 窗口并接受任务。 |
| 超出下卷窗口的输出 | DONE，反例 | 授权一个目标而模型生成两个。保存阶段返回 `WINDOW_CONFLICT`，任务进入 `WAITING_REVIEW`。重复调度无新请求。 |
| 从短卷模拟一直自动完成文学发布、连续性审核、创作无限后续卷 | PARTIAL | 现有发布和连续性审核要求仍然有效。此轮覆盖审核发布之后、具有一次明确预授权的自动交接。长篇循环还依赖作品自己的卷完成条件、文学审核和下一卷授权。 |
| 连续多场或跨卷的真实付费提供方 | BLOCKED_ENVIRONMENT | 新用例使用本机可重复的模型响应。真实供应商的文学表现、计费及延迟未验收。 |

## 启动下一场

管理员在原有 `--register-scene` JSON 内选填 `following_scenes`。每项以 `node_id` 和 `process_id` 绑定已采用的计划节点和已登记的世界过程，最多 `scene_limit` 项。可在最后一项增加下述卷终标记。缺省保留单场语义。沿用该登记的作品、分支、角色与依赖、世界范围、允许的效果、模型路由和预算，不另发凭据。期限从前一轮剩余时间扣减。

一次只建立下一场。在编辑结果为 `NO_MAJOR_CHANGE` 或正式采用了 `APPROVED` 修订后，服务使用此刻接受的世界版本复核节点状态、精确故事时间、发布前缀、硬前置节点的已接受证据以及当时实际到期的相互作用。退回、世界版本改变、过程失配或预算路由变化都有可查的停止原因。角色面向自己的 BELIEF 输入，不接收后续清单和计划节点。场景任务从服务端关联计划节点，相关节点或硬前置发生变动时，新计划的采用事务能将未完成任务置为 `STALE`。

`supervisor.editorial.delivery` 的 `continuation` 给出下一场的世界版本、选定计划、已建立任务和剩余槽数，或者停止原因。数据库在同一事务中提交编辑结果及交接。后续登记出现领域错误时，只回滚部分子任务、授权及依赖，保留第一场已接受的事实与已作出的编辑决定。

## 跨卷启动

先为目标卷选定初始计划并冻结它的原始参考线。随后使用现有私有服务绑定，为一对指定卷登记一次授权。文件内的 UUID、引用、授权额度取自本作品。执行一次后，持久服务从已审核的连续性发布中激活下一步。

```bash
python scripts/run_supervisor.py --access-file /path/to/private/service.json \
  --register-next-volume /path/to/private/next-volume.json
```

| JSON 字段 | 约束 |
|---|---|
| `world_ref`、`series_id`、`from_volume_id`、`next_volume_id` | 服务绑定作品、分支及登记时的已接受版本。来源卷与目标卷不同，每个目标卷仅一个该类授权。 |
| `story_time`、`subject_ids`、`predicates` | 下卷规划读取的故事时点、获准对象与谓词。连续性不得含超过该时点的材料。 |
| `adapter_id`、`budget_id`、`reserve_amount`、`token_reservation` | 登记的路由、共享预算与单次调用上限。模型配置指纹随授权保存，派发时复核。 |
| `deadline_seconds`、`idempotency_key` | 在 1 至 86400 秒的授权期内最多展开一个规划任务。重复相同命令返回原回执。 |

服务要求当前选中的连续性快照以指定来源卷结尾，处于当前正式历史上，且目标卷尚未出现在已出版卷序列中。发布、变更授权或重启之后，以数据库选中记录重查。模型获得上一卷的派生编辑材料，以及目标卷最初选定参考线的有限目标。它只能提出候选窗口。正式保存前再次验证代际、授权、已选快照、当前世界、引用证据、对象范围和窗口上限。保存不会将该窗口直接采用为正式剧情，不改变世界事件或已发布前缀。若执行中途关闭，模型调用及结果对账复用已有 Supervisor 机制。独立的文学质量、付费表现及人工审批流程仍由相应验收覆盖。

## R5 偏离理由、角色证据与回归路径

此前的 ChangePoint 保留整份初始计划引用、当前计划、可调整窗口、接受事件、导演任务与理由。窗口列出最多可调整的节点，不能用它推断哪一项实际受影响。新建的卷导演任务使用 `VolumeReviewOutput`，对重大偏离可以提交 `assessment`。主管工具 `nf_change_point_request` 接受同一可选字段。

| 审核问题 | 记录与约束 |
|---|---|
| 具体偏离原线哪里、影响哪些将来场景 | `reference_node_ids` 取自不可变初始计划与当前获授权计划共有的节点。`affected_node_ids` 只能从当前 K 场窗口选取。两者独立记录。 |
| 人物弧线和行为是否合理 | 每项 `characters` 记录角色、审核判断、理由、所据正式事件与弧线影响。角色须在本任务的已编译清单中。确定性的合理或存疑判断至少需要引用一个有可见后果的本轮事件。该判断属于导演的文学解释。证据不足可写 `INSUFFICIENT_EVIDENCE`，弧线影响可留空。 |
| 当时角色有何可用材料 | 新版记录指向准确的正式接受回执。作品分支管理员可按 `action_time_audit(kernel, principal, world_ref, change_point_ref)` 查回这次联合接受中各密封行动、原来的 BELIEF 上下文引用、当时的 WorldRef、故事时点与 known_at。该控制面函数只返回引用和时间。导演、规划者及其他角色的普通任务没有此读取权限。 |
| 下一步能否回归 | `trajectory` 明确区分 POSSIBLE_RETURN、DIVERGENCE、UNDETERMINED。前两项要求列出具体参考节点、受影响的窗口节点和可执行方向；DIVERGENCE 使用替代方向，未知则保留两个空方向。规划者和独立总编收到同一份评估，并在实际窗口和计划上作出决策。 |
| 旧任务、旧回执 | 已创建任务继续使用其固定 AgentInput 中的输出契约。没有 assessment 的旧 MCP 请求保留原幂等哈希。旧产物读取时单独展示未知判断，引用内容仍与原哈希一致。 |

实测覆盖工具输入的兼容重放、许可窗口内的回归、明确分化、未提供判断、越界节点、越权角色，以及上层规划和审批收到的真实消息。分支管理员可以追溯各角色的原时点引用，使用导演权限读取相同凭证被拒绝；模型消息中没有密封意图及私有上下文引用。文学生成取自合成端点，实际人物动机和创作质量仍需结合正式作品判断。[审核与交付测试](../tests/integration/test_p5_editorial_handoff.py) · [MCP 与窗口边界](../tests/integration/test_p5_rolling.py) · [PostgreSQL 原始测试记录](../evidence/p5/story/change_point_review.xml)

## 卷终结算与连续性审核

在单场授权的顶层，或在 `following_scenes` 最后一项写入 `"volume_end": {"series_id": "已经授权的系列 UUID"}`，表示这场成功通过卷纲审核后收束本卷。一个登记带有后续场次时，顶层卷终标记会被拒绝；非末项标记也会被拒绝。普通无标记场次和提前停止的链不会生成卷终产物。

在末场审核无重大偏离或上级正式采用新计划后，`volume.settlement.recorded` 给出唯一的 `settlement_ref`。该候选保存逐场的实际联合接受回执、审查任务与决定、选定计划、最初参考线、当时已发布的节点前缀和先前连续性版本。每个场景的故事区间取自实际接受事件。重复恢复不重复记账，也不会直接改写世界、批准连续性或发布文学版本。

当原有写作、编审和版本冻结流程为同一卷提供有效正式版本时，服务验证版本包含上述场景的历史且仍选中每个证据事件。原有管理员授权和策略仍有效时，服务为指定系列调用原生 `ContinuityService.prepare`：只追加事件证据，保留以前的连续性前缀。成功回执 `volume.settlement.continuity` 的 `AWAITING_INDEPENDENT_REVIEW` 包含待审候选和实际卷版本。权限或历史不匹配记入 `SETTLEMENT_REVIEW_DEFERRED`，合法的卷冻结不会被回滚。已发布卷的修订仍须走原有版本审核流程。

验收覆盖普通场无卷终候选、两个标记位置错误、连续两场仅结算一次，以及单场重大偏离后实际准备三段夹具正文、经过独立编辑审核并冻结本卷、自动交给连续性审核。测试确认初始审批人不能自审，独立身份读取并批准后可走原生发布接口。下卷的一次性授权随后依赖已发布快照。文学判断及必要的独立签核仍需具有对应权限的实际执行者。目前自动交接到原生待审候选；本用例以两个独立的测试身份执行审读和批准。详见 [卷终与邻接回归 JUnit](../evidence/p5/story/r4_settlement_postgres.xml)。
