# P5-02 持久任务依赖与恢复

`WorkflowService` 的三个入口使用现有 TaskService、PostgreSQL 和事务内授权。作品与分支由服务端绑定。状态查询返回任务状态计数，其中 `WAITING` 对应 `nf_tasks.state=BLOCKED`，`RUNNING` 表示任务正在持有执行资格；活跃模型数须另外从 Host 实测。

- `wait(task_id, generation, dependencies, *, mode, work_id, branch_id, authorize_in_tx, worker_id=None)` 为这一代任务登记一个 AND 或 OR 条件。每项依赖指定同作品、同分支的上游任务。建立依赖的任务可从 BLOCKED 启动，或由当前租约持有者在 RUNNING 期间挂起并归还租约。已发出、结果未知或仅预留的外部调用必须先完成对账。重复登记相同条件可重试。
- `resume_project(work_id, branch_id, *, authorize_in_tx, limit=100)` 确定性回收本分支已过期的运行租约，然后查找满足条件的任务。每个动作只处理最多 limit 个任务。源必须有当前代际已接受的任务以及精确对应的 `task.changed` Outbox。源事件早于登记、被别的消费者投递，或两个恢复器同时检查，都可恢复。
- 一组条件满足后，目标任务获得一次 READY 转移。Inbox 收据、等待组唤醒时间、目标状态、READY Outbox 一并提交。在正式 claim 时，既有 TaskService 签发新的 generation 和 lease。等待组不会复制正文、上游角色意图、授权令牌或模型输入。

## 权限与故障处理

登记同时检查当前调用授权、待唤醒任务的所有者、岗位、分支、截至时间和 TaskSpec 固定的 grant/policy，记录 grant epoch。唤醒时重验同一组绑定。0006 引入的恢复操作员凭据还具有单独的到期时间和策略版本，由事务内的 Kernel 授权验证。角色任务本身使用任务截止时间、grant 生效位、epoch 和固定策略版本。运行时模型没有登记任意任务 DAG 的 MCP 工具。旧 `resume()` 对 BLOCKED 返回 `WAIT_CONDITION_REQUIRED`。恢复备份时保留 BLOCKED 状态，向新代际复制其等待条件与原授权 epoch。取消的任务和未调和的外部调用都不能凭旧通知获得运行资格。

这里支持的业务事件为“上游任务的产物已由其授权接受路径接受”。它可以代表消息、角色行动裁决或审核完成，由相应的应用服务决定何时接受。若上游取消或永久失败，AND 组保持阻塞，OR 组可由其他成功来源满足。人类审批、发布、写入世界历史仍走各自的服务。Python 服务停止期间，所有 Outbox 与 Inbox 留在数据库中。

对已绑定计划节点守卫的任务，系统不能把旧代际的 PLAN_TASK 选择自动移交给新代际。主动挂起返回 `TASK_REBIND_REQUIRED`，无未决调用的过期恢复会标记 STALE。控制器可在当前计划上创建并重新绑定另一个任务。历史版本留下的 READY、PAUSED 或已登记等待也会检查原任务的所有代际；普通未绑定计划的任务沿用上述自动恢复流程。

## 迁移与验证

0003 到 0004 新增 `nf_workflow_waits` 和 `nf_workflow_edges`，既有数据无回填。登记 DAG 时只串行化同一分支的图编辑；正常世界接受不获取该图编辑锁。恢复使用短事务与 SKIP LOCKED，防止多个进程重复唤醒。Outbox 中的源回执必须保留到相关等待完成。本阶段未引入清理历史收据的作业。

空工作流数据允许降级至 0003。已有等待数据时降级事务会终止，以免删除尚在等待的依赖和既有收据。保留已有 P5 数据时，关闭任务写入入口及调度器，旧二进制仅供只读核对。旧版写入器不了解结构化等待，消化或迁移待办后才能恢复写入。整库回退须使用已验证的独立恢复副本，保留原库和对象清单。

实测环境为 Python 3.12.14、PostgreSQL 17.11、fsync 和 synchronous_commit 开启。以下组合在两个独立后端并发及真实恢复条件下共通过 32 项。隔离测试验证 0003 → 0004 → 0003 前后所有数据库表的行数及哈希一致。工作流覆盖并发环、AND/OR、跨分支、重复和提前到达、撤权、grant epoch 与 policy 切换、等待租约释放、取消以及恢复围栏。详见[用例结果](../evidence/p5/workflow/pytest.xml)及[数据库运行记录](../evidence/p5/workflow/postgres_session.json)。

```bash
uv sync --frozen
uv run python scripts/with_postgres.py --migrate -- \
  python -m pytest tests/reliability/test_workflow.py tests/reliability/test_tasks.py \
  tests/reliability/test_recovery.py tests/integration/test_p5_workflow_migration.py -q
```
