# 本地恢复、缓存与自动化核查（2026-11-14）

本机 PostgreSQL 17 与 Redis 已可用，原三书快照已恢复。以下是生产前工程记录；不表示三书已完成文学验收或已具备无人值守交付能力。

## 已观察的问题

按原三书 513 个 Attempt 核查，512 次有完整输入、输出及缓存用量，另有 B 的一次丢回执。已知输入 3,958,510 Token，输出 1,638,563 Token，输入缓存命中 169,472 Token，加权输入命中率 **4.2812%**。完整用量中 167 次输出未通过契约校验；这不是文学质量评分。135 次定向修订、158 次认知审读和 60 次事实抽取包含大量返工，冻结章节仍为零。

原提示把变化的任务身份放在系统指令中间，约 2 KB 后便遇到不同字节，后面的 Schema 和正文难以形成可复用长前缀。任务正文 JSON 又先放具体 assignment，结构化修复诊断变化也会提前打断前缀。事实抽取的一次样本约有 31 KB assignment 和重复定位材料；本文不发布其私有内容。

Harness 已有固定 WorldRef、知识切面、角色权限裁剪、不可变上下文和渐进指令机制。本地查询缓存与供应商 KV 缓存是两件事。[DeepSeek 官方规则](https://api-docs.deepseek.com/guides/kv_cache/)按已持久化的匹配前缀计命中，且不保证命中；命中输入仍不能消除生成输出及反复返工的费用。

## 本次修复

- 模型消息按固定指令、已授权材料、任务身份排列。材料字段先于 assignment；不删除证据，不改变数组及内容，不跨角色合并秘密。快照仍保存原输入，完整请求另行哈希审计。
- 成本报告按作品和阶段/角色/模型增加输入 Token 加权命中率与未知用量数。未观测用量不充作零，也不把输出 Token 计入输入命中率。
- 对无法找回输出的旧只读审核提供管理员恢复服务：旧任务取消产物资格，旧 UNKNOWN Attempt、金额及 Token 预留保留，独立新预算登记一次相同任务/模型/材料的审核。操作幂等、迟到结果拦截；不自动无限重试，也不声称旧账已结算。
- Codex 原生登录结果的生产交付核验 Host journal、线程/回合、实际模型、输入/提示/响应哈希、任务代际及输出契约。已完成结果可采用，订阅未知金额继续保留；未完成或身份不符不能采用。DeepSeek 的原有传输证据门槛保留。
- Windows 观察器使用非阻塞锁探测，私有报告目录在创建时设置 owner-only ACL；测试身份材料使用同样的私有目录条件。

B 的恢复先在独立 PostgreSQL 快照副本演练：499 个 Attempt 前后不变，旧账本和原请求逐字段不变，新审核登记且不发模型请求。原运行库执行同样操作时 Attempt 为 513，前后仍一致。原请求继续保持 UNKNOWN；新审核后续模型调用另记账。

相关定向回归：30 passed、13 个 Linux 宿主用例跳过；规划及格式恢复回归 25 passed、1 个需独立 NF/Workshop 集群的 S6 用例跳过；最终交付/恢复/缓存回归 27 passed。此前较广单元检查为 510 passed、2 skipped、17 subtests，另有 Windows 冷启动使 1 秒超时样本尚未开始 POST；确认以 3 秒启动预算仍能终止无尽 trickle 后，调整该平台样本并定向通过。静态包验证通过。未宣称整个仓库、HERA 容量门槛或完整三书端到端全部通过。
