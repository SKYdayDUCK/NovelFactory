# 架构差异与未完成问题

本报告以原 v2.0-R1 文档、Schema、ADR 和本轮用户指定的 P0/P1 最小范围为基线。所有原业务矩阵保留；新增验收追踪文件只说明实际覆盖，不把设计目标原地改成已通过。

## 1. 保持不变的核心约束

PostgreSQL 17 为唯一权威事实与任务状态源；内容寻址对象保存不可变字节。外部 Agent 只能调用应用服务，不持有数据库或对象目录写权限。WorldRef/StoryPoint/Event/KnowledgeCut 复用原统一契约。故事发生时间、角色获知时间与编辑修订相互独立。

事件、修订、提交及输入历史不可原地覆盖；正式接受采用原子事务、真实 grant、批准、任务代际、幂等与分支 CAS。历史修订替换事件选择后重放，保留旧版，不重复施加效果。future PLAN 不进入 WORLD。查询缓存不能免除权限和版本检查。任何未证明的守卫不会为了吞吐自动放行。

## 2. 有依据的实施调整

| 调整 | 原因 | 影响/验证 |
|---|---|---|
| JSON Schema-first，统一生成 Pydantic 适配 | 原公共 Schema 已有大量 oneOf/条件/负例；直接另写模型易漂移 | 与 README 的未来 Pydantic-first 建议有差异；原 Schema 字节未改，58/31 正反例双入口、bundle 漂移门禁通过 |
| SQLAlchemy Core Repository/UoW | 领域对象不应被 ORM 生命周期支配；P1 需要明确 SQL 锁序 | 仍为推荐 SQLAlchemy/Alembic/PostgreSQL 路线；真实迁移与事务竞争验证 |
| 每个修订保存完整历史 JSONB 投影 | 小内核先采用可确定性复核的实现 | 读切面一致，写/存储成本随历史增长；普通最多2000、repair最多200事件，不声明大历史吞吐 |
| 稳定 legacy RELATION_SET 与 R1 transition 共存 | 原2.0载荷合法，转移重放需兼容原历史；R1显式open/close仍支持 | 禁止同事件对同槽重复使用两种效果；借改赠、历史关系和关闭版本约束均测试 |
| 作者控制面 control_operator | 原chief_editor不等于全知世界管理员 | 保留原十角色profile；新增控制角色需当前ADMIN，actor仍本人BELIEF |
| NF-PROP-1 显式认知命题 | 原 cognitive effect 的statement只有字符串 | 不改旧Schema；新增闭合命题schema，含可选subject_time；不自动把自由文本解析成事实 |
| 五个闭合模板允许 guarded | 无法对任意自由语义证明完整依赖 | 实际完成独立写与冲突分辨，其他命令strict或拒绝；不把降级strict声称为guarded全覆盖 |
| 同步 control command 接受结束当前任务 | 本轮无需外部模型即可产生真实任务成果 | receipt/world/outbox/task终态同事务；不伪造模型TaskResult或供应商调用 |
| 单机POSIX内容寻址库与逻辑备份 | 本阶段不引入分布式对象/微服务系统 | fsync、GC锁、进程故障、真实pg_restore可验证；跨主机/物理断电不在保证范围 |
| 冻结P1迁移DDL快照 | 旧迁移不能随未来metadata变动 | 56条DDL与SHA固定；未来另加迁移，不修改历史版本 |
| 原设计检查器排除生成依赖目录 | 安装后.venv内复制的文档不是项目原文件，原全盘rglob误报相对链接 | 只调整遍历；坏原文档链接/坏contracts JSON仍拒绝，原正反例不改 |

详细理由和锁序见 `docs/implementation/P1_事务与一致性决策.md`、契约/查询决策以及独立审查报告。

## 4. 已发现、已修复的问题

开发中真实发现：任务输入遗漏不可变触发器；任务外层授权到写事务的撤权间隙；虚构认知/规则/裁决来源；修订后继前提未重验；推广未复核当前批准；普通审批分支范围遗漏；认知目标时间倒灌；未知资源被当零；备份权限profile遗漏；接受未结束任务；复用崩溃后可见对象未再次fsync；scope身份改名导致ABA风险。

这些问题均有代码修复和可运行反例/正例，最终237项完整运行通过。早期环境、测试夹具和参数绑定错误也保留记录；修复测试错误时没有删除核心反例或放宽正确验收目标。`historical_failures.json` 与独立审查报告提供原始日志索引。

## 5. 当前剩余风险和审核重点

当前没有已确认未修复且仍导致本轮必验失败的缺陷。测试不是对任意输入和未来扩展的数学完备证明，独立审核尤其应检查：

1. 新命令或新写路径是否始终参与维护gate、正式接受、scope bump与授权复核；有限模板证明不能被自动外推。
2. 修订逐前缀重验、历史epoch、当前审批和双HEAD CAS的组合；保留旧认知的provenance不能被视为重新证明客观真相。
3. 全量JSONB重放与短事务成本、查询SQL放大和50Agent尾延迟；需要扩大历史前先做新的性能实验。
4. POSIX文件/目录fsync与锁的部署前提，数据库角色是否严格限定给服务，备份是否涵盖新解释资产。
5. 缓存授权、批量切面和非公开来源过滤；本轮没有证明网络时间侧信道完全不可观测。
6. 真实模型调用与外部副作用接入时的UNKNOWN对账，以及持久任务代际与供应商重试边界。

这些风险是当前实现的适用边界，不可通过删除失败日志、编辑证书token或绕过版本/权限检查来“解决”。
