# S5 指令候选、独立评估与发布

## 从一份真实审核生成候选

在单一作品和分支上，控制端用 `nf_harness_instruction_propose` 引用目标任务代际、至少一份失败审核和独立留出审核。服务核对 S3 审核者、签名、稿件版本、引文、编辑决定和上游角色。根因记录保留反解释。世界设定、卷导演、场景调度、演员、写作、编辑或上下文组织均可成为调查对象。来源必须支持目标角色。训练稿件与留出稿件按正文摘要去重，同稿的不同审核不会制造独立留出样本。

候选和基线引用不可变 NF 工件。冻结记录包含准确 Git 版本、实际运行模块的 SHA-256、两组角色与 Skill、样本、模型/执行器配置、随机分配、次数、截止时间和 NF 预算。运行未提交源码时同时记录基线 Git SHA 与工作树模块摘要。安装 wheel 的服务通过部署配置 `NF_CREATIVE_RELEASE_COMMIT` 提供实际版本；七个模块摘要由服务自行读取。候选引用已完成的设计记录，随后实验用两个已存在的版本引用生成分组，避免工件哈希循环。

## 独立评估和授权

| 入口 | 身份与作用 | 结果 |
|---|---|---|
| `nf_harness_instruction_evaluate` | 绑定作品和分支的控制端执行冻结的全部 A/B 配对 | 各臂输入、输出、状态、耗时和成本，以及完整运行清单 |
| `nf_harness_instruction_case` | 控制端据 NF 原始记录推导实际来源与各方身份 | 本候选、实验、审核任务和发布人的登记描述 |
| `nf_harness_instruction_evidence` / `review` | 已委派、具备审核能力的任务读取对照结果并发表独立意见 | 与候选、实验和期限绑定的意见、签名凭据 |
| `nf_harness_instruction_decide` | 已签入该候选的独立发布人选择 APPROVE 或 REJECT | 不可变决定，批准时用期望世代更新分支选择 |
| `nf_harness_instruction_monitor` | 核对一项实际使用该发布的任务 | 任务状态、真实 NF Attempt、已知 Token/金额以及未决数量 |
| `nf_harness_instruction_rollback` | 获准发布人在当前选择世代恢复上一个精确版本 | 独立回滚记录和新的选择世代 |

独立登记由 `python -m novel_factory.interfaces.adaptive_authority` 处理，认证后才能读取案例。通过 `describe` 获得具体当事人，独立登记方再用 `enroll` 提供对应的已核验身份组记录和有效期。`withdraw` 撤回该案例。签名密钥与注册目录由服务端选定。角色会话只看到本次分配的审核材料。提案者与评估者均进入生产者集合，意见人和发布人须来自独立主体组。相同候选、不同发布人需单独登记。原始指令、正文、模型输入与评估样本经作品及分支权限保护。

默认关闭自动晋级。采用自动路径还必须显式配置 `auto_promote`、注册限时授权策略并完成独立审核。策略撤回由 `nf_harness_instruction_revoke_policy` 记录。选择范围绑定作品、分支、角色、任务类型、Skill 和可选 Workshop 动态实例。发布与回滚复用 NF 的 selections、工件和幂等收据。先前任务从 AgentInput 冻结的选择读取指令，再次调度时仍使用原版本。模型记账只来自 NF Attempt。

## 工程对照能说明什么

有界离线执行器按同一来源、种子及分配运行两组。审核类调用实际 S3 判断函数，材料组织类调用实际上下文重排函数。保留负例、误报、漏报、回归、中断和未执行理由。同一登记重试复用已保存的结果。在此路径，至少一个独立留出样本客观改善、有独立负例、所有配对完整且没有样本回归，才有资格送审。独立意见和发布仍是后续两个步骤。

四份原生签名审核组成阶段用例。两份用于归因，另外两份用作一正一负的留出对照。正例的独立读者分别指出两个句段的机械重复。初始工程阅读只定位第一处，候选的补充检查定位两处。另一个段落保持原样。在真实审核端口，读者显式要求原样保留的具体位置仍然受到保护。该演练的商业调用与支出均为零。自由文本角色方法及 Skill 的工程预检会保留两臂渲染内容摘要、字节数和作用域核对结果。仅凭内容交付成功不能晋级。S0 发布契约的 `literary_status` 字段为 `UNPROVEN`。本阶段没有运行商业模型或独立读者盲评，阶段级文学质量状态为 `NOT_EVALUATED`。

另一条真实写作路径使用 S1 来源内容摘要，将 S3 章节接缝审核引用的前文与已授权正文匹配。两组保留已发布的连续性材料。候选把被引用的正文移到首位，通过独立审核及发布后，一个新 writer 任务在实际网关请求中收到了此排序。对已接受的稿件，历史对照凭签名审核、原代际模型输出和唯一的一次原生接受读取原包。假如发生后续改稿，或者旧任务试图重新交付已过期的场景，服务会拒绝。[写作与材料排序回归](../../tests/integration/test_adaptive_context_replay.py)
