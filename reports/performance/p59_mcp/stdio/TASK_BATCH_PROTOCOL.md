# 已准入的静态角色任务读取合并

基线是 B（通过单次服务内紧凑读取减少重复 SQL），实验臂 H 在其上添加至多 1ms 的同绑定凑批窗口。每个绑定保留 2 个独立准入槽和连接池上限，无跨作品、跨身份、跨进程或持久缓存；只有已由原 invoke_bound_tool 单独完成工具选择及参数检验的 task_get 和 context_get 能靠近共同读取点。动态身份保留每项独立远端复核。每项继续独立落 mcp.started / mcp.finished。

2 个真实绑定，各 40 条 nf_task_get，两个闭环调用槽，第二阶段 12/s 开环；B/H/H/B，共 640 条计划工具调用。沿用 PROTOCOL.md 中两对最低收益及 P95/P99 限制。每轮绝对返回匹配，按会话＋JSON-RPC ID核对每条审计。批次形状按 H 成员数量另计，失败时保留原始结果。绑定池不同、凭证/代际不符、知识切面不同的请求不能共同读。该额外试验的 CPU/PG 限制为 3 核（0–2）、128 个连接，独立 PG17，不与前一轮的绝对数值混同。
