# 独立 runner 的短空闲连接实验

原始 stock 默认参数的托管实验已保存：99 进程/会话完成 396/396 项，下一次 PostgreSQL 启动鉴权遇到连接上限。新臂另启独立 runner 与数据库，采用生产已有参数 `--idle-db-seconds 2 --pool-slots 1`。逐个握手和核对工具列表，各角色均保留原任务、grant、作品和 SDK 会话。1 GiB 宿主可用内存保留与原实验一致，目标 200，达不到时报告最后实测数量。仅此新臂运行在本次 CI 中，前一臂单独保留在 hosted-stock.zip。

2、10、50、200 档和最终保留档分别将全体会话按 8 组宽度分波读取。每一波连续检查发现、任务状态、ContextBundle、冻结版本/权限查询，前一波排空，间隔 2.25 秒再进入下一波。全体 PID 始终保留。对照每波起始身份索引、每次授权结果和墙钟（含间隔）统计，不能用该值推算 200 个活跃 worker。最终另轮询观察绑定连接归零（最多 8 秒，记录实际连接数）；单个共同计划启动时刻对每一会话发出一次 task_get，记录实际 SDK 写入时刻和所有正确、拒绝、失败与超时，无重试。该阶段测同时到达、冷连接重新申请及业务吞吐。两种阶段分别计量。硬资源不足时写入每次已初始化检查点，保留最近完整分波及并发结果。
