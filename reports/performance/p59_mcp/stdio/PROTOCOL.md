# stdio 实测预注册

冻结数据库源 `9364b154941bfbbe95a57fee5ceb600f5219fa5b`，Runtime 参考 `877be80d7c1dfa8b6fb9c9c5a2a570c7b14d3ca0`。每次实验记录实际运行时 Git HEAD、工作树产品差异摘要和驱动 SHA-256。使用仓库锁定的 MCP Python SDK 1.29.0 和真实迁移后的独立 PostgreSQL 数据库。仅生成测试凭证，每个 Host 绑定对应独立任务、作品、角色授权、OS 进程与 SDK 会话，整个序列复用同一组身份和固定世界版本。每次切换实验臂重启各 stdio 进程。每个进程计冷启动和握手时间，再进行工具发现和运行时读取预热。无商业模型调用。

| 对照 | 冻结负载 | 序列 |
|---|---|---|
| task/context 共同读取 | 2、10 绑定，每绑定 24 条，每绑定 2 个闭环槽，工具交替；同一轮再按全局 12/s 开环重复这一序列，每绑定最多 4 个在途请求 | 默认 A、compact-role-reads B、B、A |
| 连接池降配 | 2 绑定，每绑定 24 条，闭环 2 槽和全局 12/s 开环读 | 默认 A、pool-slots=1 S、S、A |
| 工具发现并发 | 2 绑定，每绑定 40 条 tools/list，闭环 4 槽；全局 60/s 开环，每绑定最大 4 在途 | A、batch-discovery C、C、A |
| 集成冒烟 | 两个作品各 16 次，tools/list、task_get、context_get、query_batch 轮转，闭环 2 槽和全局 12/s | 默认 / 单候选，组合需实测另列 |
| 绑定容量阶梯 | 在一个进程组内按 2、10、50、200 阶梯逐个 Host 绑定，记录逐个冷启动和角色工具发现，已完成档做混合工作逐绑定复核；每档最后再次校验每一活会话 | 默认 A，实际进程数与 SDK 会话数量分列 |

开环的计划时钟在实验开始前确定，超出客户端在途上限计 CLIENT_DROP，截止 15 秒计超时。闭环各槽等待上一次回包才发送下一次。每阶段吞吐以正确数除以开始到最后回包（含排空）的墙钟计算。时延使用最近秩，主指标包括所有回包的计划至回复 P95/P99，单列成功时延及只从发送开始的时延。SDK 写流时戳为客户端将 SessionMessage 交给 SDK stdio 写入端，不代表内核 write 完成。服务端于 SDK 分派、进入同步业务方法、SQL cursor 前后分别测量。资源采样与测试凭证无关，SQL 文本、参数和工具结果不进入跟踪文件。进程内 CPU/RSS/线程与 PG 连接及锁等待按时间采样，峰值为采样下界。

对照按相邻的 A/B 与 B/A 两对分别计算。采纳须两对均达有效吞吐 +10%，或 SQL/正确请求下降 ≥20% 且有效吞吐 ≥ 对照的 95%；两对的计划至回包 P95/P99 均 ≤1.10 倍，业务内容正确，权限与状态回归通过。闭环、开环分别判，不跨档拼接。短样本的 P99 不作为普遍 SLA。固定角色发现必须恰为四项；返回空列表的调用没有完成发现业务。单项对照失败与高低负载不同结论均保留。

容量阶梯的试验进程默认使用至多 4 GiB 的合计 RSS，进程启动前用当前已启动进程的最大 RSS 作保守预测，宿主可用内存还须保留 1 GiB，独占 PG 还需给驱动与观察者保留 4 个连接。触达保护条件时给出最近实测存活数量、占用与下一绑定估算。该数只能证明在当前预算下测到了多少个，不得报告为操作系统或服务器的极限。无容器/cgroup 读数时显式记录。不能用虚拟身份填满未执行档。
