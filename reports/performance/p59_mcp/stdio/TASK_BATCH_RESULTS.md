# 同绑定静态角色任务与上下文的合并读取

采用预注册 B/H/H/B。B 为紧凑读取，H 增加 1 ms、至多两项的等待窗口，影响范围局限于基准启动的服务子进程，产品模块没有导入本实验。两个独立凭证、两个作品、两个 stdio 进程，640/640 条真实 MCP task_get 全部返回正确对象，每个 JSON-RPC 请求均匹配唯一的一对 mcp.started 和 mcp.finished 审计。

| 负载 | B1 | H1 | H2 | B2 |
|---|---:|---:|---:|---:|
| 闭环，每秒正确读取 | 49.15 | 45.24 | 50.45 | 58.12 |
| 闭环，P95 / P99 ms | 95.2 / 153.5 | 153.5 / 213.8 | 120.1 / 153.7 | 84.3 / 96.4 |
| 闭环，80 个正确请求累计 SQL | 2160 | 2142 | 2142 | 2160 |
| 开环 12/s，每秒正确读取 | 12.04 | 11.98 | 12.06 | 11.97 |
| 开环，P95 / P99 ms | 77.2 / 128.9 | 67.8 / 95.4 | 49.6 / 74.1 | 64.3 / 180.6 |
| 开环，80 个正确请求累计 SQL | 2160 | 2160 | 2160 | 2160 |

各 H 臂包含两个独立身份，两个负载和各绑定两项功能预热，共 164 个可分组读。单个绑定有 80 个 singleton 和 1 个 size=2 group。每个 H 臂只有 4/164 个读取共同执行。计划相邻的两个客户端调用抵达可共享事务的位置前，已经分别完成实时发现、参数校验和审计，因此窗口内重合很少。闭环每臂只省 18/2160 条 SQL（0.83%），吞吐两对分别 −7.9%、−13.2%，P95、P99 超过两个对照。开环 12/s 下无 SQL 节省。**拒绝把该候选加入生产或替代 B**。

处理时序保留原每次调用的受信任身份、参数检验、独立审计及已有有界准入。只有同一运行时对象上的两个已通过原入口的读取可共用一次新开 REPEATABLE READ：重新验证绑定任务代际、具体 lease owner、有效 grant、作品/分支、冻结世界和角色认知切面，再分别检查每个工具的权限。对同一 grant 的读取返回互相独立的副本，事务结束后再兑现 Future。单项请求、动态 Workshop 实例均保留原方法；该实现没有宿主间的缓存。

三项真实 PG 回归通过。混合任务状态与 ContextBundle 获得各自精确内容，非法参数保留单独错误审计；两个已入队的调用在开始共同读取前撤权后均被拒绝；另以测试替身模拟动态 assignment，验证每项调用独立回退。该替身仅验证分流，未实测远端动态实例故障。

在仓库根目录使用隔离 PG17 与锁定项目依赖运行：

```sh
python -m alembic upgrade head
python benchmarks/p59_mcp_stdio.py grouped.json.gz --suite task-batch --bindings 2 --arms BHHB
python -m pytest -q tests/integration/test_p59_grouped_role_reads.py
```

参见同目录 TASK_BATCH_PROTOCOL.md、task-batch-BHHB.json.gz、task-batch-correctness.xml 和 task-batch-manifest.json。初始主矩阵中的 3,584 条与本次 640 条分开登记。
