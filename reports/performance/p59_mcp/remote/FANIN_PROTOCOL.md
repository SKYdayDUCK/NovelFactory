# 多身份同一时刻请求

固定两个作品、200/500/1,000 个独立角色凭证和 ClientSession，单一生产角色工具内核、单个回环 HTTP 副本、2 个 PG/业务槽、另 1 个观察连接。SDK 1.29.0 Streamable HTTP 使用无服务端会话 ID 的模式。先以两个并发握手、发现并核对各角色工具。全部就绪之后同时释放屏障，各身份发一次 nf_task_get 并比对完整期望值；三档分别新建数据库。记录逐项从计划、调用、HTTP 发送到响应的时序、所有 HTTP 状态、正确/拒绝/超时、存活客户端、每作品成功、PG 连接和锁、服务端与客户端 CPU/RSS。无自动重发，客户端 SDK 遇 429 的 task group 退出单列。这是固定的小池突发诊断，不替代 stdio 阶梯、稳定负载对照或长期模型吞吐。

## 入口定位后的单项复验

从原始 200/500/1,000 项观察到大量鉴权 429 后，事先登记 Host 的有界并发候选。保持全部独立 SDK 客户端握手、相同角色数量、两部作品、同一瞬间到达和原服务端两槽；仅在每次发出 SDK 工具调用前共享一个上限 2 的 Host 信号量。每个客户端仅一次请求，Host 队列有界于固定输入人口，等待期间不借 DB/worker。计划至回包时延包括 Host 等待。三档各一次，在新的隔离数据库逐项验证。从原始单次全放行和单次受限实验给出完成率、正确/排空秒及绝对尾时延，不将负载曲线或单次诊断升格为双向选型。所有客户端仍经真实 SDK 和实时授权。
