# 回环 Streamable HTTP 预登记

Python SDK 1.29.0，2025-11-25 模式，stateless=True，无跨请求 MCP Session ID。两部独立作品、每部一份真实角色授权。各副本每次根据真实 Bearer 重新认证，从受信配置确定任务绑定，复用同一进程的有界 SQLAlchemy 池。服务端只监听回环。A 为单副本双槽，B 为两个单槽副本按 RR 路由。随后只改变双副本路由，比较 RR、least outstanding、power of two（2 个副本时后两者在无平局时等价）。路由按可用身份筛选，压测内两个角色均可访问两个副本。

每臂准备并预热所有连接，发 80 个闭环请求，四个客户端工作协程，交替本人 task/context。记录每行调用、返回、正确性、拒绝和延迟。两对 A/B/B/A 对照，正确有效 QPS 须两次 +10% 且全部回包 P95/P99 均不超过 1.10 倍。相邻对照中错误授权、错误内容或状态变更直接否决。额外两条未授权 HTTP 和跨绑定输入检查。副本冷启动单列。这里的客户端直接选择复制入口，不部署反向代理。

校准失败 1：入口鉴权与同步业务争用同一个立即拒绝的 limiter。四个客户端进入时，HTTP 429 让 SDK 1.29.0 的后台 transport task group 退出，多项工具调用随之中断。保留首次失败栈。第二次对照预先固定独立鉴权入口，上限每副本四个待处理、实际鉴权工作线程不超过本副本池预算；每次仍查当前令牌、下层工具即时背压不变。保留全部应用级拒绝。
