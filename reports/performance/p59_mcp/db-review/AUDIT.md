## 历史复核与新增实测

表中斜线分别代表同一序列内正序、逆序的两对比较。DB 每阶段 1,000 项，两个作品各 450 次状态读取及 50 次独立续租，4 个 worker / 4 个应用连接，64 个闭环请求槽。历史与本机绝对速率分别评价。历史 GET 及本机 GET 每阶段 320 次，16 个闭环客户端及 4 个连接。

| 工作负载和候选 | 有效业务速率的双向变化 | SQL 相对变化 | 复核判断 |
|---|---:|---:|---|
| 历史混合 DB，FIFO 状态读微批 | +246.08% / +238.75% | 两次 4,600→1,400 | 每阶段 1,000/1,000，P99 分别降 65.72% / 64.77%。锁与身份条件相同的一批读可共用 SQL 执行。 |
| 本机混合 DB，同一微批 | +226.64% / +237.12% | 两次 4,600→1,400 | 228.70→747.02、232.86→785.02 个/s，四阶段均 1,000/1,000，连接峰值 4。DB 层收益复现。 |
| 历史混合 DB，独立队列 | +1.78% / −0.44% | 0% | 续租 P95 降逾 80%，整体 P99 增 6.75% / 10.07%，不能作为通用加速。 |
| 历史真实纯 GET，FIFO 微批 | −3.64% / −8.24% | −7.25% / −10.75% | 两方向均减速。逆序 P95/P99 增 20.65% / 18.19%。 |
| 历史真实纯 GET，原简单 JOIN | +12.66% / +7.52% | 两次 −20% | 不足历史每方向 +10% 吞吐或 −25% SQL 的预登记标准。 |

本机 GET 的两个 A 自身 P99 分别为 1,059.83 和 291.48 ms，执行期间宿主同时进行其他专项，绝对耗时和波动不能归因于候选本身。SQL 节省在全部四阶段方向一致。历史 64 客户端各 512 项的逆序 P99 为 927.80→1,754.29 ms（+89.08%）；128 客户端归档基线的一阶段仅 485/512 正确。旧标准继续有效。历史全时间线查询固定版本字节校验候选四阶段 A/B/B/A 每批 5,000 次，分别仅核验 121/170/157/117 次。正确业务率 13.60/15.55/15.10/13.25 次/s，B 的计划至回包 P95/P99 两方向均恶化。HTTP AT-30 的 950 次/s 仍未达到。[高并发 GET](../../p59_database/raw/task-get-boundary/) · [时间线原始归档](../../p59_database/raw/actions/43291814145/) · [原预登记](../../p59_database/PROTOCOL.md)

## MCP 上的可移植边界

| 操作 | 可以共用的部分 | 每次仍须独立验证的内容 |
|---|---|---|
| 本人任务状态、角色上下文 | 先检验同一调用内消除静态证明与取结果间的重复查询。任务详情 HTTP GET 的 JOIN 仅是不同入口的对照。 | 绑定任务、当前角色授权和能力、作品、代际、租约、任务输入、角色时间/知识切面、相应审计与回执。 |
| 同一绑定的工具发现 | 到达后封组，再对同一份可信绑定的静态角色查一次当前工具。零积压时人为等候会增加延迟。 | 动态 Workshop 授权、不同绑定、控制器及不同 ceiling 须各自判定。SDK 定义缓存没有授权效力。 |
| 固定版本属性、场景素材、批量查角色知识 | 可以把同调用、同版本和作用域的独立 lookup 交给已有业务批量接口。原返回语义包含过滤、观察记录和投递前校验。 | 不合并不同版本、主体、代际、能力、actor 或知识/故事时间切面。不缓存多角色原始响应，不将过滤交给模型。只读返回也可能写审计、语义依赖。 |
| 续租、领取、预算、正式接受、Attempt 发送与结算 | 共用受限基础设施和调度额度。高读负载下为续租保留机会需单测吞吐及超期数。 | 每个真正的业务写保留其事务、幂等键/收据、授权锁、代际与 UNKNOWN 语义。长模型等待和审核等待在事务外发生。 |
