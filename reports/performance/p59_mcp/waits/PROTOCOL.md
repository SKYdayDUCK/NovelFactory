# 等待与唤醒反例

在隔离 PostgreSQL 17 与已迁移表上运行两项因果实验。模型为本地 HTTP fixture，在收到真实网关请求后用 barrier 阻塞到完成 MCP 读取及续租。比较同一项目三个阶段的六次/阶段短读取。阻塞期间至少要有一个在途 Provider Attempt、有效预留和活租约，网关连接池在取得观察连接之前 checkout 必须为 0，读与续租须早于释放 barrier 完成。释放后核验唯一调用与预算。单工作量演示不构成尾延迟 SLO。

第二项用真实冲突服务生成独立的 review ticket。为下游任务登记持久依赖，在票据待审时用项目 MCP 查询和 resume，必须零唤醒；自审须拒绝。测试脚本代替人使用新授权、独立的 operator 身份交付证据并决定，经明确的项目 MCP resume 应当只唤醒一次。核验前后任务状态、租约、attempt 数和 HEAD，无外部人工、商业费用或生产状态变更。通过验收的边界仅限所用的人审决策契约。
