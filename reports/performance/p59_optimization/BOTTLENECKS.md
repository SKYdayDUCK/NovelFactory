# Measured bottlenecks

**Writes.** On the frozen baseline, each of four changed scope tokens causes its own network round-trip while the branch commit transaction remains open. The paired experiment reduced round-trips with an ordered, deduplicated PostgreSQL upsert. It changes the read/modify/write cost of accepted changesets. The 1000-agent open-read workload commits zero world changes.

**Admission and offer rate.** In the baseline 200-overload run, 716 rejections were recorded by authentication admission, 80 by ingress, 46 by business admission and 7 by the business wait timeout. The HTTP outcomes included 849 responses with status 429. Both authentication and business queues reached 64 waiting requests. Peak application database pool use was 8/8. Across concurrently active requests, authentication and business queue instruments accumulated 477.36 and 649.17 seconds. Cumulative intervals overlap. The observer counted active transaction-id lock waits in two connection samples; most samples saw ClientRead. This evidence does not justify increasing pool size or reducing authority checks. The valid non-duplicate call rate over all 200-agent phases was 12.04/s, with 21 unique world commits. Business recovery passed.

**Load generator.** On 1000 open-read clients and 5000 attempts, fixed-size 2104-byte calibration served every synthetic reply. Using the original client and one CPU each for client and minimal server, the two transport-only wire-start rates were 140.59 and 153.94/s. The full application trial recorded 41.95 wire starts/s and 10.88 validated queries/s. The same generator topology already falls below 950/s when it performs no authentication or database work. The application further costs real permission checks, DB queries, version witnessing and response delivery. Resource sharing and the two calibrated CPU assignments prevent treating subtraction of the rates as a component cost.

**Contracts and allocations.** PG17 pg_stat_statements 1.11 plus a separately instrumented Python allocation trace cover one 100-subject compile. Its traced peak was 4,886,725 bytes. The statement contributing the most execution time inserted 203 rows and generated 101,212 WAL bytes in 4.60 ms. A different profiling run attributed 217.94 ms of a 354.48 ms profiled compile to validation. tracemalloc, cProfile and ordinary timers have distinct instrumentation costs. Compare ordinary latency distributions independently. See raw/server-profile/statement-allocation.json and raw/context-baseline.json.

**Provider and queue behavior.** One/2/4-work schedules used loopback fixtures exclusively. A returned 503 after send left one original UNKNOWN per failed task. Other providers succeeded. Under a single global model slot, four tenants with three jobs each completed in the order 3,0,1,2 repeated three times. All four durable virtual-finish counters ended at 3. raw/fairness.json includes timings and idle returns. These observations cover equal-weight, equal-length requests.
