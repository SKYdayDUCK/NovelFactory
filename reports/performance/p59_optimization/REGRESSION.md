# Regression results for the scope candidate

- Focused PG17 suite: **45 passed**, including history epochs, derived-worker scope reads and the complete query directory. See raw/scope-regression.xml and raw/scope-regression-session/postgres_session.json.
- Independent simultaneous connections: **2 passed**, including two writers submitting the same multibyte and existing/new keys in reverse order, duplicates within each transaction and an abort after the upserts. Version maps after commit and rollback are exact. See raw/concurrent.xml.
- The controlled harness compared both implementations on identical PostgreSQL starting state and one actual prepared request. It verified all 74 pairs, committed each final request once, and re-read the same receipt. The 5- and 100-item worlds include real guarded event writes, scope changes and outbox effects.
- Baseline method timing suite: **18 passed**, real PG17/Redis, actual stdio MCP and synthetic HTTP. Two earlier invocations had **17 passed / 1 failed** when their statistics fixture could not reach the Redis service. The corrected invocation starts Redis in the same namespace as the tests. Raw failed JUnit and logs remain in raw/matrix and raw/matrix-with-redis.
- Runtime experiment with more projects than available slots originally made one scheduler poll per task. That prematurely expected one attempt even when the scheduler legitimately returned IDLE. The final driver records idle admissions, polls the same task, and checks exactly one original Attempt and one send. raw/attempted contains the earlier partial results/script.
- Original AT-30 overload repeated on baseline and candidate. Business recovery passed on the 200-agent runs. Both missed the original offer gate. See CAPACITY_RUNS.md.
- Full repository, dual-service, recovery and native host regressions are recorded at the code-review level with their own tested SHAs. The raw outcomes above concern the scope-upsert candidate and frozen main as labeled.
