# Mixed business requests against frozen worlds

Two character grants, one branch-scoped resume grant and one task-administration binding used the same Uvicorn server and PostgreSQL 17 database in each trial. The two character tasks were assigned different actors and different frozen revisions of the same book and branch. The HTTP clients connected over loopback TCP and the MCP clients initialized the official Python SDK over Streamable HTTP. The fixture built its history through world commands before starting the measured requests. The SDK sessions and HTTP transports were already initialized when each round began. [Registered counts](MIXED_OPERATIONS_PLAN.md) · [Driver](../../../benchmarks/hera_mixed_operations.py)

| 12 | 156 | 60 | 96 | 132 | 24 | 12 | 24 | 24 |

Ten calls per round shared a release barrier, including the initial submit. Three subsequent commands retried the accepted submit, cancelled it, and retried the cancellation. The origin alternated each round. Every command supplied a durable idempotency key. Every response met its operation-specific check, including both scope denials. The database audit counted two receipts and two transitions per new task. In each trial the branch head, seven revisions and five world events matched before and after. Ledger totals for reserved and spent amounts were zero before and after, with zero provider attempts. The raw files contain actor, task and WorldRef identifiers, per-call timings and result fingerprints. ## Replay and interpretation

Use an isolated PostgreSQL 17 administration database, set `NF_TEST_DATABASE_URL` as for the other HERA benchmarks, and run `python -m benchmarks.hera_mixed_operations --output /tmp/hera-mixed-ops` from checkout `9aecab3`. It creates fresh databases for each population. The complementary six tests used checkout `8348b2b`; the subsequent diff touched only this benchmark. The first measuring driver at `9b6925a` encountered a SQL text/UUID array type error while auditing the first trial. The audit was corrected, both trial sizes passed at `8348b2b`, then the status batch was expanded to two distinct IDs with alternating order and both sizes were repeated on the final measurement source. [Initial audit error](raw/mixed-operations/initial-audit-error.log.gz)

The scope of these trials is mixed-operation correctness with four authenticated principals per database, on one host. The longest provider operations, formal commits, renewal, review and Workshop delegation have their own execution evidence. The concurrent batch has no provider IO or billable spend. This experiment has no control arm or throughput adoption threshold.
