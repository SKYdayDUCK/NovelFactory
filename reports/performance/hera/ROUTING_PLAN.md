# Fixed-budget HERA routing experiment

A real stateless plain HTTP and remote MCP application is spawned per replica. A separate client process opens one identity-bound client per endpoint and never reuses one identity's transport for another. The host routes each read using current in-flight operations. A single process has four database connections, two auth and two application slots. Each of two processes has two database connections, one auth and one application slot. No model workers participate. Reserve admin DB connections only for fixture setup and verification outside the measurement.

Each trial performs 128 reads of the same authorized, pre-created tasks. Half use REST and half use SDK Streamable HTTP. All verify the full pinned world reference, owner-specific task ID, generation and state. Barriers exclude initialization and teardown. Preserve raw request times, routing decisions, failures, work, CPU and RSS, and each server's measured connection and admission peaks. This is a closed-loop host test; the separate mixed-ingress burst records cover offered backlog.

First compare 8 versus 32 client lanes in order 8/32/32/8 on one process. Trigger multi-process evaluation only if both reciprocal pairs reach two application slots with waiters and increasing clients 4× adds less than 30% goodput in each pair. Compare single vs RR, least outstanding, and power-of-two choices individually in A/B/B/A order at 32 lanes. Both reciprocal comparisons must improve goodput and preserve 100% correctness and P95/P99 within 20%. Two distinct samples from exactly two replicas give P2C the same decision as least outstanding, modulo deterministic tie-breaking. Retain the explicit measurement. No production routing default changes in this experiment.
