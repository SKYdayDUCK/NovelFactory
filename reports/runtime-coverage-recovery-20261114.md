## 已修复的故障

- 旧事实报告中的问题可能来自历史草稿。原生 MCP 报告读取现在返回受限、不可变的版本来源，独立核查者须比较当前原稿和真实查询，不能把疑问直接判为矛盾。实际 A 的隔离取证中，35 项问题有 34 项匹配历史报告；这只是来源证明，不自动判定问题失效。
- 查询区分未求值、已求值但未知和真实登记错误。未求值只能触发场景范围内的正式覆盖闭包，再核查同稿；未知事实保留证据。错误查询时点、无依据作者决策、缺实际 MCP 与 malformed 输出进入有限修复，不无限重写正文。
- 场景覆盖推进后，后续交接、章节冻结及整卷编辑原先会因混合 WorldRef 停止。现在专用交接验证真实接受与纯覆盖链，冻结时正式重对账同一原稿并建立不可变检查点视图。旧模型查询在原、新切面逐项重新求值；PENDING、UNKNOWN 或变化答案不能借兼容证明变成已审核。
- 覆盖后的整书退修保留写作者的原场景源切面，独立审读使用正式采用切面；原场景、计划和旧回执不改写。子版本通过正常事实对账及独立审核后，才原子切换冻结检查点，再重新编辑和双路盲读。
- 有依赖的后场子稿须实际收到本版已通过三审的前驱全文。交接证明绑定冻结输入、提示、全文交付、版次和真实原子接受回执；普通旧稿交接仍被拒绝，不能单凭版次标签跳过检查。子检查点改用本版事实报告。
- Windows 持久宿主、原生 PostgreSQL 17 客户端、对象刷盘、可信 HTTP 未发送故障恢复和测试 Redis 隔离已有专门回归。普通 pytest 在真实发送边界禁止模型出站。

管理器和恢复调度由程序执行。规划、复杂判断与审核使用 Codex；写作及角色扮演使用 DeepSeek Flash，新测试不发送 Pro 请求。稳定角色/Schema 前缀、材料去重和按需 MCP 读取减少重复输入，实际缓存比例仍以供应商回执中的输入 Token 加权统计；不会把未知用量记为零或承诺固定命中率。
