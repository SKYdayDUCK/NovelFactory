## 消息与 Redis 恢复

原始合同每档使用 8 个 worker，每名员工发送 3 条消息。每第五个操作重发并重复确认。发送和 ACK 走带身份校验的 Workshop dispatcher 与 PostgreSQL 事务，事务期间暂停通知，之后删除独占 Redis Stream 并重建。原门槛要求全部确认、零重复业务效果、恢复不超过 60 秒、发送和 ACK 的 P99 均不超过 2000 ms。

## 岗位、路由与租期

`controls/junit.xml` 记录 21 个通过用例。完整组织路由矩阵实际接受 79 次、拒绝 439 次，覆盖 154 个非边。两项主管调任回归覆盖新增和复职。管理者同时提交两条雇用请求争取最后一个可用岗位时，活跃人数从 8 变成 9，与上限相同。数据库产生 1 条操作回执。胜出的幂等重放与原回执相同，落选方以最新修订再试收到 `ROSTER_LIMIT_EXCEEDED`。

`summary.json` 罗列每份原始 JSON 的 SHA-256。每项服务的启动、停止和退出状态见各目录的 PostgreSQL 会话记录。原始数据、复演命令和源码指纹保存在同目录 ZIP 内。NF 原生 50/200 热点及 1000 开环读按其原负载与 Issue #13 独立报告，W6 验证数据不变更其状态。
