# W0 契约与核验入口

W0 以已签收的 P5.5 主线 `df1e0cc904e3b94a360d86e3a3e00bfec3258673` 为 NF 契约基线。固定的十岗位、十二个 Skill、两个目录 SHA-256 随 AW wheel 一同交付。GitHub 对固定提交与实际运行树分别重算指纹；授权由两个 stdio 服务分别执行。历史 `evidence/W0` 保留原先绑定 `b3b0e9b0` 时的两侧分立运行。[历史原件](../../evidence/W0/run.json)

| 正式检查 | 当前实现和可复核输出 |
|---|---|
| 目录绑定、版本协商、支持的大小与 TTL、私有文件、无效字段与撤权 | [AW 测试](../../workshop/tests)，JUnit 记录实际握手；部署与授权边界见 [Workshop 说明](../../workshop/README.md) |
| NF 项目绑定 | `nf_project_status`、`nf_resume_project`；逐连接发现、受限成功、其他作品与分支拒绝。[NF stdio](../../tests/integration/test_p5_mcp.py) |
| NF 任务绑定 | `nf_task_get`、`nf_context_get`、`nf_query_batch`、`nf_artifact_put`；检验代际、BELIEF 读取、候选写入及幂等。[NF stdio](../../tests/integration/test_p5_mcp.py) |
| NF 编辑任务 | `nf_change_point_request`、`nf_rolling_window_submit`、`nf_change_point_review`；不同编辑任务运行授权调用，核对跨岗位拒绝、首写、重放与正式历史。[滚动计划场景](../../tests/integration/test_p5_rolling.py) |
| 双进程与权限边界 | 各自的真实数据库/低权服务账号，跨库连接失败，两条活跃管道。AW 撤权与重签后旧连接、旧 binding 的重连均拒绝。NF 撤权独立于 AW。[双服务验收](../../workshop/acceptance/test_w0_dual_services.py) |

[W0 工作流](../../.github/workflows/agent-workshop.yml) 对 PR 和 main 在独立 PostgreSQL 17.11 集群上分别迁移两库，运行三组测试。逐工具矩阵来自真实调用的结果，空字段使作业失败。Stage 签收时间、实际 merge SHA 和主线验收会写在 [#7](https://github.com/SKYdayDUCK/NovelFactory/pull/7) 和交付台账。W0 无商业模型调用。
