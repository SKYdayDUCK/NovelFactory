# 第二部分：P5.7 Creative Harness 正式开发

## 八、Harness 总体定位

正式名称：

**NovelFactory Creative Harness**

这是一套面向多智能体小说创作的规划、推演、写作、审核、反馈和优化系统。

不能只是重命名已有模块，也不能只有架构设计。

必须完成实际工程开发。

### 保留三层职责

**NovelFactory Core**

负责世界真相、统一时间线、世界查询、角色认知、任务、正式接受、历史版本和权威调用账本。

**Agent Workshop（P5.6）**

负责组织、员工、层级通信、Skills 授权、任务委托、专业审核人员与组织预算。

**Creative Harness（P5.7）**

负责上下文装配、任务策略、候选规划、隔离推演、创作评估、分层审核、反馈分析、指令优化和质量监控。

Harness 不能成为第二套世界数据库、第二个权威任务调度器或第二本费用账。

优先复用已交付的 NF/Workshop 服务和 MCP 接口。

---

## 九、P5.7 功能目标

Harness 至少包含以下模块：

### H1：Context Harness

负责为不同 Agent 编译合适的创作上下文。

要求：

- 分离工程约束与文学表达材料。
- 保留世界事实和角色认知约束。
- 避免将内部数据库、权限、版本管理术语直接灌入小说正文。
- 支持不同角色的上下文视图。
- 支持章节接缝、人物声音和作品风格。
- 对上下文进行版本和内容哈希绑定。
- 记录内容来源和实际加载结果。

重点研究《潮闸余灯》暴露的问题：

世界事实正确，却把“认知切面、依赖失效、联合裁决”等工程概念写成小说旁白。

这类问题需要在上下文装配阶段就进行防控。

### H2：Planning Harness

管理多候选剧情规划。

支持：

- 从已接受世界状态生成候选计划。
- 对比不同人物目标和冲突路径。
- 识别不合理因果与强行推进。
- 分析剧情后果和局部修改范围。
- 保留合理的意外与人物自主性。
- 不强制每个场景执行多候选规划。

候选计划不得直接变成世界事实。

### H3：Simulation Harness

在受控的假设空间中推演角色与世界。

要求：

- 基于现有 WorldRef 和合法知识切面。
- 人物只使用对应 BELIEF。
- 推演候选与正式时间线严格隔离。
- 可以比较多个假设后果。
- 限制候选数量、Token 和执行时间。
- 仅经现有 NF 正式接受机制提交结果。
- 复用已有分支、冲突检测和状态管理，不开发第二套模拟世界数据库。

### H4：Review Harness

实现真正细粒度的审核系统。

至少支持：

- 世界设定审核。
- 名称与概念自然度审核。
- 编剧与剧情审核。
- 场景调度审核。
- 角色行为与对白审核。
- 句段级文笔审核。
- 章节衔接审核。
- 整卷风格与结构审核。
- 事实与认知一致性审核。

审核应有精确文本锚点、问题类型、影响、反解释、修改建议、修订范围和复核状态。

不能只返回笼统的 `PASS` 或“文笔有待提高”。

#### AI 味审核

重点关注：

- 模式化命名。
- 无必要的组织和制度设定。
- 强行植入的抽象概念。
- 过度解释人物心理。
- 反复使用“不是……而是……”等机械句式。
- 不必要的象征隐喻。
- 工程术语泄漏。
- 人物声音趋同。
- 用旁白解释代替人物行动。
- 场景缺乏具体冲突与互动。

必须根据题材、角色和剧情判断。

不能使用简单禁词表。

例如，“账”在商业或财务剧情中完全合理，但不应无故成为所有人物关系的共同象征。

审核必须保护合理的文学表达、多义性和作者风格。

### H5：Dynamic Agent/Skills Harness

支持可选的动态 Agent 和 Skills。

必须提供总开关：

`creative_harness.enabled = false`

以及独立的动态能力开关，例如：

`creative_harness.dynamic_agents.enabled = false`

`creative_harness.adaptive_instructions.enabled = false`

默认全部关闭。

关闭时，现有静态系统应保持正常行为、权限和性能边界。

开启后支持：

- 动态创建受控 Agent 实例。
- 动态选择合适的岗位模式。
- 在原有授权范围内选择 Skills。
- 创建版本化 Agent Profile。
- 创建版本化 Skill。
- 按作品、团队、角色绑定指令。
- 为运行中的任务冻结版本。
- 撤销旧权限。
- 归档历史配置。
- 回滚不合格版本。

动态 Agent 不能自行授予工具权限，不能通过改写 Skill 绕过服务端授权。

### H6：Adaptive Optimization Harness

实现持续优化：

收集失败样本 → 归因 → 生成候选 → 冻结评估 → A/B 对照 → 审批晋级 → 监控 → 回滚。

优化对象包括：

- 世界设定 Agent 指令。
- 编剧 Agent 指令。
- 卷导演指令。
- 演员行为指导。
- 写作 Agent 指令。
- 文笔审核指令。
- 其他专业审核 Skills。

必须能够区分失败来源。

例如正文太抽象，可能来自：

- 世界设计 Agent 的设定偏好。
- 编剧过度强调主题。
- 写作 Prompt 缺乏自然场景指导。
- ContextBundle 包含过多工程语言。
- 文笔审核未识别模式化表达。

不能一律归因到 writer。

自动优化不得直接修改正在执行的任务。

初期允许自主生成候选和离线验证，但生产指令发布必须遵循授权策略。

`auto_promote` 默认关闭。

`creative_harness.enabled = true`

- 指令更新不污染在途任务。
- 权限、BELIEF、WorldRef 保持隔离。
- UNKNOWN 预算保留。
- 真实双服务恢复可用。
- 优化结果具有可复核的评估记录。
- 失败可以回滚。

1. 原静态系统。
2. 新 Harness，动态优化关闭。
