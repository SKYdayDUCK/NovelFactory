# W4 技能共享与独立审核

[PR #12](https://github.com/SKYdayDUCK/NovelFactory/pull/12) 目标为 `main`，前置 W3 于 `e6763d844f023d7c6a13060dbaebca0416fe3099` 签收。需求见《P5.6 开发阶段与验收计划》W4 行、《P5.6 员工预设岗位与 Skills 共享规范》和《P5.6 审核体系与 Token 成本控制》。既有 W4 原提交 `71b471416c9407e348d4bdce817588def5f11d5b`、冻结来源 `4f7d8ca35bdf0e04045986950edf5819bd572e80` 均保留；历史 67 个通过的用例使用旧 NF 版本。[历史官方工件](https://github.com/SKYdayDUCK/NovelFactory/actions/runs/43073039711)

| 要求 | 正式检查入口 |
|---|---|
| 五类共享范围、角色与任期、旧任务冻结哈希和撤销 | `workshop/tests/test_w4_skills_stdio.py` 通过不同员工的真实 stdio；无法验证原任务归属时保护历史快照。 |
| 七种专业审核、不能自行降低高风险门槛、回避本人/代理与跨主管派单 | `workshop/tests/test_reviews_skills.py`、`test_review_stdio.py`、`test_review_team_assignment.py` 核验审核路由、证据范围、拒绝和额外轮数上限。 |
| 旧安装的审核、决定及重复操作不得向新组织泄露 | `workshop/tests/test_legacy_paid_reviews.py` 用原 W4a 应用和迁移写入两套旧安装的真实数据，然后用新版本做决定、复核和同键重试。 |
| 历史 W4 升级及权限视图 | `workshop/acceptance/test_w4_historical_upgrades.py` 以签收的 W3、最初 W4、旧 W4b 三种发行库验证就地升级。原 W4a 路径由旧审核用例覆盖。早期预演曾把 w002b 用作合流号，正式 W2 用它建立权限视图。w004c 在缺失时执行原视图迁移并完整保留旧数据。 |
| 跨服务审核准入、NF 真实调用账本、组织预算与最终签字 | `workshop/integration/test_w4_paid_review.py` 使用两套独立 PostgreSQL、真实 AW/NF stdio，复用本地 HTTP 模型替身。NF 管理侧核验已存储且通过模型输出契约的当前结果，再执行任务确认并对同一尝试录入显式合成账单。Workshop 在 NF 确认与结算前拒签，之后同键只批准一次。该用例没有商业供应商费用，也不评价作品的文学质量。 |

W3 的双向物理 PITR、Redis 全失与 NF Bridge 真实前置回归仍在常规工作流中运行。冻结候选、主线合并 SHA 和逐项原件由[原 PR](https://github.com/SKYdayDUCK/NovelFactory/pull/12)与阶段签收记录归档。
