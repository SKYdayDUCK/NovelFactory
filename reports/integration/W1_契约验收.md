# Workshop W1 组织与雇佣验收

基线为已签收的 W0 主线 `c4939e24b6b5501d82127f528f2054e9c1992856`。W1 保留原分支的四种预设、组织修订、人员任期、组织图、可见名册与 PostgreSQL 幂等操作回执。

| 需求 | 正常入口及验证 |
|---|---|
| FR-AW-01～04 / AT-40 | 独立数据库从 w000 升至 w001，再追加所有权与名册迁移。虚构作品权限、未声明组织归属、历史同名身份均不得成为 NF 或新 AW 业务授权。 |
| 组织归属 | 一个安装显式拥有一个目录。复用历史 w001 目录前先认领；拒绝另一个安装，同一员工名/任期不能绕过归属核验。旧 W0 令牌保留它已有的协商权。 |
| 名册与雇佣 | 经理、作者与受限员工的投影分别核对。重复 bootstrap、CAS 冲突、占用同槽、不同演员同角色、多次重放、岗位变动、暂停与离职使用真实 PostgreSQL。 |
| 实际 stdio | 管理者通过 MCP 聘用员工，另一个员工进程读取裁剪后的目录，修改本人任期后同一旧连接失去权限；重新启动管理者进程核对已提交的终态与版本。[端到端场景](../../workshop/tests/test_w1_stdio.py) |
| 历史升级 | 原 w000、已有人事/图与操作回执的 w001 各有验收。按升级前的全列逐行核对历史；新角色与公开名册字段使用显式默认值。原始回执随 GitHub Actions 运行保存。 |

W1 的聘用与名册路径没有供应商调用。正式 NF 委托、模型消费及专业审核各在其对应阶段独立验收。W1 合并后对实际 main 重新执行两库迁移、双服务、权限与并发检查，再开放 W2。后续历史修订存在既有分叉时需通过 Alembic 合并修订保存两条已部署的祖先路径。
