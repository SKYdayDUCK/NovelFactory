# W5 作者接续、管理者恢复与组织历史

[PR #14](https://github.com/SKYdayDUCK/NovelFactory/pull/14) 以签收的 W4 主线 `6c711adf794842bdf4469ab51e89093d37761bcc` 为基础。原 W5 提交为 `609e92278476c60a893658ef53b6ff15f659b153`。本阶段复用 `d308e1ce1986a33e4781be97fba8a862b89dd76f` 的安装与任期校验，以及 `bfb74f681435b12a385eb54e596c658e64629276` 的旧部署兼容修复。历史样本保存在 `evidence/workshop/w5/`。本阶段的冻结候选、实际 CI 和主线结果分别写入串行交付台账。[W4 主线签收](W4_主线签收.md)

| 要核对的行为 | 工程入口与可核验事实 |
|---|---|
| 作者从外部 MCP 请求继续项目 | `workshop/integration/test_manager_resume.py` 通过真实 AW stdio 提交同一操作键，使用安装的 `aw-manager-run --route` 启动独立进程。首次唤醒真实 NF 项目，第二次空闲退出。验证持久请求 ID、NF 状态、无新增任务和空闲期间没有启动对端。 |
| 进程失联、重复定时和撤权 | `workshop/tests/test_manager.py`、`test_manager_lease.py`、`test_resume_upgrade_authority.py` 及委托回归覆盖请求幂等、当前安装与任期、运行中撤权、租约交接、进程崩溃和重试耗尽。租约验证与实际对端调用之间须留出有界调用的执行时间。 |
| 办公状态、进度与历史 | `aw_state_get`、`aw_progress_get`、`aw_history_get` 从服务端员工身份取可见范围。分页游标绑定安装、员工、任期、授权代际和固定读点。测试需要核对变更归属后旧绑定的读取和历史重放。 |
| 已部署数据库 | `workshop/acceptance/test_w5_historical_upgrades.py` 使用已签 W4c、初版 W5、W5a 和 W5b 的真实程序构造旧库。比较旧字段与行、历史序号、授权、活动请求以及新库目录。保留已发布的迁移编号和分支拓扑。 |
| Workshop 离线时的 NF 与恢复 | `workshop/integration/test_paired_restore.py` 使用不同 PostgreSQL 集群、不同服务登录、独立 stdio、本地 HTTP 替身和物理 WAL。记录原操作键及对端回执，检查恢复围栏、Attempt 和托管预算。 |
| 旧功能与交付 | Workshop 与 NF 的既有正式 CI 继续运行。分别归档 PR 事件与合并后 `push` 事件的源码、Git 树、JUnit 及原始工件。Issue #13 的容量阈值和未达标结果沿用原记录。 |

部署时由操作员按 `workshop/README.md` 配置受信项目与委托命令，私有路由文件由执行服务的用户持有，权限为 0600。定时入口在 `workshop/adapters/systemd/`，作者 MCP 入口在 `workshop/adapters/codex/`。执行恢复前停止定时器和管理者进程，启用恢复围栏。需要回退数据库时使用相互匹配的备份，保留两侧回执并先进行只读对账。
