## 本批解决的问题

P2-04 至 P2-06 需要让世界、正文、审核及发布成为分别可追溯的接受边界。将任意 JSON 保存为“通过报告”，或者给同一旧稿换一个 WorldRef，都不能构成闭环。本批在原有 artifacts、selections、receipts、任务和 outbox 上实现这些边界，不新建世界状态来源，也不增加数据库表。

| 阶段 | 输入与实际输出 | 接受门禁 |
|---|---|---|
| 场景和写作 | 复用原 SceneContract；固定 ScenePlan、plan/node、batch、风格、前驱交接；精确 UTF-8 TEXT 与 DraftRecord | 角色、task/generation、controller plan binding、场景时间、当前场景选择及前驱接受均有效 |
| 抽取与对账 | 实际原文交付、Unicode code-point span、分类断言、关键状态核验、Reconciliation/Alignment 及服务端验证执行记录 | 伪造 PASS 不足；重要新增必须正式接受；不确定、历史冲突、遗漏必需事件或错误认知均阻断 |
| 正文接受 | 不可变 NARRATIVE_ACCEPTANCE、event links、明确披露记录及本地选择 | 本事务复验，世界效果数恒为零；接受正文不代替文学批准 |
| 文学档案与审核 | 原文覆盖、反证、声线、人物选择证据；场景、章节、接缝、整卷分层报告 | 摘要或节选不能冒充全文；不同 reader/旧 hash/旧代际不能借用覆盖 |
| 整卷编辑 | STRUCTURE → SEAM → LANGUAGE；结构选项、弃用理由、功能图与具体分歧决议 | 有界轮次、CAS、硬冲突不能审美豁免；最终精确稿必须重新复核 |
| 内部发布 | 固定有序正文、共同 WorldRef、plan/style/arrangement/disclosure/literary 引用与独立批准，生成原 core ReleaseManifest | 当前正文及前驱选择、精确批准、当前授权、prior release CAS；旧清单保留，未执行外部投递 |

详细接口见 [正文对账实现](../src/novel_factory/application/narrative.py)、[文学审核与编辑](../docs/implementation/P2_文学审核与编辑.md)、[固定快照与发布](../docs/implementation/P2_固定快照与发布.md)。原核心 2.0 文本/发布契约不改，增量结构使用独立 narrative/editorial/release Schema。

## 几个必须明确的行为

**多次叙述同一事件只建立呈现关联。** 对账使用 occurrence_id 和 event_version_id，正文接受与 release 不调用世界效果重放。新交易、伤势、重要信息等不能作为 SURFACE_DETAIL 隐藏：写作者的重大增量声明必须得到对应抽取，待审提案未经过 Kernel 接受前，相关正文不能正式接受。

**新世界状态必须显式对齐。** 同一分支的后续切面可以重算 AlignmentReport 后保留相同原文字节，批准必须重新绑定。无关世界提交不会机械废弃固定快照；与正文事实、计划前提、认知或衔接有关的变化会同步阻断。跨分支不会放宽 `ancestor` 检查：必须新场景、新任务、明确原稿来源及重新资格验证，不能把 branch_id 改名。

**模型产物接入不扩大材料权限。** `RuntimeTaskService.prepare` 通过正式应用服务创建有界角色任务及固定上下文；`AgentGateway` 的服务端材料端口只交付控制面授权的场景、原文和文学记忆。把 ArtifactRef 填进 TaskSpec 本身不授予阅读权。原 `Kernel.get_artifact` 规则保持不变，writer 没有增加 PLAN 权限。

**全文覆盖是交付证据。** 原文读取回执记录实际返回范围及精确 hash，覆盖合并使用 Unicode code point 半开区间。覆盖不等于理解，工程审稿夹具不等于真实模型判断，也不等于作者已经读完。

## 实际验证与失败记录

各模块已在隔离 PostgreSQL 17.11 下进行定向验证，包含真正的独立连接/CAS、撤权/取消、提交前失效、丢回执、事务回滚及精确材料访问。最终合并回归 **364 项全部通过，170.92 秒**，`fsync=on`、`synchronous_commit=on`。机器结果见 [final.xml](../evidence/p2/batch2/final.xml)、[final.json](../evidence/p2/batch2/final.json) 及 [PostgreSQL 配置](../evidence/p2/batch2/final-pg/postgres_session.json)。不把各轮重复运行相加来夸大覆盖数量。原设计包检查仍为 PASS，原核心 schema 冻结测试和 P1 并发、恢复测试均在本次全量运行内。

额外跨模块测试 [test_gateway_narrative.py](../tests/integration/test_gateway_narrative.py) 实际执行：创建角色任务 → 未授权材料零派发 → 控制面绑定 → Gateway 候选 → RESULT_STORED → 精确候选正文 → 全文抽取/对账 → 正文接受。改变保存的模型候选文字被拒绝，世界修订与事件数均不变。[PG 证据](../evidence/p2/batch2/gateway-narrative.xml)。适配器明确为 `TEST_FIXTURE`，此测试不计为真实模型生产实验。

开发失败包括 narrative Schema 的 commands 引用 URI 错误、测试漏写 StoryInterval.bounds、改稿测试未把 prior_draft_ref 冻结到新任务输入，以及取消审核的公开错误码与底层错误码预期不一致。修复引用与夹具，保留真实拒绝条件；失败 XML、日志和最终成功证据保存在 release/narrative 子目录。

## 本批的边界

角色“已知”证据必须来自其当时真实认知来源，猜测正确不自动成为知情。没有已注册、能证明发言者/时间/内容的 speech 模板时，重要 `SAYS` 断言保持未决，不能借用任意资源转移事件制造传播事实；正式认知接收仍使用原受约束的 RECORD_COGNITION。

当前发布为内部不可变清单和本地正文导出，外部投递明确 `NOT_REQUESTED`。真实模型生产实验仍为 `BLOCKED_ENVIRONMENT`，作者完整阅读仍待完成。本批工程测试通过不能据此宣布完整 P2 出口或文学质量验收通过。
