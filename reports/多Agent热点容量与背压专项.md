### 本轮基线队列定位

在可用 CPU 6–8 的独立 PG17.11 和服务进程上，200 人热点基线先执行一轮。200 人均完成突发前的业务，得到 21/21 个新世界提交；145 人同时完成了额外突发读，全体完成 2,081/2,141 项预定操作。客户端共观测 1,114 个 HTTP 429，恰好对应服务认证队列满 954 次、认证等待到期 3 次、操作队满 58 次和操作等待到期 99 次。入口拒绝数为零。HTTPX 池等待 P95/P99 为 83.42/340.04 ms，服务端 50 ms 周期的心跳超期 P95/P99 为 13.20/43.16 ms，突发实际请求头开始 32.11/s。峰值连接、数据库 CPU 采样值、各级队列明细见 [独立基线](../evidence/scion_round2/s4/pilot.json)。

这次试跑的候选在输出硬件身份时退出，其目录缺少本地 Git 元数据。保留的基线只用于定位该次 429 来源。后续对照重新创建完整的独立检出，从同一 PostgreSQL 模板和对象目录分别恢复两臂。跨运行的 CPU 和 UUID 不用来配对。

## 候选与语义

固定契约源中有 15 份 Draft 2020-12 文档和 1,031 个静态引用。服务反复验证输入、结果、工具及领域契约时会重复解析这些引用。在 `NF_SCION_SCHEMA_LINKS=1` 下，服务按定义预解析固定的 schema 引用，现有 Draft 2020-12 验证器仍对每份新请求执行格式、分支、类型等约束。表中当前 207 个定义全部能静态解析。缓存只保存项目内 schema，无输入、认证结果、授权决定或查询结果。

每个根文档须明确使用支持的方言；引用目标也执行相同检查。未知词汇、动态作用域、内嵌资源 ID、非标准引用、带额外约束的引用或循环均回到原注册表。候选拒绝时执行原校验路径，沿用原错误码与脱敏信息。默认关闭此开关。池总额 8、准入与限流、等待上限、重试预算和实际业务成功判据保持原配置。

冻结的本地候选 `06adae39e576c0cb96978b5b8b1c11e727b5fc9b` 只引入该候选、针对性测试和测量脚本。两边使用同一测量器；基准客户端、数据准备和客户端响应验证均使用原路径。每个服务进程在退出时回报实际开关状态、ASGI 收到请求数以及 50 ms 心跳延迟。各进程的分位数单列，单进程的峰值缺少同时性，不能直接相加推算系统峰值。心跳反映事件循环超过预约时刻的延迟，可能受 CPU 调度和同步工作等多项影响。原 PostgreSQL CPU 仪表根据 /proc 的父子信息累计，宿主隐藏活动子进程时会少计。数值为零也不能推断数据库没有消耗 CPU，归因另列 SQL 计数、连接归还、数据库缓冲读与死锁。

开启候选后，契约与准入测试 113 项通过。差分覆盖仓库合法与非法样本、逐个删除已有字段、额外字段、空值、子集变更、跨文档方言、循环、动态引用及根定义名与嵌套引用的指针转义回退。固定实例的局部重复校验中，先导版本的查询请求、BELIEF 查询结果、上下文结果单次均值分别从 0.682、0.953、0.959 ms 降到 0.399、0.584、0.610 ms，每项约 300 次。先导版本和最终保守白名单在全部 207 个项目定义生成相同的 schema，当前定义名均为简单 ASCII 标识符，聚合 SHA-256 为 `744201ba0c69cbe4e32f41b312880e333b46cbec5615ce201ad45a9d274c3d53`。局部耗时不足以证明实际吞吐提高。

## 真实 PostgreSQL 对照

正式对照原始配置沿用 200 热点 80% 共享、1 个 API 进程、全组总池 8；1,000 开放读、500 混合与 600 秒持续读均为 2 个 API 进程、全组总池 8。CPU 6–7 上 200 热点、1,000 开放读和 500 混合依序运行。600 秒在 CPU 8 上测量，同核另有独立 S5 测试，两臂的共享负载时序可能不同。原始输出含逐请求有效性、状态、ASGI 计数以及真值与阶段计数。相同工况的两臂比较需先检查输入指纹、CPU 集、实际加载源码、服务开关和判定。
