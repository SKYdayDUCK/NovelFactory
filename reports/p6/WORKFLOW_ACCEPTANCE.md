# P6 原生写作窗口工程验收

本报告记录可配置生产板在真实 PostgreSQL 17.11 上的工程实验。文中“章”是短小的工程样文；三条正式创作输入的文字、模型用量和发布成绩由本目录的创作验收报告单列。

| 场景 | 通过条件与实测路径 |
|---|---|
| 单窗三章，其中第三章依赖前两章 | 已采纳的计划及场景进入原生 P5.8 生产板。依赖场景停在 `WAITING_HANDOFF`，前两章获得正式接受引用后才可登记该场写手任务。原生绑定在领取时核查前驱和固定上下文。 |
| 三个单章窗口 | Supervisor 每次有界推进，测试在每一步重建 Supervisor。三章共十二次本地工程 Provider 调用，每章分别由写手、人物认知评阅者、事实抽取员和章节读稿人各执行一次。按注册的章序收集不可变文本、草稿、章读稿和接受回执。 |
| 事实对账与正式接受 | 独立认知评阅者先核对同版正文及人物获知时点，发现问题时保留报告并阻断接受。另一身份的抽取员收到准确的全文交付，在返回值中列出引句及分类。服务核验引句唯一且共同覆盖全部非空白文字，计算 Unicode 跨度和哈希，执行 `submit_extraction`、`reconcile` 及 `accept_narrative`。随后重新读取当前选定接受、核查规则与认知证据，并匹配写手任务、代际、场景及章节读稿所见草稿。 |
| 错误分类与缺页 | 对含 `UNCERTAIN` 的提取，原生对账生成 `BLOCKED` 回执且接受表为空。读稿漏掉最后一个标点时，系统拒绝该引句集并保留失败任务与模型返回。 |
| 首卷进入次卷 | 两个独立卷共两章、八次工程 Provider 调用。首卷各章获得接受和读稿，独立编辑批准绑定完整的冻结版本后，Supervisor 调用 `ReleaseService.freeze`。连续性审核未齐时游标等待。针对预期前缀与卷序的独立连续性批准齐备后，主管发布快照并开启下一卷。次卷写手材料包含新场景和经过权限过滤的前卷连续性快照。 |
| 终卷未取得全书盲评 | 最后一章已固定时，普通 P2 编辑批准仍须经过 P6 全文盲评门禁。工程模型没有真实盲评分数，两种三章窗口设置均被阻止发布。 |
| 分支域与资源 | 许可绑定作品、分支、原授予者、权限代次、策略版本、原生预算及到期时间。下一窗口按其已采纳场景缩小人物读写的故事时间上界。只读状态要求当前 ADMIN，选区和窗口在应用事务内持久化。 |
| 局部重规划 | 在可重规划的 Profile 中，操作员可提供该范围的新采纳场景，使用当前世界和窗口引用进行比较并更新。已打开的本窗拒绝替换。其余窗口、章节身份、现有冻结文本保留。 |

同一锁版环境的滚动、P5.8 原有生产板及底层发布回归共 19 项通过。阻断事实及不完整引句两个反例另行通过。新增的人物认知逐场复查见 [灵感、滚动及认知联合回归](evidence/epistemic-workflow.xml)。此前的原始记录见 [19 项回归](evidence/rolling-provider-recovery.xml) 与 [两个阻断反例](evidence/rolling-blocked-facts.xml)。

## 独立运行

从仓库根目录，以启用 PostgreSQL 17 的项目测试环境执行下列命令。测试启动回环 HTTP 工程 Provider。不同测试为已知零费、已发送但响应丢失和缺少财务回执分别建模。

```sh
uv run python -m pytest -q tests/integration/test_p6_rolling_production.py tests/integration/test_p58_production_pipeline.py tests/integration/test_release.py
```

创作启动、后续卷授权和路由配置见 [模型运行证据](MODEL_RUNTIME_EVIDENCE.md)。对于已注册生产，`scripts/nf.py supervisor --access-file <private/supervisor.json> --rolling-status` 返回本次运行 ID、章节目标、目前登记的章节数、冻结章数、当前窗口序号和原因、最后一个检查点及正式发布引用。检查点记录有序章节和上一检查点，可按原顺序重建固定前缀。

本轮工程样文不计入正式文学轮次。首卷编辑批准及连续性审核的测试输入通过正式服务递交。实际作品的编辑、世界事件接受、已核验模型账单、两名独立全文盲评及最终内部发布仍各自需要真实运行回执。

### 卷间编辑、发布与连续性移交

在两个各一章的工程卷上，冻结首卷后重开 Supervisor。缺少编辑批准时保留 `RELEASE_INCOMPLETE`。把首卷的正式编辑批准撤回后，下一次调度得到 `EDITORIAL_APPROVAL_REVOKED`；数据库仍无首卷 RELEASE 选区。重新取得同一版本的有效批准后，Supervisor 从已冻结的场序推导发布请求，调用原生发布服务。读回 `RELEASE_RECORD` 可核对其引用的是新的批准。

中长篇预设要求跨卷记忆。即使独立评阅者批准了空记忆候选，游标也会保留首卷位置。读过准确的卷序、当前前缀和原文证据后，独立评阅者仍可提出 `CHANGES_REQUIRED`，此时没有发布连续性快照。取得新的 `APPROVED` 回执后，Supervisor 原子提交连续性快照并转入次卷。校验覆盖快照内的评阅引用、已发布卷序和次卷写手实际收到的连续性材料。正例使用正式权限、真实 PostgreSQL、明确标记的本地工程模型和测试中通过应用服务签下的编辑/连续性意见。[PG17 对照回执](evidence/serial-publication-postgres.xml)

仍须有独立覆核者按章生成所需文学评价、编辑决策及正式批准。新增移交代码消费这些原生批准；真实独立编辑与连续性意见的生产仍需授权模型和相应审核职责实际执行。本轮三部作品没有内部发布记录。
