# P5 运行与交接

作者在已配置的项目里输入 **继续未完成的任务**。Codex 使用专属 MCP 连接调用 `nf_resume_project({})`，从 PostgreSQL 恢复等待边与租约。独立服务领取已有派发授权的 READY 任务。等待、空闲和重复提醒只执行数据库工作。关闭编辑器不会停止独立服务；关闭服务或机器后，恢复发生在下次启动。

## 首次接入

1. 在 Linux 或 WSL 的服务账户下准备 Python 3.12、PostgreSQL 17 和持久对象目录。安装锁定依赖 `uv sync --locked --group dev`。当前真实 Host 回归使用 `codex-cli 0.167.0-alpha.4`。服务账户的 PATH 需要能够解析原生 `codex`。服务需要以下环境：`NF_DATABASE_URL`、`NF_OBJECT_ROOT`、`NF_MODEL_ENDPOINT`、`NF_MODEL_NAME`、`NF_MODEL_API_KEY`。模型端点接收 HTTPS Chat Completions。服务端的私有配置不进入 git、编辑器工作区或角色提示。
2. 在新测试库或已经备份的目标库执行 `uv run --no-sync python -m alembic upgrade head`。若需验证接线，用 `uv run --no-sync python scripts/bootstrap_p5_m0.py --private-dir /var/lib/novelfactory/private/m0` 新建隔离样例。它包含一项 READY 和一项有前置条件的摘要任务。重复初始化会复用样例。对已有作品，管理员用 [恢复授权签发步骤](../adapters/codex/P5-stdio.md) 绑定明确的 work 和 branch，并按[任务登记步骤](P5-03.md)登记所需角色、预算与切面。
3. 在服务账户前台启动 `uv run --no-sync python scripts/run_supervisor.py --access-file /var/lib/novelfactory/private/m0/supervisor.json`。生产中可以使用[独立服务单元](../adapters/systemd/novelfactory-supervisor.service)。按部署情况调整项目、配置和凭据绝对路径，环境文件由服务管理员维护。默认示例使用服务账户 novelfactory 和可写目录 /var/lib/novelfactory。在采用 systemd 的主机安装单元后执行 `systemctl daemon-reload` 和 `systemctl enable --now novelfactory-supervisor`。可用 `journalctl -u novelfactory-supervisor` 查看状态；单次诊断可在前台命令最后追加 `--once`。
4. 作者账户使用专用受限 SSH 密钥，将[模板](../adapters/codex/p5-mcp.toml)加入 Codex 配置。服务器端强制执行 stdio MCP 程序。编辑器账户与角色账户均不应读到服务器的数据库 DSN、对象或管理员绑定，也不能改写服务代码。作者端在 VS Code 重新打开项目，输入恢复指令。客户端预期只列出 `nf_project_status` 和 `nf_resume_project`。见[桌面验证和脱敏取证方法](../adapters/codex/P5-stdio.md)。

## 数据库回退与故障恢复

先停止该作品对应的 Supervisor，保存数据库和对象库的匹配备份，并在新的隔离数据库验证。P5 新增 0004、0005、0006。对没有 P5 业务数据的库可运行 `alembic downgrade 0003`。有等待、授权或 Host 数据时，保护性迁移会拒绝可能丢失记录的回退，事务回滚。生产事故中优先选择已验证的备份及同一恢复点的对象。物理 PITR 复验可在新目录运行 `uv run --no-sync python scripts/pitr_drill.py --output /tmp/nf-p5-pitr-new-dir`。

恢复先检查调用账本。发出后失去回执的调用进入 UNKNOWN，保留预留额；后台不会重新花费这笔费用。管理员用 attempt ID、供应商回执、调用审计产物与数据库结果核对。世界事实只由 Kernel 的接受收据确定。WAITING_REVIEW 保留无效行动、需要作者裁决或权限已经变化的交付；更换权限、改写已发布历史和对外发布需要各自授权。

## 为已有作品登记一场可自主推进的互动

在服务端准备已正式接受的 WorldRef、当时到期的语义互动过程、已选用并排定未来节点的卷计划、该作品的共享预算。管理端一次登记参与者、各自的等待条件和允许自动接受的作用范围。注册、签发岗位 grant 和写入 DAG 在同一事务内完成。普通作者恢复凭据没有登记权限。

```bash
uv run --no-sync python scripts/run_supervisor.py \
  --access-file /var/lib/novelfactory/private/supervisor.json \
  --register-scene /var/lib/novelfactory/private/scene.json
```

下列 JSON 给出字段格式。用项目真实的 UUID 与完整 WorldRef 替换占位值。每个登记键只对应一次同内容的登记。模型连接配置与实际费用预留来自服务端。

```json
{
  "world_ref": {"work_id":"<作品>","branch_id":"<分支>","world_revision_id":"<已接受版本>"},
  "volume_id": "<已选计划所属卷>",
  "story_time": {"tick":30,"phase":0},
  "scope_ids": ["<场景地点一>","<场景地点二>"],
  "participants": [
    {"actor_id":"<A>"},
    {"actor_id":"<B>","after_actors":["<A>"]},
    {"actor_id":"<C>"}
  ],
  "subject_id":"<A>",
  "destination_id":"<场景地点二>",
  "scene_limit":2,
  "budget_id":"<作品预算>",
  "adapter_id":"codex-text",
  "reserve_amount":"1",
  "token_reservation":100000,
  "idempotency_key":"volume-1-banquet"
}
```

`after_actors` 安排本场角色之间的执行顺序。需要等待已登记的信使或其他前置任务时，使用参与者的 `after_tasks` UUID 数组。任务完成信号只唤醒接收方，其模型输入仍由自己的 BELIEF 和时间切面决定。管理员可用 alternative_destination_ids 增加本场已登记的地点。裁决可以选择留在原地或本场任何一个获准地点；角色模型只收到自己的任务。其他效果、未解决问题和授权范围外的变动留在 WAITING_REVIEW。任务拒绝或暂缓时，运行记录保留其具体原因。

一次登记覆盖本场角色、联合裁决、正式接受、卷纲复核和有重大偏离时的两个上层规划任务。下一场、下一卷的卷约以及实际作者审美决策需要各自的输入与授权。[实现与复验](../tests/integration/test_p5_autonomous_banquet.py)

登记的联合裁决限定一个到期的语义互动过程。专项覆盖留在原地、选择备用地点、伪造引用、越权资源效果和写入中途崩溃。[联合裁决与回退](P5-06_joint_handoff.md)

## 故障与修复记录

中间提交的远端回归发现跨卷夹具仍返回摘要形状，导致 WindowPlan 候选校验失败。提交 `4bc4b3f` 加入按测试场景提供类型化候选的入口；该提交的[远端工程回归](https://github.com/SKYdayDUCK/NovelFactory/actions/runs/42965997261)通过。生产网关仍核验冻结的输出 Schema。

并发审查发现初次登记时两个连接可能同时持有作品行共享锁并请求升级。提交 `128a57f` 统一为先取得作品行更新锁，再核验角色并查找既有收据。两个并发登记收到相同结果，循环依赖登记整笔回滚。独立 CLI 检查还验证了服务配置的分支围栏：同一作品管理员握有通配授权，用主分支访问文件登记另一分支的实际任务得到 VIEW_DENIED；授权、Outbox 和调用账本没有变化。使用目标分支的合法访问文件则新建一个登记，两个步骤均未发起模型调用。
