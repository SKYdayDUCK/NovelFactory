# P2 第一批：规划、世界过程和外部 Agent 接入

日期：2026-11-10。开发分支：`dev/p2-production-loop`。
继承的已验收 P1 基线：`721f155c9cc912cddfdae559afe4f2516d0967f2`。

## 范围与实现

本批对应 P2-01 至 P2-03，沿用现有模块化单体、不可变世界修订、固定任务输入、角色授权、短事务接受及调用费用账本。原 `core.schema.json`、`literary.schema.json` 和 `temporal_concurrency.schema.json` 保持原始字节。

| 任务 | 可运行能力 | 证据及限制 |
|---|---|---|
| P2-01 | 世界底稿与独立审核；卷契约及窗口；类型化计划、采用 CAS、局部重规划；计划依赖的同步任务围栏 | [实现说明](../docs/implementation/P2_世界与卷规划.md)。底稿审核不创造事实；新增世界设置仍须经过受信初始化或内核接受。 |
| P2-02 | 正式登记过程；入站下界与闭包；无角色确定性过程求值；共同前态的密封角色意图及联合裁决；原子接受；模型返回顺序置换不改变选中结果 | [实现说明](../docs/implementation/P2_世界调度.md)。登记的预计结果不是已发生事件，超时不造成角色失败。带过程的历史修订需要专门重建，目前返回 `SCHEDULE_REPAIR_REQUIRED`，不会复制无效推进证据。 |
| P2-03 | 冻结角色/技能/模型配置；无工具 HTTP 模型适配器；任务绑定、单次派发、预算及未知费用保留；原始输出、错误和候选存证；有界 worker 及 CLI | [实现说明](../docs/implementation/P2_Agent接入.md)。真实模型生产验收仍受环境阻断；单进程 worker 上限不代表全局 provider 配额或 200 模型并发。 |

进程登记与推进状态位于已有不可变 `WorldRevision` 的 `provenance.simulation_state`，其哈希加入 manifest。新建的三张不可变协调表只保存交互、意图与被选候选，没有引入第二套世界权威。迁移 `0003_p2_simulation` 仅添加结构，不回写 P1 记录。

控制面与运行时 Agent 保持分离：角色提出行动，确定性规则或有来源的语义建议给出候选，仍由 Kernel 的已授权接受建立世界历史。网络调用前释放数据库连接，调用期间撤权或取消会阻止候选交付，但保留费用及迟到输出证据。

## 验证记录

基线先在隔离 PostgreSQL 17.11 上执行完整测试：248 项通过，71.19 秒。GitHub 的既有基线运行 [42791882463](https://github.com/SKYdayDUCK/NovelFactory/actions/runs/42791882463) 亦为成功。

第一轮整合回归 267 项通过，74.58 秒；该轮发生在最后一批定向测试加入前，不作为最终覆盖数量。[原始结果](../evidence/p2/batch1/attempt1.json)和 [JUnit](../evidence/p2/batch1/attempt1.xml)均保留。

最终完整回归 **307 项通过，92.68 秒**。结果记录在 [final.json](../evidence/p2/batch1/final.json)、[final.xml](../evidence/p2/batch1/final.xml) 及 [PostgreSQL 会话](../evidence/p2/batch1/final-pg/postgres_session.json)。单元、契约和 HTTP admission 单独执行 162 项通过。[结果](../evidence/p2/batch1/unit.json)。

关键反例包括：

- 双连接首次计划采用竞争；计划依赖被毁但异步重规划尚未执行时立即阻断；无关节点继续。
- 三角色返回的全部六种顺序；缺失角色输入不推进；条件不成立没有交付；入站下界等界及独立地区推进。
- 同键及不同键并发派发；未知费用阻止盲目重试；无凭据零派发；错误角色、私有材料及无隔离证明 Host 拒绝。
- 在 `0002` 创建并接受真实 P1 世界，再升级 `0003`，逐表记录摘要保持不变，同一接受请求仍返回原回执。[升级测试](../tests/integration/test_p2_upgrade.py)。
- 备份包含精确角色、技能、目录及查询权限文件；丢失角色正文或版本不匹配不能宣称恢复成功。

开发期间的失败不删除：规划测试中的不完整 bootstrap 夹具、测试查询漏 cursor、跨目录重复测试模块名，以及网关规范化数据的 tuple/float 错误均已修正。对应仍存在的原始 XML、JSON、会话日志保存在各模块证据目录。无法回溯原始文件的早期本地终端失败只作为开发说明，不补造原始日志。

## 真实模型验收状态

当前没有可用的 `OPENAI_API_KEY`、`ANTHROPIC_API_KEY` 或 `NF_MODEL_API_KEY`。检测到本机 Codex 的 ChatGPT 登录状态后，进行有限的无世界数据连通性探测，四次均未到达模型派发：三次应用服务初始化报只读文件系统，一次严格配置检查拒绝现有不兼容配置。

状态为 **BLOCKED_ENVIRONMENT**，确认模型请求数为 0，实际费用为未知/未取得计费凭据，不能据此写成“真实模型验收通过”或价格为零。[脱敏探测清单及日志](../evidence/p2/live_probe/manifest.json)。未修改权限、运行时根目录或用户配置来绕过限制。

可复现的模型接入使用明确授权的 endpoint、模型、凭据和预算；`scripts/run_agent.py` 只运行已创建、编译、领取并绑定输入的任务。HTTP 协议夹具与确定性 Agent 适配器一律标记 `TEST_FIXTURE`，不计入真实模型生产实验。

## 后续批次及停止门槛

第二批将实现正文产物、事实抽取与对账、文学档案和多层编辑、固定快照并行写作与发布；第三批完成端到端短卷、A–H、50/200 行为负载和恢复。第一批通过不能被写成完整 P2 出口通过。

P2 的真实模型短卷及真实作者全文阅读报告仍是独立门槛。P3-01 只能在 P2 验收满足后依实测瓶颈考虑，P3-03 最多建设评测基础，不推断文学质量收益。其他 P3 与 P4 不在本轮范围内。
