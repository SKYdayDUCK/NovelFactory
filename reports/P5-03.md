# P5-03 运行与实测

## 首次配置

在已迁移到 P5 的测试项目中启动独立 Python 调度进程。生产使用有权处理该作品的服务身份，通过私有配置文件提供 `token`、`work_id` 和 `branch_id`。此身份只进入 Python 服务。给 VS Code 的恢复凭证单独签发，给角色的运行授权由数据库绑定。该版本的后台服务需要作品级 ADMIN，它能读取受限材料，应部署在作者信任的机器上。

在服务进程环境中设置 `NF_DATABASE_URL`、`NF_OBJECT_ROOT`、`NF_MODEL_ENDPOINT`、`NF_MODEL_NAME` 和 `NF_MODEL_API_KEY`。模型端点支持 HTTPS Chat Completions，服务层固定模型配置和费用预留。选择 `codex-text` 还需 PATH 中有支持 `codex app-server --listen stdio://` 的 Codex CLI。本次实测版本见下方证据。Python 子进程启动 Codex 时仅设置临时 HOME、临时 CODEX_HOME、系统 PATH 与回环代理例外。

## 新建可运行的两轮示例

在服务端完成上面的环境配置，并将 PostgreSQL 17 数据库迁移到当前版本。下面三条命令从空库创建独立的合成作品、一项 READY 摘要和等待该摘要的第二项任务，随后启动后台执行。目录必须属于服务账户且权限为 0700。两项任务各有最多 100,000 token 的预留和 1 USD 的账本额度；真实模型供应商必须单独配置、授权和计费。初始化本身不会发送模型请求。

```bash
uv run --no-sync python -m alembic upgrade head
uv run --no-sync python scripts/bootstrap_p5_m0.py --private-dir /var/lib/novelfactory/private/m0
uv run --no-sync python scripts/run_supervisor.py --access-file /var/lib/novelfactory/private/m0/supervisor.json
```

将强制命令的 MCP 绑定路径指向同目录 `resume.json`，然后在 Codex 输入“继续未完成的任务”。样例只写新作品，重复运行同一初始化命令会识别已创建的项目。配置写入前发生错误会回滚数据库事务；恢复凭证有效期默认 24 小时。两份带令牌的文件均保存在服务端且权限为 0600。SSH 强制命令与作者侧配置见 [Codex 接入说明](../adapters/codex/P5-stdio.md)。

## 交付一个任务

1. 用现有 `RuntimeTaskService.prepare` 创建岗位、故事时间和输入固定的任务，并设置 `adapter_id="codex-text"`（或 `external`）。就绪任务用 `queue_state="READY"`，有前置条件的任务用 `queue_state="BLOCKED"`。省略 `queue_state` 仍保留既有的立即领取、编译行为。
2. 对等待任务，调用 `WorkflowService.wait` 写入明确前置任务和 AND/OR 组。前置任务的 ACCEPTED 事件满足条件时，新一轮获得新的 generation、lease 和 ContextBundle。恢复后的 Codex 轮次使用新的 Thread ID。
3. 用任务所属作品已配置的 budget_id，准备一个私有登记文件。字段为 `task_id`、`manifest_ref`、`knowledge_cut`、`context_tokens`、`input_ref`、`budget_id`、`reserve_amount`（十进制字符串）、`token_reservation`。两份 ref 使用步骤 1 返回的 `manifest_ref` 和 `agent_input["input_ref"]`。对自愿走自动摘要交付的 `evidence_maintainer/summary`，可额外提供 `accept_summary: true`。普通运行结果进入既有候选审核流程。
4. 登记及启动服务。重复登记同一内容会返回原有配置。每次扫描都要重新通过数据库授权。服务在无就绪任务时休眠，等待期间只运行确定性代码。

```sh
uv run python scripts/run_supervisor.py --access-file /private/scheduler.json --enroll /private/job.json
uv run python scripts/run_supervisor.py --access-file /private/scheduler.json --interval 1
```

`--once` 可运行一次恢复扫描和最多一次推理。停止常驻进程后，重新执行上面的启动命令即可续接。未返回的供应商请求先核对 `nf_call_attempts` 中的调用身份与供应商账单。已结算但未交付的候选也需要对账。该版本自动阻塞这种调用，保留调用与结算记录，人工关联供应商收据和持久产物后再决定后续处置。

## 隔离与审计

每次 Codex 执行均使用空工作目录、独立配置、只读沙箱和审批关闭策略。关键隔离发生在服务拥有的单次文本传输边界。上游只能收到 AgentGateway 已编译的角色消息和合法 KnowledgeCut。Codex 提供给本地端点的提示、工具定义与任何本地文件均不转发给模型。返回的正文通过 JSON 编码成为唯一的 assistant 文本项。上游返回工具调用将被 HTTP 适配器拒绝。即使正文包含形似工具调用的 JSON，也只能作为正文抵达 Host。二次请求遭拒。模型凭证与数据库凭证均不进入 Codex 子进程。

调用账本先取得唯一发送权，再启动 Host。线程和轮次记入 `nf_host_turns`，分别通过 `attempt_id` 关联调用、任务及 generation。Host 收到文本之后必须发出对应 turn 的 completed，并返回与文本桥逐字相同的正文，随后 AgentGateway 独立验证角色身份和产物契约。数据库在发出真实供应商请求前再查 grant、lease、generation、权限 epoch 和 policy。收到回执后再次校验。权限失效时，已有计费证据可以保留，结果交付要重新获准。

预授权的摘要交付只接受已绑定调用记录、成功输出和完整证据的摘要候选。接受摘要发布 task.changed 事件。世界、章节、对外发布和其他正式接受仍由原有应用服务执行。

## 复现

```sh
uv sync --locked --group dev
export PG_BIN=/usr/lib/postgresql/17/bin
export NF_P5_SUPERVISOR_EVIDENCE="$PWD/evidence/p5/supervisor_m0.json"
uv run python scripts/with_postgres.py --migrate -- python -m pytest -q \
    tests/integration/test_p5_supervisor.py tests/integration/test_runtime_tasks.py \
    tests/integration/test_agent_gateway.py
```

本地缺少 Codex 时独立 Host 用例显示 SKIPPED。GitHub 的 PostgreSQL 集成作业安装固定版本的原生 Codex，进程恢复和整场验收用例在 CI 中缺少 Host 时按失败处理。本次实际使用 PostgreSQL 17.11 和 codex-cli 0.167.0-alpha.4。机器记录包括两轮实际 thread/turn 标识、Outbox 接受到唤醒的延迟、真正启动和退出的 Host 数，以及两次重复恢复后的就绪、等待、运行计数。上游为本地确定性 HTTP fixture，包括 token 计数；没有得到真实付费模型或文学质量观测。[本次 M0 记录](../evidence/p5/supervisor_m0.json)

测试还实际在供应商已经读到请求时强制终止 Python worker，启动新进程，用过期的数据库租约触发恢复。另一个故障点在费用结算完成与候选持久交付之间。两种情况下都保留原调用，供应商收到一次请求。此运行不证明 IDE 扩展握手，也不证明在机器停机时能够工作。

## 把角色候选提交到密封席位

为同一次互动的 A/B/C 建立独立 `character_actor/character_action` 任务与 BELIEF cut，取得各自服务端 grant。以这些 grant 建立已有 `WorldSchedulerService.prepare_interaction` 互动。为每个任务登记时在私有 JSON 中加入同一 `seal_interaction_id`。服务核对该任务的 actor、grant、WorldRef、故事时间和目标输出契约。登记时可以让 B 的任务等待 A 交付其行动。只有角色自己的上下文送往模型。

调度进程领取角色任务、验证返回的 ActionProposal 后，下次扫描通过已有模拟服务校验其证据与行动时段。有效意图和任务 ACCEPTED 的 Outbox 同事务提交。失效候选进入 WAITING_REVIEW，保留结构化阻断原因。其余角色只能看到自己席位的交付情况。控制器可在全部席位齐备后选择联合裁决候选，世界版本仍须经 Kernel 的正式接受。[三角色交付记录](../evidence/p5/supervised_actor_handoff.json)

## 自动交付重大偏离与滚动计划

作者可先为 `volume_director/volume_review` 登记一份 `editorial` 配置。字段 `operation=request_change`、`volume_id`、`prior_plan_ref`、`reference_timeline_ref` 均由服务端固定，相关 ref 和当前 `plan_manifest_ref` 也必须属于该任务的原始输入。配合 `continue_editorial: true` 可预授权一次至多三个有限轮次的编辑流程。三次调用共用原预算账户，继承模型配置、任务截止期限、授权故事时间及 PLAN cut。各轮都有独立任务、grant、context 与调用账本。

卷导演在联合接受屏障满足后收到其本轮的正式事件引用。返回 AgentTextOutput，`text` 说明原因，`event_refs` 引用此次联合接受的变化，`important_deltas` 列出重大偏离。无重大偏离即可结束。有重大偏离时，服务提交 ChangePoint，并在同一事务内创建 `volume_director/replan`。该岗位依据授权材料输出 WindowPlan。服务将通过校验的目标写入未来 K 个槽位，再为 `chief_editor/editorial_decision` 创建独立任务。

上层根据固定的 ChangePoint、候选计划和窗口给出 `APPROVED` 或 `RETURNED` 及理由。前者经 PlanningService 再校验后选择候选计划，后者保留原选择。有未决问题、失效授权、错误输入或并发冲突时，任务进入 WAITING_REVIEW，可凭 `supervisor.editorial.delivery` 回执查到原因。整条链不具有修改已发布历史或直接接受世界事件的权限。若要逐阶段自行登记，可以省略 `continue_editorial`。[自动采用实测](../evidence/p5/editorial/approved.json) · [退回实测](../evidence/p5/editorial/returned.json)

卷纲审核的 `accepted_effects` 只投影唤醒本任务的正式联合接受回执。服务复核本代际 WorldRef、所选事件版本、故事时间、卷纲当前选中的计划和上下文中的 INPUT_MANIFEST。关系双方、生命周期主体、资源账户及确切资源与单位受清单限制。对包含认知记录、未授权谓词、未授权主体、目标区域、早先另一事件和私人裁决说明的 PG17 用例，实际 HTTP 收件只带一项获准的仓库扣减 30 袋；收款方、私人说明与认知哨兵均未进入提示。后续窗口和总编工单只收到各自绑定的计划材料。原始证据位于 `evidence/p5/editorial/approved.json`。
