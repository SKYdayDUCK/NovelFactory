# 项目目录骨架的使用说明

本包交付技术设计、规范、Schema 示例和独立机制实验。完整目标目录与模块职责见 [02 代码架构](../docs/02_代码架构与模块设计.md)，开发次序见 [11 研发路线](../docs/11_研发路线与测试计划.md)。`src/` 中的局部指导文件用于说明后续代码责任，不表示对应服务已经实现。

## 1. 当前资产和后续实现

| 区域 | 本阶段交付性质 | 后续动作 |
|---|---|---|
| `docs/`、`research/`、`baseline/` | 详细设计、证据和原始架构资料 | 开发时按模块读取，设计调整通过 ADR 追踪 |
| `AGENTS.md`、局部 `AGENTS.md` | 开发行为规范 | 与代码同仓库维护，保持简洁 |
| `.agents/skills/`、`SKILLS.md` | Codex 项目开发技能与索引 | P0 验证实际发现及按需加载 |
| `runtime/roles/`、`runtime/skills/` | 小说角色契约与任务方法 | 由应用加载器绑定实际服务权限 |
| `contracts/` | 关键边界的 Schema 和示例 | P0 确认类型生成、验证与兼容策略 |
| `benchmarks/` | 五档行为负载假设、计算器和实测设计 | P1/P2 接入真实服务驱动，计算结果不可冒充吞吐/延迟 |
| `runtime/query_profiles.json` | 角色允许的查询平面、操作与编译 recipe | 与 task grant 和操作/平面 capability 求交，不作为独立授权 |
| `validation/`、`experiments/` | 包一致性检查与独立小实验 | 先运行本包检查；正式实现使用独立业务测试 |
| `src/novel_factory/` | 当前只放必要局部规范 | 按阶段新增实际模块，不填空壳服务凑目录 |
| `migrations/`、`tests/` | 当前局部规范 | P0/P1 建立真实迁移和 PostgreSQL 测试 |
| `adapters/claude/` | 说明及未生效模板 | 根据已验证 Host 模式选用 |

`pyproject.toml`、锁文件、业务模块、部署配置和实际迁移在实施时生成，不根据本说明推断这些内容已经存在。

## 2. 建立开发仓库

在空的新仓库中保留本包结构即可开始 P0。若合并到现有仓库，先逐项比较根/局部规范、契约、依赖和同名技能，再整合差异；不要用覆盖复制破坏现有代码或用户修改。

保留 `.agents/` 目录随项目一起复制，它承载开发技能。不要复制到个人技能目录，也不要把运行时技能移动到开发 Host 的自动发现目录。根 `SKILLS.md` 提供导航，Codex 实际加载以官方规定的仓库路径和目标版本验证为准。

建议第一次开发任务包含：

1. 阅读根规范及 docs01、02、11，确定 P0 范围和目标依赖。
2. 运行下列设计包检查，记录真实输出；先修正包内问题再实现业务。
3. 在隔离环境锁定 Python/数据库/依赖版本，建立 Schema 验证与最小迁移测试。
4. 按 P1 构建最小可信内核，同时准备 P2 的短卷场景；避免长期只写基础设施。

```bash
python validation/validate_package.py
python -m unittest discover -s experiments -p 'test_*.py'
```

以上命令须从包根运行；其成功只说明当前检查及实验通过，不等于生产数据库、Agent Host、真实模型、长篇质量或完整工厂已验收。

## 3. 文件责任和扩展

新增业务文件放入已有职责边界，并复用应用端口；一个模块有真实输入输出和测试需求时再创建。跨模块契约放 `contracts/`，关键决策追加 docs12，源证据追加 `research/`。独立实验不得被正式业务代码导入。

新目录确有局部风险时可添加简短 `AGENTS.md`，否则继承上层规范即可。新技能须有明确触发条件和稳定复用流程，不以技能替代业务代码、事务或权限校验。

Claude Code 移植先读 [适配说明](../adapters/claude/README.md)；不要把模板直接放入项目根后假定原生 AGENTS 与局部规则仍按原方式加载。
