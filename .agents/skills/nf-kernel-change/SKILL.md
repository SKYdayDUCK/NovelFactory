# 内核变更

## 输入与输出

输入：任务目标、受影响模块、具体失败样例或新需求、现有 WorldRef/故事时间和预期行为。缺少复现资料时先建立最小合成样例，不把合成数据称为用户事实。

输出：实现或可评审设计、必要的 ADR/迁移候选、风险对应的测试、兼容性与恢复说明；标明已验证和未验证部分。

## 操作步骤

1. 读取根及目标目录 `AGENTS.md`，按需阅读 [数据模型](../../../docs/03_数据模型与知识图谱.md)、[事件版本](../../../docs/04_事件溯源与版本体系.md)、[调度](../../../docs/05_世界模拟与调度引擎.md)。
2. 写出受影响的不变量、输入版本和接受边界，确定改变的是候选、世界事实、正文还是派生结果。
3. 检查并发读取、分支头 CAS、短事务、效果去重、失效传播和 outbox；涉及语义改变时起草 ADR。
4. 以最小范围实现候选方案。模型和其他外部调用留在事务外，正式接受重新校验前置条件。
5. 验证能暴露风险的反例：重复、过期、跨分支、未推进、冲突资源或故障中断；数据库机制用真实 PostgreSQL。
6. 同步契约/文档/迁移，给出实际观测结果与恢复路径。明确实验只证明了哪些机制。

## R1补充

检查R1 ScopeToken、封闭动作组、负向范围、history/interpretation及活动产物选择；HEAD变化不直接判全部过期，不能证明独立时保守处理。

## 工具与边界

- 使用仓库文件工具、实际测试入口和隔离 PostgreSQL；不依赖某个模型供应商 SDK。
- 可自主修复和编写候选 ADR/迁移；真实高风险操作按已有授权范围执行。
- 不原地改写正式事件，不通过改变模型完成顺序决定故事因果，不让正文重写再次应用世界效果。
- 不为通过测试删约束或赋予角色额外权限；必要的设计调整应可评审和可追踪。

验收依据：[研发与测试](../../../docs/11_研发路线与测试计划.md)、[架构决策](../../../docs/12_架构决策与风险.md)。
