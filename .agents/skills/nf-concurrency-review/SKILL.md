# 并发与时态交接检查

## 输入与输出

输入：具体用例、数据规模、角色/查询/模型行为、部署环境、并发失败样例或目标瓶颈。输出：操作分层、scope与读取切面、失败路径、受影响契约、实测或未测结果及扩展门槛。

## 步骤

1. 读根及目标目录规范，再读 [13 时间](../../../docs/13_统一时间线与动态知识演化.md)、[14 并发](../../../docs/14_高并发服务与一致性协议.md)、[15 验收](../../../docs/15_并发压测与端到端验收.md) 中相关部分。
2. 分开故事发生、效力区间、修订与叙事位置；固定WorldRef、KnowledgeCut、interpretation_ref及计划/读者清单。批量查询只解析一次cut。
3. 分开查询、模型等待、候选准备、语义裁决和正式接受；登记每类实际成本，不让Agent数量替代RPS或模型在途数。
4. 对guarded命令检查注册模板的正向、负向、约束组、过程、封闭冲突组、权限/解释和活动选择scope；不能自报完整或只比写实体版本。
5. 确认原提案、TaskSpec和批准内容未原地改版，base/validated/parent同枝血缘成立；旧strict批准不自动变guarded，跨分支/Retcon走严格流程。
6. 先写能暴露失败的反例：无关HEAD更新、write skew、空查询后新增、ABA、解释升级、撤权缓存、批量混切面、丢回执。数据库锁与恢复用目标PostgreSQL。
7. 根据实际环境记录吞吐、尾延迟、排队、连接、索引延迟、拒绝/重试与正确性；加入open-loop和冷热数据，不能把快速拒绝算成功容量。

## 边界

- 工具：仓库检查、Schema验证、隔离PG、多进程压测工具、明确标记的标准库负载模型。模型推理时不持有数据库连接。
- 对纯方案可自主计算假设负载、写候选实现和运行隔离实验；未实际压测不宣称支持500/1000 Agent。
- 不以全局大锁、最后写入者获胜或取消约束提高“成绩”；不让数据库抢锁次序决定小说胜负。
- 缓存每次重新授权；技术解释变更与普通索引重建区别处理；高影响语义依赖不完整时保守阻塞。
- 结果注明已验证机制、未验证容量与下一道门槛；不无限追加与当前风险无关的测试。
