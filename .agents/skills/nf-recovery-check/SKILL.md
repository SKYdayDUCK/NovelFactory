# 恢复验证

## 输入与输出

输入：恢复目标、故障点、数据库/对象备份清单、版本与环境标识、授权范围。输出：可复现演练步骤、恢复前后对照、未恢复项、幂等/对账结果及真实环境执行建议。

## 操作步骤

1. 读取 [事件版本](../../../docs/04_事件溯源与版本体系.md) 和 [测试计划](../../../docs/11_研发路线与测试计划.md)，确认恢复的是哪个作品、分支及一致备份点。
2. 默认在新建隔离数据库与独立对象目录演练。检查数据库版本、配置、解释器和对象哈希清单，不覆盖现有环境。
3. 按指定故障点恢复事件链、分支头、关键投影、推进进度、审批及正文引用，比较恢复前的已接受收据。
4. 重放不调用模型；重复 outbox/inbox 不产生第二次业务效果；任务旧代结果必须被拒绝。
5. 对外部结果 UNKNOWN 保留证据和预算，先查询/对账再决定重试，不能用重新调用掩盖不确定性。
6. 验证角色隔离、历史查询、未推进状态和索引落后语义仍成立；记录不能从现有备份恢复的内容。
7. 输出演练结论与具体剩余风险；生产覆盖或不可逆清除超出现有授权时，提交已经可评审的执行与恢复计划。

## R1补充

恢复解释/历法清单、scope单调版本和活动选择；固定修订未求值不能因恢复后新HEAD前进变成已求值，旧命令回执按原身份返回。

## 工具与边界

- 使用目标 PostgreSQL 的 pg_dump/恢复工具、对象哈希核验、应用测试和故障注入；凭据不写入日志。
- 数据库可以启动、行数一致或内存实验通过都不足以证明业务恢复成功。
- pg_dump 不自动包含集群级角色与外部对象；它也不是 PITR 基础备份。
- 不在生产执行未经授权的恢复覆盖，不删除历史来让恢复检查通过。

当前独立实验入口：`python -m unittest discover -s experiments -p 'test_*.py'`。它只验证实验声明的性质。
