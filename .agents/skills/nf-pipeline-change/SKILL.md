# 生产线变更

## 输入与输出

输入：受影响阶段、角色/任务契约、作品与版本、现有失败案例或创作需求。输出：阶段和任务差异、输入输出及失败路径、角色/技能调整、工程与文学分开的验收记录。

## 操作步骤

1. 读取 [编排](../../../docs/06_Agent编排与管理.md)、[生产线](../../../docs/07_剧情与文学生产系统.md) 和目标 [角色契约](../../../runtime/roles/README.md)。
2. 明确每次交接的 WorldRef、计划/正文版本、任务代际、允许读取的信息、产物及审批责任。
3. 检查并行章节固定快照、场景前后状态和读者披露边界；角色认知不得因写作方便获得世界秘密。
4. 已接受世界事件转为文本时只渲染，不再施加效果。正文改变先分类为表达、披露或持久事实，再选择相应接受流程。
5. 失败后按任务、Attempt 和候选版本关联原因，区分技术修复、业务契约返工、文学修订和方法变更。保持并发、身份和外部计费授权。
6. 分开工程硬门槛与文学建议，保存审查证据和主编决定，限制无进展的反复返工。
7. 用合法内部角色完成独立端到端验收。开发者只提供工程输入；样本或修复不得代写正式作品。

## R1补充

世界背景并发更新不自动废弃无关正文；新采用切面要有正文对账，不能复用世界接受证书代替文学/披露审核。

## 工具与边界

- 使用应用服务、受限模型网关、版本化任务和角色 catalog；运行时 Skills 由项目加载器渐进加载。
- 角色/技能的文字描述不授予权限；新增工具访问须与服务端 grant 和数据范围一致。
- 不用统一文学分数替代编辑判断，不以模板阈值机械禁止合理表达。
- 不因正文被删除而自动撤销世界事实，不让抽取/摘要结果自动变为正式事件。
- 局部可逆开发可自主完成；外部发表与真实权限扩大按根规范和已有授权处理。

## 文学示例验收

调整创作方法时从[岗位任务卡](../../../docs/literary_knowledge/TASK_METHODS.md)选对应段落。在起稿前固定题材、篇幅、独立评阅量表和预期使用的指令快照。编辑按原文锚点处理同因问题，保留一处不该改的声音；收稿分别记录宿主角色执行、原生世界接受、正文送达、内部冻结和盲评。变更内置角色或主 Skill 的字节后，应实测启用了 Creative Harness 的来源校验与恢复路径。
