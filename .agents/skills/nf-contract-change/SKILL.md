# 契约变更

## 输入与输出

输入：契约名称、调用方/被调用方、目标行为、已有版本与兼容要求。输出：Schema/类型/示例的同步差异、兼容性判断、错误语义、调用方迁移和验证记录。

## 操作步骤

1. 读取 [contracts 规范](../../../contracts/AGENTS.md)、[数据模型](../../../docs/03_数据模型与知识图谱.md) 和对应服务文档，确定唯一契约责任方。
2. 分开标识世界版本、故事时间、任务代际、传输请求、业务幂等和事件效果；写清缺失、空值及未知状态。
3. 列出合法与非法输入、额外字段策略、错误码、版本不兼容处理；Pydantic strict 不替代业务校验。
4. 保证身份来自受信通道，审批绑定到具体候选和版本；输入字段不能赋予提交权。
5. 更新 Schema、有效例、类型适配、调用方和文档。旧事件保持原文，并验证旧版本仍可解释。
6. 校验示例及边界反例；MCP/HTTP/CLI 分别验证传输形状，同时验证它们调用同一应用语义。

## R1补充

新增2.1契约不原地扩写core 2.0；检查统一时间字段、计划/读者清单、一次pin批量、角色查询profile及服务端证书binding。

## 工具与边界

- 使用 JSON Schema 验证器、Pydantic 和已选 Host/SDK 的兼容测试；锁定实测版本。
- 当前包检查命令为 `python validation/validate_package.py`；它不能代替真实 Host 联调。
- 只修改 MCP protocolVersion 字符串不构成适配；JSON-RPC id 不构成业务幂等。
- 不把无约束字典作为长期契约，不静默删除未知字段掩盖接口错误，不把符合 Schema 等同授权。
- 扩大真实权限或破坏已存在数据另按根规范判断授权；候选 Schema 和兼容适配可自主编写。
