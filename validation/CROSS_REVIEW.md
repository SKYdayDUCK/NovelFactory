# 系统级交叉审查与修正记录

> 保留记录：下文是原 v2.0 阶段审查，原来的 12 份文档、2 份 Schema、23 个工具和 18 项实验数量只描述当时范围。当前 v2.0-R1 的整合审查见 [R1 并发复核](R1_CONCURRENCY_REVIEW.md)、[R1 需求覆盖](R1_REQUIREMENTS.md)及[最新验证报告](REPORT.md)；不得把旧范围当成 R1 完整检查清单。

审查日期：2026-11-10。范围：12 份技术文档、2 份 Schema、接口目录、角色/技能目录、开发规范、研究映射、研发计划及组合交接案例。结论是**已形成相互衔接的设计包**；它不是实际系统已经正确运行的证明。

用户要求的逐项出处见 [需求矩阵](requirement_matrix.md)；实际静态校验和有限实验结果见 [REPORT](REPORT.md)；实现阶段案例见 [case_matrix.json](case_matrix.json)。

## 1. 十三项系统审查

| 审查问题 | 最终设计及本轮处理 | 主要验证落点 |
|---|---|---|
| 世界真相是否多头权威 | 不可变权威记录＋分支选择清单；关系、资源、图谱和摘要是其受控视图。KnowledgeService 不另开写入真相通道 | 03/04；T01/T09/F17 |
| 时间是否与版本混用 | WorldRef 与 StoryPoint 分开；OccurrenceTime 的有界可能发生时间不当持续区间，也不自动选择端点 | 03/05；T12/S01/V2 时间用例 |
| 计划、模拟、正式事件是否混淆 | 计划无效果；模拟在隔离分支；event_candidates 载荷存在不等于已被有效选择和接受 | 04/07；T03/S06/F07 |
| 角色是否读到越权信息 | 服务端视图、actor/时间绑定、独立会话；错误、计数、引用和缓存也过滤；隐藏与不存在保持同形返回 | 06/09；T02/F06/F13/F19 |
| 裁决与调度是否重复负责 | 调度封闭参与集合、因果和推进覆盖；裁决形成候选后果；WorldCommitService 唯一接受 | 05/06；S02/S03/S08 |
| 宏微是否重复扣除 | 稳定 occurrence/effect 身份及选择清单；MVP 微观只补表现；真正效果替换需完整等价性审查 | 04/05；T08/S04 |
| 改正文是否误撤销事件 | 世界接受、正文接受、内部发布、外部交付分开；文本增删先分类对账，事实变化走提案或 Retcon | 04/07；T05/T08/F18 |
| 并行写作是否混用快照 | 同批固定 WorldRef 与场景/披露契约；最终整卷固定一个世界切面，旧稿先重验证再采用 | 07/09；T07/F03/F07 |
| Agent 是否绕过正式提交 | 普通角色只有建议工具；控制面核验任务代际、grant、输入依赖、批准和 CAS，Schema 通过不产生权限 | 04/06/08；F01/F03/F08 |
| MCP、技能与服务是否重复 | 业务只在应用/领域层；MCP/HTTP/CLI 为适配；技能组织操作、角色描述职责、权限由服务端执行 | 02/08/SKILLS；工具绑定检查 |
| AGENTS 是否妨碍正常自主性 | 核心文件修改本身不需额外许可；允许普通修复、候选 ADR、隔离实验和迁移设计；越权高风险执行才升级 | 根/局部规范；交接演练 |
| 创作是否受机械规则束缚 | 普通细节不逐词入图；文学选择使用证据、反解释和编辑决议；不预设普遍文学评分函数 | 07/09；L01–L05 |
| 关键假设是否有验证路径 | 所有未实测机制保留状态和 P 阶段门槛；18 项有限实验与60项待实施业务验收明确分开 | 11/12/REPORT |

## 2. 本轮发现并直接修正的设计问题

| 编号 | 问题与风险 | 已采用的修正 |
|---|---|---|
| CR01 | 一句“世界事件已接受”未充分定义分支中哪一版本生效 | 显式 event_operations 的 ADD/REPLACE/DEACTIVATE、先前版本检查及记录选择清单；载荷与正式成员资格分开 |
| CR02 | 用一个时间区间同时表达发生不确定性和过程持续性 | 引入 EXACT/BOUNDED/UNSPECIFIED 的 OccurrenceTime；查询依所有相容时点结论，不能定则 UNDETERMINED |
| CR03 | 过程状态可能把“等待模型”当成故事过程暂停 | world_stage 与 evaluation_status 分开；ProcessAdvance 为调度元数据，和事件/触发变更原子接受 |
| CR04 | 时间前沿到达某个下界后可能误判该时刻已清空 | evaluated_frontier 为排他边界；允许证明严格早于 H 的范围，不允许未经交汇处理跨过 H |
| CR05 | 宏微替换只比较终态会漏掉中间认知与信息传播 | 比较资源、权利、消息、观察及必要中间切面；MVP 限制为不新增效果的表现细化，复杂替换进 P3 |
| CR06 | 多阶段互动若放在无版本内存中，会产生旁路事实 | 在隔离候选分支逐阶段正常接受；每阶段同一 world_ref 分别裁剪，未采用候选的认知和会话一并隔离 |
| CR07 | 幂等键可能掩盖同键不同载荷或换键重复接受 | 幂等范围与业务参数哈希明确；另有提案/目标分支接受唯一约束及稳定效果身份 |
| CR08 | 取消后的迟到结果与已成功但丢回执容易混淆 | 取消/接受按锁序线性化；取消先拒旧代，接受先保留结果；同命令只读原回执不重新执行 |
| CR09 | 所有 TaskSpec 强制已有 ContextBundle 会阻断准备过程 | 准备阶段允许 null；外部调用前必须持久绑定，当代结果及后续状态不得为空 |
| CR10 | task_get/task_cancel 若依赖未生成的上下文会无法控制任务 | 这两个请求只用受信任务身份与授权，不含 context_bundle_id；组合演练字段同步修正 |
| CR11 | 单靠异步 outbox 更新失效状态，存在接受空窗 | 关键范围版本与最小失效屏障跟正式接受同事务；详细图展开和索引更新仍可异步 |
| CR12 | 只登记命中行会漏掉“没查到阻碍”的负向依赖 | DependencyManifest 保留谓词、范围戳、规则及覆盖；范围变化使相应否定判断失效 |
| CR13 | 字符偏移和内容哈希跨语言不一致 | TextSpan 固定 Unicode code point 半开区间，原始 UTF-8、不做 NFC/换行规范化；结构哈希另定 NF-CANON-1 |
| CR14 | UNKNOWN / NONE / PENDING / STALE 被当作一个空值 | QueryAnswer 分开事实确定性、知识、求值、索引新鲜度、覆盖和值状态，并提供正反例 |
| CR15 | Retcon 只有服务名和报告引用，开发者不知道如何核验 | 补 PrepareRetconRequest/PromotionRequest；四类报告固定输入绑定、覆盖、实际检查证据和阻塞条件 |
| CR16 | Retcon 变化包原地换 WorldRef 会破坏来源与审批 | VersionService 创建有来源关系的新目标包；计划初始候选与最终候选靠修复提交链衔接；双端 CAS 推广 |
| CR17 | 草稿直接改 world_ref、或删文就删事件 | 旧稿保留；新输入、AlignmentReport 与批准独立重建；正文操作不重复或反向执行世界效果 |
| CR18 | 四组共享技能要求角色调用无权工具 | 增加 chief_editor、environment_director、evidence_maintainer、literary_editor 的受限模式和交接出口；未扩张工具权限 |
| CR19 | 服务文档有 KnowledgeService/RepresentationService，但代码树缺落点 | 补相应应用文件位置；仍复用统一提交与存储端口，不新增第二权威状态 |
| CR20 | Host/协议官方规范已变化，泛称“支持 MCP/Skills”不足以落实 | 标明目标 profile、版本差异、实际未测状态；Codex 主源与 Claude 适配区分，不仅改版本字符串冒充兼容 |

以上修改已经反映在最终文件。CR15 的报告机器类型及执行门禁仍是明确的 P1/P2 开发任务；“字段契约已补全”不表示相关服务已经实现。

## 3. 跨模块交接演练

[HANDOFF_EXERCISE](HANDOFF_EXERCISE.md) 让开发者按实际开发技能，处理 D12 借剑改赠、D30 旧稿并发、取消迟到及报告过期的组合案例。演练固定 11 步服务顺序、引用/版本字段、复用与失效矩阵，以及 H01–H11 的实现验收要求。

演练特别保留 D30 发言与发言内容真假的区别：过去改为赠与，不自动否认师父曾说过将来赠剑；是否保留、解释或修订台词需证据与编辑决议。由此检查世界、认知、未来计划、正文及文学判断的不同责任。

## 4. 无法靠纸面审查关闭的事项

| 未决问题 | 后续验证方式 | 失败时的保守路径 |
|---|---|---|
| 通道/过程登记是否完整 | P2 两地区消息延迟、未知过程与交汇案例；人工检查注册范围 | 阻断受影响范围推进，允许无依赖区域继续 |
| 复杂语义裁决是否稳定且尊重角色 | 同输入多候选对比、动机/合法性独立审阅、成本记录 | 缩小模拟范围，关键语义问题交明确决议 |
| 宏微等价证明是否可操作 | P3 构造终态相同但中间观察不同反例 | 维持表现细化，不开放自动效果替换 |
| 文本抽取和依赖识别会漏掉什么 | P2 关键终态直接核验＋独立原文回读＋标注漏检集 | 保守扩大重审范围，重要事项人工审定 |
| PostgreSQL 锁/约束/恢复是否真正有效 | P1 多连接交错、断点注入、备份恢复和实际重放 | 不开放真实多 worker 正式接受 |
| 外部 Host 的隔离、取消和调用回执 | P0/P2 固定 Host/供应商版本联调；撤权/未知回执案例 | 单一适配和有限并发；UNKNOWN 不自动重试 |
| 长篇文学效果及有限返工是否改善 | P2 短卷与 P4 跨卷阅读、证据问题单、版本对照 | 由负责编辑裁量；不让硬评分逼迫模板化 |

本轮没有将这些候选机制改写为“已解决”。可先编码的确定性边界与需实验选择的语义/文学机制，在研发阶段和 ADR 中分别标示。
