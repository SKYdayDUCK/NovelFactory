# P5.5 日志、Trace 与统计

## 事务和访问边界

LogService 将模型证据、文学证据和场景关联写入原业务事务，只存引用、范围及计量元数据。MCP 先留下一条开始记录。校验参数、校验岗位能力、执行方法后，再写终态、耗时或安全错误码。进程在两次记录之间退出时会留下只有开始的调用。正式写操作的执行结果仍以原幂等回执为准。错误日志不包含调用参数、角色秘密、完整 Prompt 或认证材料。未注册工具统一记作 UNREGISTERED；请求编号仅以 SHA-256 存储，避免调用方利用自由字符串携带私密材料。

域事件沿原事务 Outbox 保留。LogWorker 在自己的消费事务中重读该源，按任务、版本、授权或工件恢复范围。日志行和 audit.recorded Outbox 同事务提交。统计组只消费这个话题。日志组不接收统计事件；模型和世界事务都无需等待 Redis。原始调用台账、模型输入/输出工件与世界事件各自保持原身份。

场景登记将 interaction_id 绑定到角色、裁决、受控提交及卷导演任务。滚动编辑后继继承父任务的场景及卷标识。Trace 查询需要实时有效的作品、分支 ADMIN 授权；不向角色 MCP 注册统计工具。历史上缺少因果关系的事件仅展示可验证的关联。未能绑定作品的旧域通知保留在原始 Outbox 中。

## 增量与重建

StatisticsWorker 根据 PostgreSQL 中的权威消息重读 audit 记录，调用 calculate，按 (metric_version,event_id) 写入一份统计贡献。Inbox、统计贡献与消费完成在同一 PostgreSQL 事务中提交。重算从 nf_audit_events 和其指向的不可变业务工件读取；不依赖清理前的旧 Redis 消息。版本 1 包含事件和业务指标，版本 2 增加事件耗时汇总。独立版本可共存。

升级前已归档的 P5 消息可通过 import-legacy 分批补登留存的原始模型证据和正式世界接受；重复执行至 more_possible 为 false。旧版没有产生的 MCP 日志不能推断。

每个统计切面使用作品、分支和准确的已提交 audit event_id 集合计算 SHA-256。一条先开始、后提交的事务不会混进已有切面。切面保存在数据库里，支持物理或逻辑备份及恢复。相同切面去重；每个作品/分支范围保留最近使用的 16 个不同切面，超出时自动淘汰最久未使用项。淘汰只影响按旧令牌再次请求的能力，原始日志和统计贡献一直保留。每次生成新切面扫描该范围的事件，短时间重复查询应复用 source_cut。大规模历史切面生成、重建和比对应在专用统计预算内使用。

verify_statistics 对同一切面的每个事件比较相同公式生成的贡献和增量投影，可发现相互抵消的错误；返回差异总数和最多 100 条事件级指标差异。完成度说明已选取审计来源的投影覆盖。旧部署从未保存过的语义评价不会被历史回算补造。

## 管理员入口

以管理员私有 JSON 文件绑定准确作品与分支，文件权限 0600；结构同 P5 项目 MCP binding，token 使用管理员本人的独立凭据。角色及 resume_operator 不能使用管理查询。CLI 不接受 SQL、数据库密码或 Token 命令行参数。

```bash
python scripts/p55_statistics.py --binding /private/work-admin.json import-legacy
python scripts/p55_statistics.py --binding /private/work-admin.json current
python scripts/p55_statistics.py --binding /private/work-admin.json read --version 2
python scripts/p55_statistics.py --binding /private/work-admin.json rebuild --volume-id VOLUME_UUID
python scripts/p55_statistics.py --binding /private/work-admin.json verify --source-cut CUT_SHA256
python scripts/p55_statistics.py --binding /private/work-admin.json trace --trace-id INTERACTION_UUID
```

read、rebuild、verify 可选起止时间（有时区的 ISO 日期，左闭右开）、场景 trace_id、作品内角色、卷、模型或实验 ID。可通过 register-experiment 和 --experiment-id、--start、--end 登记严格限于当前作品分支的实验窗口；相同 UUID 的窗口不可重新定义。内部服务支持跨分支作品汇总，仅有全分支 ADMIN 授权可用。current 给出当前 PostgreSQL 任务状态、在途调用、按币种的未结算预留；不把预留金额记为支付。

## 指标口径

| 数据 | 计算口径 |
|---|---|
| 任务与等待 | 唯一观察任务中的已接受数/观察数。指定时间窗的已接受任务数/秒。领取延迟从当代输入建立至首次 RUNNING；有依赖的 READY 测量依赖满足及等待声明均完成至唤醒。运行并发来自 current 的 RUNNING 行。 |
| 模型 | 正式响应中输入、输出和缓存 Token 单列，合计仅加输入及输出。可取得的推理明细是输出的子项。经原网关和账本确认的 OpenRouter 费用独立计入；确定性适配器和本地回环夹具按 fixture 单列。 |
| 延迟、吞吐 | 每项耗时返回样本数、均值、最近秩 P95/P99。模型峰值并发只覆盖具有结束时间及历时的已完成调用；UNKNOWN 由实时台账返回。资源监控器另提供 Redis PEL、积压、SQL、CPU、RSS、吞吐与进程延迟，部署侧按独立运维权限查看。 |
| 世界与文学 | 正式接受的修订和修订事件数分别统计。可查 ChangePoint、窗口提案、返工草稿、草稿 Unicode 码点数及审读问题分类。字数包含标点和空白；多版草稿分别计数。 |
| 可用范围 | 按场景和卷归集已有绑定的模型费用。没有稳定的逐章调用映射、价格表或独立质量分数时分别返回 null 与原因。文学问题计数不代表质量通过。历史上未发出工具调用审计时无法补算拒绝调用。 |

## 迁移与回退

0010 添加不可变日志与场景映射；0011 添加有界切面和统计贡献。两项都是扩展迁移。运行中可停止统计进程，继续保留业务及审计。重建后运行相同水位的核查再恢复服务。含不可替代审计或场景映射时 0010 拒绝降级；0011 拒绝直接丢弃非空统计。恢复旧应用时优先保留新增表及备份。
