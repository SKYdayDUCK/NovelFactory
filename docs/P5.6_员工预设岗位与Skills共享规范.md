# 员工、预设、岗位和 Skills 共享

## 继承映射

岗位和 Skill 的当前来源是 runtime/roles/catalog.json、runtime/skills/catalog.json 及 RuntimeCatalog.snapshot。每个工坊岗位引用 NF 目录版本和内容哈希。新增组织头衔可以绑定多个批准的工作模式；签发 NF 创作任务时只能选择其中一个具体 NF role_id。

| 当前 NF 岗位 | 工坊岗位或工作模式 | 可继承的 Skill |
|---|---|---|
| chief_editor | 总导演的作品决策、整卷总审 | plan-volume（editorial_decision_only）、edit-volume、review-change-point |
| world_designer | 世界设定 | prepare-world |
| volume_director | 卷纲导演、编剧的情节规划模式 | plan-volume、volume-director-review、roll-window |
| character_actor | 演员；每个实例单独绑定人物及当时所知 | simulate-character |
| environment_director | 环境导演 | prepare-world、adjudicate-actions（仅环境提案） |
| adjudication_advisor | 独立裁决顾问 | adjudicate-actions |
| writer | 正文写作者、编剧的文字模式 | write-scene |
| evidence_maintainer | 跨卷记忆、证据维护 | maintain-memory、review-consistency（仅收集证据） |
| reviewer | 编剧、导演、角色、文笔等审读模式 | review-consistency |
| literary_editor | 文学研究、跨卷编辑 | research-literature、edit-volume、maintain-memory |

workshop_manager、审核主管和系统维护人员是组织身份。管理者需要看作品状态时单独绑定 ProjectBinding；组织管理身份本身不持有作品 ADMIN。编剧做情节设计和写正文分别领取不同的 NF 工作绑定。七项开发技能只用于工程维护。开发技能路径不进入创作任务的运行时快照。

## 名册与预设

EmployeeRoster 的必备字段为 employee_id、role_id、display_name、supervisor_id、team_id、status、capability_profile、skill_manifest_ref、allowed_routes、employment_revision 与 authorized_scope。对本人投影包括本人路由和资格；对同事只提供按范围裁剪的公共目录。私钥、进程参数、任务文本、未披露的角色绑定和其他人的原始 Grant 只由各自的授权服务处理。

| 预设 | 岗位槽位与启用条件 | 审核与成本安排 |
|---|---|---|
| Minimal | 管理者、总导演、卷纲导演、编剧/写作者、需要发言的演员；低压时可由同一员工先后承担兼容的生产模式 | 普通场景抽样；独立审核无人可用则暂缓签发关键批准；默认一次只派一个模型任务 |
| Standard | 独立编剧、总导演、卷纲导演、演员池、写作者和审核主管 | 多演员可并行，关键变更交独立审读；每场上限从预设读取 |
| Long-form | Standard 加跨卷连续性维护、文学编辑和跨场审读 | 在卷结算、读者披露边界及前后章交接触发专项；冻结已发布前缀 |
| Research / Audit | 按需增加世界规则、系统稳定及统计审核模式；取样设计和版本写入实验清单 | 确定性检查优先，研究调用使用独立预算桶，保存失败样本 |

PresetRevision 保存岗位槽位、基数、图模板、创作模式、技能版本约束、Grant 上限、模型调用/并发/费用上限、唤醒事件和退出规则。额度缺失的模型任务等待配置。相同 slot、绑定人物和在职版本只能有一个活动实例。变更预设先输出人员增减与受影响路由，再用组织版本 CAS 提交。被撤销员工的已发送调用交给对账服务处理。实例登记和动态启动分别记录，加载员工名单时供应商调用次数必须为零。

## 共享契约

| 策略 | 可见性与条件 |
|---|---|
| PUBLIC_SHARED | 同一安装中注册为公共的通用方法。端点访问仍需角色 Grant |
| ROLE_SCOPED | 必须命中 role_id 与 task_mode；局部模式按原目录继续限制 |
| TEAM_SCOPED | 要求团队任期与资源范围相交，同时验证任务模式兼容性 |
| PRIVATE | 仅持有者或显式受托的指定实例，禁止自动转授 |
| CONTROL_ONLY | 组织控制面或具名维护身份；角色运行时禁止加载 |

SkillBinding 保存 source_catalog、source_revision、skill_name、content_sha256、mode、owner、scope、expires_at、revocation_epoch。签发时校验内容哈希和允许范围，开发/组织/创作命名空间分开。先算“岗位允许 ∩ 团队策略 ∩ 当前委托 ∩ 技能模式”，再由 NF 用冻结快照和实时 Grant 交集决策每次工具调用。升级生成新绑定；已开工的任务读取原哈希。遇撤权应停止后续调用并保留历史，不能用冻结版本恢复被撤回的能力。
