# Agent Workshop 详细技术架构

实施起点为独立进程、独立数据库身份、单个模块化应用。作者客户端通过 Workshop MCP 与组织控制面交互。工坊可复用一台 PostgreSQL 实例，使用独立数据库和禁止跨库读取的账号。NF MCP 是唯一作品业务接口。以下 aw_ 表及接口均为设计。

## 模块与存储

| 模块与表 | 主键、唯一性与索引 | 写入与读取责任 |
|---|---|---|
| Organization：aw_organizations、aw_org_revisions | org_id，(org_id, revision)；active_revision CAS | 保存配置、图和预设哈希。每个变更记录父版本和操作者 |
| Employment：aw_employees、aw_employment_versions | employee_id，(employee_id, employment_revision)；team_id/status | 岗位、代班、有效期、工种和授权上限。离职追加版本 |
| Routing：aw_edges、aw_route_grants | (org_id, revision, src, dst, kind)；grant_id、expires_at | 定向动作、作用域、临时授权的发行者与撤销点 |
| Directory：aw_roster_views | (org_id, revision, audience_scope_hash) | 按范围生成可再建目录视图，只保存必要管理元数据 |
| Messaging：aw_messages、aw_deliveries | message_id，(sender_id, operation_id)，(message_id, recipient_id)；recipient_id/state | 保存已验证的组织消息、附件引用、回执和每个收件人游标 |
| Delegation：aw_delegations、aw_remote_receipts | delegation_id，(endpoint_id, operation_id)，(nf_work, nf_branch, nf_task, generation, delegation_id) | 记录业务请求意图、NF 回执和同步版本，计划/任务状态来自 NF |
| Capability：aw_skill_bindings | (employee_id, employment_revision, skill_id, content_sha) | 索引已有工厂技能的来源、允许的模式及分享范围 |
| Review：aw_reviews、aw_review_evidence | review_id，(artifact_revision, review_mode, round, policy_revision)；author_id、reviewer_id | 管理审读委派、证据引用及意见。批准业务产物须走 NF |
| Finance：aw_budget_holds、aw_cost_observations | reservation_id，(delegation_id, purpose)，(nf_attempt_id, accounting_revision) | 工坊记录组织配额占用；将 NF 的预留/实际使用映射到项目和员工 |
| Reliability：aw_outbox、aw_inbox、aw_change_log | event_id，(subscriber, event_id)，(org_id, seq) | 本地组织写入与 outbox 同事务。按组织 seq 读取变更，重复通知无业务副作用 |

主管关系与允许通讯边拆开存储。时间采用数据库 UTC 时间加独立的组织修订序号；故事时间保留在 NF 的 WorldRef/KnowledgeCut。外键只约束工坊本地表。跨服务引用至少包括 NF 实例、作品、分支、实体类型、版本标识，验证和结果读取都从 NF MCP 执行。

## 命令与事务边界

雇佣命令携带 operation_id、expected_org_revision、preset_ref 和岗位槽位。先校验预算上限、主管图、岗位兼容性，再取得组织行锁；任期、组织新修订、名单及通知意图一次提交，同幂等键不同请求哈希拒绝。名单发给千人时，事务内只写一次发布事件；扇出 worker 按 (revision, employee_id) 游标分批提交并恢复。

提交作品委托依次经过 REQUESTED → SENDING → BOUND。先将意图和本地额度占用落盘，再离开事务调用 NF MCP。响应丢失进入 RECONCILING，以原 operation_id 查询 NF 收据或执行同键幂等重试。NF 终态转换为 SETTLED 或 RELEASED，本地恢复任务按已登记游标对账。超时不能释放已发送未知调用的资金。撤权与接单竞态由设备 session 的 employment_revision、grant epoch 和 NF 最后一道能力复核共同封闭。

## 生命周期、运维与恢复

雇佣状态区分 ACTIVE、SUSPENDED、ENDED。委派状态与 Model Host 进程状态分栏。无模型的通知服务、就绪路由、日志投影、名单更新和对账定时器均可常驻；管理者只在业务事件触发时开始一次有截止时间的 turn。工坊吞吐只计成功委派和送达；实际作品吞吐以 NF 的业务收据统计。

独立备份工坊数据库和私有配置引用。恢复后先冻结外发，按 NF 的幂等键和已提交水位逐项对账，重放未确认通知，最后恢复新委派。Redis 全失时，从两边各自 PostgreSQL Outbox 重放各自事件。NF 比工坊恢复得更早时，把领先的跨服务引用标记为待核查，阻止继续消费对应结果。运维工具应可列出未决范围、最近证据、待人工处置项与重试期限。
