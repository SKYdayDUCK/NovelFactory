# Agent Workshop 需求分析

状态为待实施设计。适用对象是作者、管理工坊的服务人员，以及通过岗位授权执行小说任务的 Agent。作者默认只和 workshop_manager 对话。例如，作者要求“用三个人物写十个连续场景，先给我看第一幕”；工坊应能说明谁负责卷纲、哪些角色已经反馈、预算还剩多少、第一幕在哪里审阅。作品、本文与创作进度均从 NovelFactory 取证。

## 责任与业务结果

| 需求 | 使用者得到的结果 | 验收证据 |
|---|---|---|
| 建队与恢复 | 用一个预设创建团队。重复启动取回同一在职名单和版本 | 同一幂等键只有一个组织修订和一组入职通知 |
| 分级生产 | 编剧交方案给总导演，卷纲导演分解场景、给演员派发并接收反馈 | 每一跳都有获准方向、消息种类和独立收据 |
| 独立角色认知 | 演员查询公司目录和人物 BELIEF 时看到两种经过授权的视图 | 目录、通知、路由错误和角色上下文均通过秘密隔离反例 |
| 委托与跟踪 | 管理者从一条分工记录追踪到 NF 的作品、分支、任务代际和产物 | 工坊、NF 任一侧重启后仍可从相同 operation_id 对账 |
| 选择性审读 | 发起编剧、导演、角色、文笔、世界、稳定性或统计审核 | 每项审核含模式、来源、判定、理由和可复核的范围 |
| 限额与休眠 | 没有 READY 工作时员工保留雇佣状态，模型执行轮次结束 | 闲置期供应商新增调用、Tokens、费用预留增量均为零 |
| 作者决策 | 对涉及作者立场或正式历史修订的事项显示选项、证据和受影响范围 | 选择记录可追溯；正式修订另有 NF 审批回执 |
| 退出、交接、查看历史 | 离职后失去发信与接单能力，接任者取得新委托；原员工历史可查看 | 旧 session/委派重试拒绝、本人历史保留、旧调用完成后可对账 |

## 用户路径

1. 作者给出创作目标、预算、预设和是否允许自动雇佣。管理者建议岗位与范围，授权模板内的实例由程序开通。
2. 工坊校验图，发布名册版本。总导演委派卷纲导演，卷纲导演通知演员。通知只含可访问的工单引用。
3. NF 按已有任务、租约和冻结上下文执行。工坊看到“等待 A 的观察结果”时记录等待原因；模型进程可以退出。
4. 演员偏离剧本后，NF 检查 ChangePoint、计划版本和语义依赖。工坊按组织边送达异常，安排相应独立审核者。
5. 管理者提供当前采用的计划、正文引用、审核状态，以及当前已知的调用成本。作者设备断线后按游标恢复此视图。

## 范围与非功能需求

工坊负责雇佣、岗位、组内路线、组织状态和跨系统委托。作品事实、正文选择、PLAN、BELIEF、任务执行、供应商调用账本与正式接受都由 NF 持有。界面首期使用 MCP，后续管理 UI 通过相同读模型显示员工状态、工作历史；作品时间线、物品变更与关系图通过带权限的 NF 引用取得。权限目标是任何岗位不能因成为主管、获得技能、知道同事名称而获得作品权限。

延迟和吞吐按消息入库、通知送达、NF 状态对账分别测量。以同一主机、同配置和同负载对照；量产场景的数值门槛应在容量实验前冻结。异常恢复必须证明业务委托零重复、授权撤回有效、UNKNOWN 调用保留。版本、撤权和费用审计属于首次试运行的准入条件。
