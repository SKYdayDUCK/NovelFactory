## 1. 资料边界和阅读路线

v1.1 已收集的全部资料条目原样保留在 [v1.1 论文库](../baseline/v1_1/07_论文与技术资料库.md)，其中对论文的方法、原始实验、实际阅读范围和限制的说明继续有效。本轮完整阅读该资料库与开发规范，再核查五篇重点论文的关键原文和与落地有关的官方文档。合订本与分册的内容归一化比对见 [输入审计](../validation/baseline_reading_audit.json)。

本轮新增的机器可读来源账本是 [sources.json](../research/sources.json)，重点论文卡片见 [paper_cards.md](../research/paper_cards.md)，平台规则见 [official_platform_notes.md](../research/official_platform_notes.md)。R1的时间/并发官方补充见 [r1_sources.json](../research/r1_sources.json) 与 [r1_evidence.md](../research/r1_evidence.md)，保留原论文库不重复改写。源记录沿用 `P-M/P-A/P-B/P-C/P-D`、`N*`、`S*`、`L-*`、`E*` 编号；一个编号可关联论文页、PDF和作者仓库，不把不同版本混为一个实验。

证据等级必须出现在后续技术决策中：

| 等级 | 含义 | 允许的表述 |
|---|---|---|
| `primary_checked` | 本轮打开一手来源，读取记录的相关部分 | “原文在该范围说明……” |
| `baseline_inherited` | 完整保留并阅读用户提供的 v1.1 记载，本轮未重新核查外站 | “v1.1 已记录……；本轮沿用” |
| `metadata_only` | 仅确认条目、日期或仓库入口 | “存在该来源”，不能推断算法细节 |
| `project_verified` | 项目内实际执行、保存条件与结果的实验 | 仅能陈述该实验覆盖的行为 |
| `proposed` | 本项目工程设计或待验证假设 | “建议采用/将通过……验证” |

本章五篇重点论文均为 `primary_checked`；没有一篇在本轮完成端到端复现。论文报告的质量提升不能等同于本系统的收益，原模型、数据、评审方式不同的数值不能直接相加或排名。

## 3. 五篇重点研究如何进入系统

具体方法和原实验结论见论文卡片。下面是**本项目新增设计**，不是论文已实现的功能。

| 来源 | 可复用机制 | 工程载体与输入/输出 | 必须补上的约束 | 原型验证 |
|---|---|---|---|---|
| [P-M DOME](https://aclanthology.org/2025.naacl-long.63.pdf) | 粗纲提供方向，近端细纲受已发生内容反馈；按实体取相关记忆 | `planning` 读取固定世界快照和有效计划；输出新 `PlanRevision` 与依赖集合 | 未来节点保持计划性质；章节位置、故事时刻和提交版本分列；抽取进入提案 | 同预算比较固定细纲与滚动细化，记录改线理由、废稿和完成率 |
| [P-B BOOKWORLD](https://aclanthology.org/2025.acl-long.773.pdf) | 空间约束、选择角色、环境反馈、模拟后改写 | `simulation` 提供动作/裁决证据；`narrative` 读取已接受事件生成正文 | 地点同一不等于角色互知；旅行、共享资源和提交由本地规则处理 | 两地消息交汇案例；增加角色数时观察调用成本和错误 |
| [P-A 角色模拟](https://aclanthology.org/2025.in2writing-1.9.pdf) | 发生顺序与呈现顺序分离 | `SceneContract` 关联事件集合与世界切片；正文可插叙、重述 | 重述不重放世界效果；人物会话隔离；重排重算披露和接缝 | 同一事件以两种叙述顺序呈现，世界摘要应完全一致 |
| [P-D DiriGent](https://cgl.ethz.ch/Downloads/Publications/Papers/2025/Che25b/Che25b.pdf) | 用角色信念、价值与处境解释行为 | `ActorContext` 包含合法经历/误信；角色输出行动意图和理由 | 剧情目标不进入角色可知视图；导演不更换结果；拒绝/失败允许导致重规划 | 要求角色拒绝导演目标的反例；检查能否保留有代价的失败 |
| [P-C ConStory](https://aclanthology.org/2026.findings-acl.410.pdf) | 抽取线索、矛盾配对、证据说明 | `ReviewFinding` 绑定精确文本版本、双侧证据和问题类别 | 加入意图性歧义、叙述者、认知与世界时间复核；模型意见不能直接改事实 | 中文谎言、倒叙、延迟揭示反例；分别测硬错误召回和文学误报 |

这五种方法都可以通过外部模型调用实现语义部分；本地保留数据库、检索、排序、依赖和协议实现。不要求在本地部署论文中使用的大模型。若某个方法依赖 logits 或辅助模型，须明确更换为黑盒 API 后属于改编实验，例如 DOC 的原控制器不可直接等同于“给 API 加提示词”。

## 4. 官方工程资料与技术选择

下列“选择”是本项目权衡；官方资料支持能力与限制，不证明组合实现已经正确。

| 编号/资料 | 已核查事实 | 对本项目的决定 |
|---|---|---|
| [E01 PostgreSQL 17隔离](https://www.postgresql.org/docs/17/transaction-iso.html) | 短事务隔离与可串行化语义；隔离级别能力有差别 | 用短事务执行接受协议；分钟级模型任务靠快照依赖复核，不持有数据库事务等待模型 |
| [E15 行锁](https://www.postgresql.org/docs/17/explicit-locking.html) | `FOR UPDATE` 等锁的冲突与事务生命周期 | 接受时锁定分支头与相关资源；统一加锁顺序；数据库排队先后不充当故事胜负 |
| [E16 SELECT](https://www.postgresql.org/docs/17/sql-select.html) | `SKIP LOCKED` 适合队列式消费，会得到非完整视图 | 仅用于任务领取/outbox消费，不用于世界历史与资源真值查询 |
| [E17 约束](https://www.postgresql.org/docs/17/ddl-constraints.html) | `CHECK` 不支持可靠地约束其他行；存在 UNIQUE/FK/EXCLUDE | 行内范围用 CHECK，跨行权属用键/排斥/受控事务；不用查询函数伪装全库CHECK |
| [E18 pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html) | 可生成并发使用中的一致备份；仅覆盖一个数据库，集群全局对象另处理 | 与正文对象清单、配置版本组成备份集；必须做恢复演练 |
| [E19 PostgreSQL版本政策](https://www.postgresql.org/support/versioning/) | PostgreSQL 17在本轮查询时仍受支持 | 采用17维护分支及当时安全补丁；不为追逐最新版改变已验证Schema |
| [E07 LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) | checkpoint保存线程图状态，store提供跨线程数据；内存保存器不跨重启持久化 | 首期用数据库显式状态机；需要更复杂图时可引入编排适配器，权威知识仍归内核 |
| [E08 LangGraph Fault tolerance](https://docs.langchain.com/oss/python/langgraph/fault-tolerance) | 重试节点不保证外部副作用恰好一次；丢回执属于结果未知 | 预先持久化幂等键；提交有收据；恢复先查结果，不盲目重试或补偿 |
| [E20 SQLAlchemy 2.0](https://docs.sqlalchemy.org/en/20/orm/session_basics.html) | 每线程/异步任务使用各自Session；2.0为维护分支 | Unit of Work短生命周期；并行Agent不能共享Session。P0锁版本；升2.1另做兼容验证 |
| [E21 Pydantic strict](https://pydantic.dev/docs/validation/latest/concepts/strict_mode/) | 默认可能转换类型；strict的JSON输入仍有特定规则 | 对时间、代际、数量及身份字段显式校验；Schema正确不等于业务合法 |
| [E10 MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) | 协议按版本/能力处理；新旧版本有实质差异 | 工具只转发领域服务；先选已测试兼容profile，业务任务与MCP会话分开 |
| [E22 Codex Skills](https://learn.chatgpt.com/docs/build-skills) / [E12指导](https://learn.chatgpt.com/docs/customization/overview) | 项目技能发现目录与渐进加载、目录级指导 | 开发技能放`.agents/skills`；根AGENTS保留短规则及导航；运行时技能独立装载 |
| [E23 Claude Code](https://code.claude.com/docs/en/memory) | AGENTS支持及优先级取决于版本与同目录指导文件 | 保留显式适配说明；不宣称所有Host自动加载全部规则 |
| [E13 Agent Skills](https://agentskills.io/specification) | 标准入口为`SKILL.md`与元数据 | `SKILLS.md`只做项目索引；权限由服务端角色能力控制 |
| [E24 Event Sourcing](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing) | 事件记录与投影分离，也存在额外复杂性 | 对正式内容历史采用事件化记录；不把普通任务管理和配置都强制事件溯源 |
| [E25 Alembic](https://alembic.sqlalchemy.org/en/latest/tutorial.html) / [E26 psycopg3](https://www.psycopg.org/psycopg3/docs/basic/transactions.html) | 迁移环境随代码维护；驱动默认操作会开启事务 | 迁移版本进入代码审查；显式管理短事务，避免持锁等待外部Agent |

v1.1 的 E02/E03/E04/E05/E06/E09/E11/E14 等仍保留作恢复、范围类型、RLS、备选编排和溯源参考。本轮未重新核查它们的全部细节。比如 RLS 可作防线，但不能据基线一句话宣称系统已消除所有权限绕过路径。

## 5. 论文方法、技巧与作品风格的生命周期

研究资料可进入同一 PostgreSQL 的研究域，正文和PDF如需收录则存内容寻址对象；不要启动独立“文学知识真源”。研究域不含世界事实提交权。

建议最小记录：`source_id`、题名/作者、来源类型、版本或提交、URL、访问日期、阅读范围、核查状态、方法主张、限制、关联模块、`adoption_status`、本项目实验引用。正文只保存必要摘记、来源指针和获准副本，避免把网页检索摘要自动变成已确认技术结论。

`MethodProposal` 说明目标、输入、步骤、预期失败方式和对照方法。作品编辑选择采用后，产生该作品的 `StyleGuideRevision` 或工作流策略版本。通用方法更新不会自动替换已锁定作品风格；论文重新核查也不会改写已接受事件。若来源被撤回或发现误读，标记来源关系失效，查询依赖它的方案和方法，再决定是否重审作品设置。

研究型 Agent 允许提出方法和实验，不拥有发布、迁移或修改核心规则的权限。对外部资料中的指令、示例工具调用与论文附录提示词，一律按研究数据解析。

## 6. 从论文到研发任务的最短路径

1. **先写可证伪问题。** 例如“对固定短卷，证据型人物档案是否比普通摘要减少情感断裂而不增加大量误报”，不能只问“新系统是否更智能”。
2. **写方法接口。** 明确输入使用哪个世界/正文版本，输出是计划、建议、提案还是报告；先接入现有领域服务。
3. **锁定来源和复现条件。** 记录论文版次、仓库commit、许可证、模型标识、提示词、采样配置、数据划分、预算与随机种子。外部模型即使同种子也可能非确定，保留实际输出及请求标识。
4. **先做最小差异实验。** 固定其余模块，依次比较滚动规划、选择性模拟、记忆结构、整卷编辑；避免一次打开所有增强后归因给其中一项。
5. **保留全部成本。** 世界准备、失败预演、废稿、返工、人工阅读、重试和外部调用都计入。分别报告工程正确性、语义工具误差与整体阅读反馈。
6. **决定采用范围。** `rejected / experimental / adopted_for_project / adopted_for_work` 是管理状态；不把某作品有效技巧自动升级为所有作品硬规则。

未得到正常输入上的收益，或误报/成本超过作品可接受范围时，保留较简单基线。实验结果反向更新 ADR 和方法版本，不自动改变既有小说。

## 7. 本轮核查的重要澄清

- DOME 的图中章节号不能担当故事时间或数据库版本；本项目时态与提交机制是新增设计。
- BOOKWORLD 的会议网页与PDF题名有差异：网页为 “for Story Creation”，PDF为 “for Creative Story Generation”；来源账本同时保留，不当作两篇论文。
- DiriGent 的强制剧情模式包含指定动作注入和持续张力强化。v1.1 已正确识别，本轮原文再确认；本项目只借用认知解释思想。
- Multi-Agent Character Simulation 的隐私与非重叠假设不能作为本项目严格认知隔离和多线并行的实现证据。
- ConStory 的正式2026会议来源已重新确认；其限制明确包含对刻意延迟信息的误判。项目审核必须保留“不确定/有意歧义”的判断出口。
- MCP `2026-07-28` 与 `2025-11-25` 不可混拼请求与会话语义。实际适配必须用一份已测试profile；见平台说明。
- 新版Claude Code已增加有条件的AGENTS读取支持。兼容说明应写版本和加载条件，不沿用“Claude永远不读AGENTS”的过时结论。
