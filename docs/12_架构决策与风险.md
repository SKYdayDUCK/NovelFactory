# 12｜架构决策与风险

> v1.1 ADR-01–24继续有效。以下 V2-ADR 编号表示实现细化，状态“采用”表示设计决定，不表示完成产品验证。

## 1. 对 v1.1 的调整结论

不改变总体边界。把v1.1候选技术中的PostgreSQL、DB状态机和统一服务门面选作本期实施基线；补全分支身份、推进覆盖、事实提交与叙事发布的可执行语义。SQLite不作为本项目多worker生产数据库或PG并发验证替身。R1进一步把封闭模板的scope守卫、统一读取切面和多进程资源控制前移P1；不改变世界/叙事的总体责任。它仍可用于独立小实验，但本包无需它。

“main”在API里必须先解析成具体branch_id和world_revision_id；它在用户界面是作品canon_branch_id的别名。这样repair分支通过后能切换正式历史，而旧branch及release保持不变。不是把数据库revision改写成故事时间，也不是引入第二个世界数据库。

## 3. 必须保留的设计不变量

- 世界正式事实只能通过WorldCommitService接受，正文/摘要/图查询不能另写一份真相。
- 计划、预演、角色信念与客观事实有不同plane；消息产生、到达和观察各有事件/证据。
- 读写使用精确WorldRef，长期任务携带依赖及代际；取消先撤销接受资格。
- 已接受世界效果在每个选定历史/投影构建中仅一次；一次发生可以多次被叙述。
- 同世界的共享资源竞争先联合裁决，再解决数据库提交；存储顺序不充当剧情胜负。
- 索引过期、世界未推进、信息未知、计划未来、确定none分别表达。
- 旧版本和旧release继续可查询；Retcon不覆盖原记录，也不自动重写旧读者版次。
- 角色权限由服务端和宿主隔离落实；Skills和角色自称不赋予能力。
- 文学判断保留证据、分歧、选择和创作空间；艺术建议不变成无限循环的门禁。

## 5. 本次审查的地位

本包进行了基线覆盖检查、跨文档术语和责任审查、Schema与实例校验、引用路径检查以及小规模机制实验。具体发现与修订记录写在[最终交叉审查](../validation/CROSS_REVIEW.md)。这些验证不会证明真实PG事务、MCP宿主、模型隔离或中文长篇质量已经达标。

不能仅靠纸面消除的问题已保留为上表实验与11的验收任务。后续开发应先完成P1和P2，让最有风险的工程边界与真实创作同时暴露问题，而不是继续无限扩充设计文件。

## 7. R1明确保留的风险和原型门槛

- 依赖模板漏掉负向范围、跨实体约束或新通道，会导致错误的独立性判断。先限于少量可审计命令，不能给自由语义提案一个自报COMPLETE开关。
- 证书准备若先验证旧事实再刷新新token，会出现TOCTOU。必须同一短一致快照采样HEAD、输入和守卫，释放事务后验证，并在接受时复核原采样值。
- 未参与scope bump的legacy writer会破坏新接口。旧strict、新guarded、计划采用、撤权和技术解释变更均须遵守对应统一登记/锁序。
- 同一WorldRef不代表角色known_at、计划、编排或解释相同；缓存/上下文缺任一必要键会造成污染。统一工具还需同时检查操作与plane能力，不能用batch绕权限。
- 分支HEAD仍有短暂串行服务率上限。并行推理和guarded减少的是无谓返工；若实际接受队列成为瓶颈，再比较批量封闭变化包、事务优化或更复杂提交结构，不承诺无限水平扩展。
- 本地LRU、PG队列和SQL图查询的成本取决于历史规模/热点/命中率。1万至100万事件是压测数据档位，没有已测P95/P99或“1000 Agent可稳定运行”的结论。

独立交叉审查见[R1_CONCURRENCY_REVIEW](../validation/R1_CONCURRENCY_REVIEW.md)，A–H及37项待实施检查见[验收矩阵](../validation/r1_case_matrix.json)。有限参考模型仅帮助发现反例，不能关闭真实PG、Host和文学评测门槛。

## 8. 生产返工与恢复决策（2026-11-14）

P6-ADR-01：质量模式的同一场景使用累计修订额度（12 次）与 Codex 诊断额度（2 次），各节点技术修复另限 6 次；问题签名变化不恢复额度。诊断冻结原稿、报告、任务代际和方法历史，仅改变下一次 Flash 任务的局部方法；不接受世界效果、不批准正文、不跳过独立复审。缺材料、重复方法和额度耗尽均停止新派发。代价是复杂问题可能明确暂停，不能用无限付费返工换取表面持续运行。

P6-ADR-02：旧无界实验可由 ADMIN 对固定 WorldRef、board SHA、writer task/generation 和源码提交执行一次 v1 额度迁移。baseline 是新授权的起点，旧修订计数、任务、Attempt 与预算原样保留。确定性授权产物阻止切回旧 board 再次续期；模型不能调用迁移来扩权。反例包括并发 CAS、旧代际、重复授权、非 ADMIN 和回执故障回滚，使用隔离 PostgreSQL 17 核验。

P6-ADR-03：无法恢复输出的已发送任务需要管理员显式承认 UNKNOWN 费用后建立独立替代任务。原 Attempt 和账本不结算、不复写，旧任务取消产物资格，迟到结果被围栏拒绝；新任务保留冻结角色、模型、契约和材料。程序宿主只管理服务与进程寿命，不重发这些请求。完整 Host/HTTP 证明、账单结算和文学验收继续分别核验。

P6-ADR-04：审核证据由真实 MCP 审计与宿主回执共同证明，提示词中的自报查询不授予可信性。核查任务固定原稿、世界与报告，按八题窗口逐项取证。UNKNOWN 不能成为已证实矛盾；语句归属只说明原文存在这种说法，不创建事实或认知。补查只替换审核任务，不替换正文或清零原额度。稳定前缀和按需材料读取减少重复输入，原始来源及全部问题仍保留。

P6-ADR-05：未发布的冻结卷退修采用不可变子版本。独立认知、事实和文学证据全部通过后，原控制者在单个短事务内执行正常正文接受并切换新冻结检查点。edition_ref 只为这一完整候选集合提供受限父章例外，不绕过正式对账、不应用世界效果。父检查点单独留存，新活动链只计入子版本；故障回滚必须同时恢复全部正文选择与检查点。整书盲评失败后由真实编辑提供退修方法，变更后的正文重新取得编辑批准与双路盲评，相同稿件不能重新投票或伪造通过。

P6-ADR-06：可信 HTTP 适配器明确报告 TLS 配置失效且未发送、无任何响应或供应商回执时，NOT_SENT 审计、零费用结算、unsent 标记与任务新代在同一事务提交。只允许两次新代重试，第三次未发送失败保留明确暂停；旧 key 不重发。已为 UNKNOWN、已有返回结果、非可信适配器的自报均不得降为未发送。调度器只豁免同代标记且费用与 Token 均为零的 FAILED 记录，保留其余对账围栏。反例及恢复证书后的真实 Supervisor 续跑由隔离 PostgreSQL 与本地 HTTPS 验证，不连接付费模型。

P6-ADR-07：Windows 对历史只读对象仍执行真实文件刷盘和哈希校验。同对象独立锁保护获取可刷盘句柄所需的临时只读属性转换，恢复属性后再校验，不升级全局共享对象锁；不修改字节或 ACL。新备份文件以可刷盘句柄打开，备份客户端使用明确的 PostgreSQL 17 原生工具目录。进程强杀窗口的属性限制与恢复步骤见[运行手册](implementation/P4_02_恢复与升级运行手册.md)。
