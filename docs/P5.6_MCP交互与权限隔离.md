# Workshop 与 NovelFactory 的 MCP 协议和权限隔离

## 接口状态

当前 NF 项目绑定提供 nf_project_status、nf_resume_project。任务绑定按角色、代际与冻结技能暴露 nf_task_get、nf_context_get、nf_query_batch、nf_artifact_put，以及适用的 nf_change_point_request、nf_rolling_window_submit、nf_change_point_review。具体列表由 McpRuntime.available_tools() 动态生成。以下 aw_* 与 nf_delegation_* 是待实现接口。

| 接口 | 调用主体 | 输入与服务端校验 | 输出、写入与幂等 |
|---|---|---|---|
| aw_roster_get / aw_state_get | 已认证员工、作者观察者 | 从会话获取组织及任期，按可见范围校验游标 | 当前名册版本、可见成员、允许路由、状态引用。增量游标绑定范围 |
| aw_hire / aw_suspend / aw_transfer | 管理者 | preset_ref、slot、expected_org_revision；检查人数与预算上限 | 新组织修订、员工任期、变更收据 |
| aw_message_send / aw_delivery_ack | 受雇员工或系统通知者 | graph_revision、kind、接收者、scope、operation_id；鉴别实际 sender | 一封信一份持久化收据；ACK 绑定具体收件任期 |
| aw_delegate / aw_handoff | 持有相应组织边者 | 目标、资料引用、授权范围、截止时间、额度、idempotency_key | 工坊分工 ID 和跨服务关联号。交接不转移旧供应商调用 |
| nf_delegation_submit（新增窄控制入口） | 与作品和分支绑定的受托应用身份 | NF 自行匹配允许的任务模板、角色、人物、上限、作品、分支和调用方；不接收任意 capabilities | 调用原 RuntimeTaskService / Supervisor 建立授权任务。返回不含私有 token 的 task_id、generation、world_ref、receipt_ref |
| nf_delegation_get（新增窄读入口） | 原委托方或明确观察者 | 同一组织连接、作品、分支、operation_id；重新验权 | 同步 READY/WAITING/终态、可见结果引用、S9 等待原因码 |
| aw_review_decide | 获分配的独立审核者 | 产物版本、证据引用、expected_review_revision、意见；检查作者/审核者身份分离 | 工坊意见收据；如需世界采纳使用 NF 现有审批路径 |

例：NF 提交成功而工坊未收到响应时，工坊将 intent 标为 RECONCILING，然后以原 operation_id 调 nf_delegation_get。NF 找到既有回执时返回原 task_id，不新建任务。若返回不可用，应保持预算预留，根据截止时间延期或升级。网络请求不得置于持有组织/作品数据库锁的事务内。

## 信任边界

NF 内部既有 Principal、TaskBinding、Grant、能力交集和正式接受服务继续逐调用检查。工坊采用可撤销服务绑定，签名材料存放在私有进程内；stdio 传到角色的令牌仅对应其任务代际。组织路由令牌不能传给 NF 当作作品授权。敏感调用记 operation_id、工具名、作用域和结果码，日志省略凭据与角色秘密。

同一员工可以同时有“组织成员”和“小说中人物行动者”两种视图。前者能查目录和授权联系路径；后者按 actor_id、known_at、generation、WorldRef 编译 BELIEF。禁止把目录、管理者报告、审核员意见整段拼进 actor 提示词。需要人物获得新消息时，应提交受控小说业务事件，待 NF 接受后再从该人物的认知切面读取。授权检查失败使用统一不可用响应，避免暴露某个隐藏员工、产物或冲突的存在性。

客户端重连需重新握手，校验双方协议版本、实例 ID 和当前 grant epoch。工具缺失时将该能力标记为未协商，暂停对应委托。测试必须实际经 stdio 完成握手、工具发现、成功调用与负例，并核对 PostgreSQL 收据。分支切换、Grant 撤销、任期终止、故障重投、晚到的旧结果各有单独用例。
