# Agent Workshop 开发阶段与验收计划

P5.6 单独立项。以下 W0–W6 均为实施任务。P6 小规模真实模型试验可直接使用已验收的 P5/P5.5。集成时先冻结 NF MCP 的真实工具清单和权限负例，再给新增委托能力建立独立评审和版本切换点。

| 阶段 / 依赖 | 可独立交付的代码与接口 | 退出标准与证据 |
|---|---|---|
| W0 契约基线 | 固定 NF 基线、安装身份、十岗位与十二技能索引、双侧版本握手 | 使用测试工程实跑当前九个 MCP 工具所允许的调用；记录发现列表与拒绝证据。新接口列出实现差距 |
| W1 目录与雇佣，依赖 W0 | 独立数据迁移、四类预设、员工任期、组织图 CAS、aw_roster_get | 并发雇同一岗位、重复入职、调岗、离职、循环主管全部验过；重新启动名册相同，更新目录不调用模型 |
| W2 分级通信，依赖 W1 | 路由鉴权、信箱、通知、回执、临时路由与应急升级 | 逐边测试正反向和消息种类；越级、过期授权、转授权、密件泄漏、撤权在途均拒绝；队列重放业务效果唯一 |
| W3 委托与恢复，依赖 W0/W2 | aw_delegate、nf_delegation_submit/get、跨系统引用、预算预留 | NF 创建任务后丢响应、工坊先重启、Redis 全失与双方 PITR 落点不同均可复核；一项授权意图只有一个 NF 任务代际 |
| W4 Skills 与审核，依赖 W1/W3 | 五类共享、冻结技能哈希、七种审核模式、回避、限额 | 给作家共享写作法后仍不能用审核批准工具；旧任务使用旧哈希，撤权限行；双重任期、代理自批和跨角色秘密读取拒绝 |
| W5 运行与运维，依赖 W2–W4 | 唤醒管理者、分工进度、状态查询、管理 UI 所需只读投影 | 交接历史、费用、延迟、产物引用与 NF 对齐；相同水位重建一致。空闲时模型调用为零，供应商 UNKNOWN 禁止重发 |
| W6 贯通验收，依赖全部阶段 | Minimal 与 Standard 各一次端到端；Long-form/Audit 用同一验收剧本侧重触发 | 作者目标→建队→分级委派→三个演员→一次偏离→定向修正→独立审核→作者取件。逐项核对跨服务收据、实际模型类型与成本 |

## 故障与容量试验设计

准备两套隔离 PostgreSQL（或同实例两套独立数据库）、Redis、两个 stdio 服务、独立角色运行身份与确定性供应商。每条测试记录两个源码 SHA、迁移版本、图/名册/政策版本、NF WorldRef、task/generation、原始 JUnit 和日志。身份和角色秘密采用可识别的虚构标记，检查响应、错误、目录、审计和模型输入均无越权披露。

在网络发送前、NF 接受后回应前、ACK 前、审核提交与选择 CAS 之间分别注入崩溃。重启并重复投递；判定依据是 PG 中的唯一业务效果和最终任务状态。预留预算小于下一次最大调用时应看到有限的待授权状态。撤权或切换组织图的同一时刻对同一条边发信，以数据库线性化点判断可见性。

以 10/50/200 个员工分别记录消息投递率、端到端 P50/P95/P99、积压排空时间、有效收据数与模型并发。先跑固定并发基准，动态策略使用相同拓扑、同种子和输入。把使用者首次投递、重试请求、最终成功和模型吞吐分别计数。门槛预先登记，未达门槛作为容量结论；继承的 P2/P3 失败项目保持原始阈值。

W6 需一位独立评审复核代码/回执关联、隔离范围、费用和人工待决事项。上线候选先只读映射组织状态，再按单个授权作品开放委托。关闭新委托后，现有 NF 任务继续按自己的状态机运行；保留工坊日志与对账 worker，直至未决收据处理完毕。
