# 动态并行与资源控制

固定并发是默认值。启用示例为 `python scripts/run_supervisor.py --access-file project.json --processor compute --workers 2 --adaptive`。组消费进程支持 `python scripts/run_processor.py --group statistics --workers 2 --adaptive`。命令行上限和注册表上限同时约束控制器。

| 资源 | 采样及决策 |
| --- | --- |
| CPU / 内存 | 使用亲和集、逻辑 CPU 数、cgroup v2 quota、使用时间、throttling、可见的 CPU PSI、进程 CPU 时间、RSS、可用内存、swap、OOM 计数。可用 CPU 数取 affinity 与 quota 的较小者。cgroup 不可读时按宿主采样并将缺测值保留为空。 |
| ComputeWorker | 每个活跃进程有独立数据库引擎和 ObjectStore。父进程短事务领取有截止时间的索引准备租约，子进程按不可变版本计算并重新验证授权和租约，原 Inbox 提交投影。超时旧进程不能覆盖已被新租约收回的版本。 |
| ModelWorker | 使用现有 I/O 执行池。核对最近 429、在途和 UNKNOWN 调用、预留 Token、每分钟请求量、近期服务延迟和待领取任务的预算。模型调用、费用预留、代际、权限仍由 P5 判定。没有凭据时 compute 和 recovery 也可运行。 |
| DB / 可观测性 | 记录当前活动连接、锁等待、长事务、借连接等待、PoolTimeout、采样 SQL 时间。世界与恢复的项目级确定性巡视在一个进程内顺序执行；可跨作品扩展。日志和统计的组消费可在独立线程池和独立 DB 连接预算中伸缩。 |
| 任务与积压 | 记录项目 READY、最老等待、数据库未处理订阅、可见 Redis group 的 lag/pending、计算队列、成功吞吐、失败率及 P95/P99。SQL 统计和采样仅输出计数或时长。 |

控制器从 1 个执行额度开始。观察周期默认为 3 秒，`--sample-seconds` 可调整项目执行器周期。有积压且有余量时每周期增加 1；数据库争用、模型限流/预算不足、内存压力、吞吐下降且 P95 恶化时将新领取额度减半。CPU 有 EMA（新样本权重 0.35），扩容阈值 65%，过载阈值 85%。机器缺少可用内存等关键采样时回到保守额度。已有 future 继续运行。每次目标改变将工作类别、前后额度、决策原因及数值样本写入 `nf_scale_decisions`，事件高频时增量清理 7 天前记录。

Compute 准入与模型准入共享 PostgreSQL 短事务锁并合计计数，原 GLOBAL/WORK/ROLE 硬上限继续生效。派生索引对应 ROLE `derived_index`。原默认三个上限皆为 2。计算在父进程数据库事务以外进行。项目父进程至多 `max(5,workers+2)` 个池连接和 1 个 LISTEN；compute 另有每个子进程 1 个池连接。每个组消费进程的 PostgreSQL 上限是 workers + int(adaptive)，Redis 上限是 workers + 1。跨服务应按实际实例数量汇总配置，并留出 relay、MCP 和数据库管理余量。

测试使用短突发计算索引。采样占短任务批次的比重较大，效果及复现命令见仓库性能报告。
