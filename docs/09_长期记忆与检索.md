## 1. 记忆是受证据约束的访问层

MemoryService 负责组织、查找、压缩和交接已经存在的材料；ContextService 内的 ContextCompiler 负责按任务recipe组合经过授权的上下文，先固定读取切面，再批量访问各领域。两者不拥有另一份世界真相。事件、正式设定、实际认知和正文版本仍由对应领域服务接受。

| 平面/材料 | 主要用途 | 权威边界 |
|---|---|---|
| WORLD | 规则、实体、事件、资源与过程状态 | 由正式世界提交支持；检索索引只是投影 |
| BELIEF | 某人物观察、记忆、信念、私有决定与其变化 | “人物相信 X”可以为真；不推导“X 是世界真相” |
| READER | 某叙事版本和位置之前文本已提供的材料 | 记录披露，不宣称真实读者一定理解或记住 |
| PLAN | 目标、条件路线、未来人物弧线 | 可变计划，不注入角色当作经历 |
| SIMULATION | 隔离分支的假设与候选演化 | 在对应分支有明确身份；不混入 canonical 查询 |
| LITERARY | 原文锚点、解释、声音、未竟后果与编辑决议 | 引用同一事实/文本；不能覆盖正式心理或事件记录 |

通用论文/文学方法另置 `research` namespace。namespace 是命名和权限范围，不是强制再部署一套数据库。外作人物、论文中的故事例子和当前小说实体不因同名自动合并。

## 2. 长期记忆的最小数据对象

### 2.1 五种对象足以起步

| 对象 | 必要字段组 | 生命周期与责任 |
|---|---|---|
| SourceAnchor | source kind、ArtifactRef 或 event/revision ref、locator、所引片段hash | 来源不可变；正文改版产生新锚点，不让旧位置自动指向新句子 |
| SummaryArtifact | 覆盖范围、源引用集合、summary kind、WorldRef、适用时间/读者位置、方法版本、验证状态 | 外部 Agent 产候选；摘要审核后可用于检索；依赖变化需失效 |
| CognitiveRecord | actor、观察/信念/私有决定类型、命题/对象引用、获得时间、来源时间、来源渠道、修订事件 | 权威认知经世界/认知提交接受；不是摘要器可任意改的标签 |
| LiteraryMemoryEntry | entry kind、人物/关系范围、证据锚点、解释/意图、反证、适用叙事位置、审议状态 | 保存文学解释与计划；采纳后仍不改变世界事实 |
| ContextBundle | task/role/actor绑定、WorldRef、story_time、授权/方法版本、选入材料、遗漏/覆盖说明、token预算、sha256 | 服务构建、内容固定；作为本次推理输入与依赖证据 |

SourceAnchor 统一使用 core TextSpan：对原始 UTF-8 解码后的 Unicode code point（不是字形簇）取半开区间 `[start,end)`，`unit=UNICODE_CODEPOINT`；不做 NFC 或换行规范化。ArtifactRef.sha256 对原始字节计算，`quote_sha256` 对切片重新 UTF-8 编码计算。不能混用 UTF-16 code unit、UTF-8 字节和视觉字符定位。PDF/论文使用页码和章节等独立 locator，不伪造正文字符偏移。

MemoryCandidate 与 ReadingCoverage 的最小机读契约见[literary.schema.json](../contracts/literary.schema.json)，正例/拒绝例索引见[literary_index.json](../contracts/examples/literary_index.json)。ACTOR 受众在结构层要求 actor_id、BELIEF plane 和角色经历摘要类型；来源可见性、故事时间、真假分类和语义遗漏仍由服务与审阅核验。`source_coverage` 只说明声明来源集合的覆盖，不表示世界完备。

SummaryArtifact 不是可变的一行 `summary`。每次改写形成新 ArtifactRef，保留源覆盖及摘要类型：事实摘要、角色经历摘要、场景功能摘要、文学解释摘要不能混为一个全知梗概。

### 2.2 文学档案的有限结构

LiteraryMemoryEntry 的起步类别：`ARC_INTENT`、`EDITORIAL_INTERPRETATION`、`OPEN_EMOTIONAL_CONSEQUENCE`、`RELATIONSHIP_ASYMMETRY`、`VOICE_ANCHOR`、`READER_EXPECTATION`、`EDITORIAL_DECISION`。人物名、年龄、库存等直接引用权威实体，不再在档案内维护一份可写副本。

记录示意：

```json
{
  "entry_kind": "RELATIONSHIP_ASYMMETRY",
  "subjects": ["character_a", "character_b"],
  "interpretation": "甲愿有条件合作，乙将合作理解为已经和解。",
  "evidence_refs": ["accepted_private_decision_a", "accepted_belief_b", "text_anchor_42"],
  "counterevidence_refs": [],
  "review_status": "ACCEPTED_FOR_EDITORIAL_USE",
  "scope_note": "作者/编辑可见；角色材料分别经认知视图重建。"
}
```

这是说明语义的局部示例，完整引用形状以 `contracts` 为准。`ACCEPTED_FOR_EDITORIAL_USE` 只表示该解释获准进入编辑材料，不是世界事件接受。

已经接受的“甲当夜决定暂不原谅”属于 BELIEF/私有决定事实；不得因文学档案是派生对象就把它降为随意解释。人物说“我已经原谅”只直接证明发言，其心理真伪按作品叙述约定和证据处理。

## 3. 角色认知隔离与故事时间

### 3.1 服务端生成 ActorContext

ActorContext 请求不接受客户端自行扩大视图。task principal 固定 work_id、branch_id、actor_id、world_revision_id、story_time、policy_version。R1另以KnowledgeCut.known_at表达知情时点，SubjectTime表达所问事件/状态时间；普通角色行动默认两者一致，历史回看或对未来的预测不得改成全知事实。ContextService 只能在 grant 允许范围内取材，返回的引用、错误与元数据遵守相同权限。

构建顺序：

1. 验证任务仍有效且 caller 与 task 绑定，解析固定 WorldRef及当前权限epoch。TaskSpec同代world_ref不可变；动态查询得到不同cut时返回TASK_REBIND_REQUIRED，由控制面新建输入代际后编译。
2. 查询该人物在 story_time 已合法获得的观察、消息、信念和私有决定；保留来源时间与接收时间。
3. 取其合法可见的身体、可用资源、目标与关系视图；不知道的隐患不能作为确知事实出现。
4. 加入适用的经历摘要与原文锚点，只包含当时已有经历；不加入后来形成的作者解释或未来弧线。
5. 返回覆盖、证据及未决状态；保存 read receipt 和依赖指纹，再形成不可变 ContextBundle。

消息形成、到达、观察和相信是不同变化。D27 的旧命令在 D31 才送达，不能因此得知 D30 的所有新局势；收到消息后仍可怀疑。另一条合法现场宣告可以让人物 D30 获知同一内容，不把单一路径的最早到达时间解释为所有渠道的全局禁知期。

倒叙场景按其 story_time 取角色认知，按叙述位置取读者披露。即使 WorldRef 已包含 D50 历史，D20 的角色上下文仍不得获得后来事件。研究材料、simulation 分支、作者弧线和裁决者的私有意图集不进入 ActorContext。

### 3.2 不把检索缺失当遗忘

人物某段经历未被召回，说明本次上下文有限，不能自动生成“人物已经遗忘”的认知事实。确实遗忘、误记或记忆被改变，需有世界规则与获准事件。情感影响也不按统一衰减函数归零。

允许角色基于已有信息猜测、怀疑甚至猜中秘密。系统能约束自己提供的材料并核查明确知识来源，无法证明外部模型永远不会利用预训练知识或类型套路。测试应使用原创合成秘密，避免拿模型熟知作品中的固定谜底假装验证信息隔离。

### 3.3 避免旁路泄露

对无权读取的信息，不输出 `WITHHELD`、隐藏实体数、秘密路径长度、被过滤文档标题或“你尚不知道凶手是甲”这样的错误。公开结果可统一为当前视图无可用依据，详细原因仅写授权审计。

返回示例中的 UNKNOWN 仅描述当前授权视图；不得同时附世界真值作为“校验信息”。不要先给角色加载全知全文，再期望检索过滤撤回秘密。会话与缓存按角色、分支和授权范围隔离；撤权后禁用缓存，即使其内容 hash 没有变。

## 4. 区分事实不定、知识未知、过程待求值与索引陈旧

查询状态采用正交字段，不能用一个 `found=false` 代替全部原因。

| 场景 | truth_status | evaluation_status | knowledge_status | freshness/coverage | 调用方应做什么 |
|---|---|---|---|---|---|
| 已确认且可见的持有人 | DETERMINED | EVALUATED | KNOWN | CURRENT；限定范围 COMPLETE | 可在有效依赖下用于决策 |
| 事件只确定在 D22–D25，查 D23 | UNDETERMINED | EVALUATED | KNOWN | CURRENT；可能 PARTIAL | 使用明确候选/区间，不造单一时点答案 |
| 角色无获知来源 | UNDETERMINED | EVALUATED | UNKNOWN | CURRENT；授权知识范围 | 表达不知道；不能以此推导世界不存在 |
| 运输尚未推进到查询时点 | UNDETERMINED | PENDING 或 BLOCKED | 依视图 | 不由 freshness 替代 | 请求调度/细化，或暂停相关确定性判断 |
| 派生索引没追上所需 revision | 不据索引确定 | 不由索引决定 | 不据索引决定 | STALE 或 ABSENT | 回权威数据；回源失败才阻塞相关任务 |
| 已毁物品的活跃使用能力 | DETERMINED | NOT_APPLICABLE | KNOWN | CURRENT | 返回不适用与历史，不能当作“未查到” |
| 经声明完备的库存确无该物 | DETERMINED | EVALUATED | KNOWN | CURRENT、COMPLETE | 可返回该范围内确定的 none |

`coverage` 的 COMPLETE 仅对声明的作品/作用域/时间/谓词成立，不宣称开放世界完整。`freshness` 为 CURRENT、STALE、ABSENT、NOT_USED；权威查询未用索引时可为 NOT_USED。这些字段的允许组合与完整形状以 [core.schema.json](../contracts/core.schema.json) 和数据模型为准，表中是语义例子。

查询值另用 `value_status` 区分 VALUE、NONE、UNRESOLVED 与 NOT_APPLICABLE；未知/未推进用 UNRESOLVED，不用空集冒充确定不存在。关键资源、唯一性、消息到达和否定前提必须走权威查询或已证明足够新的强投影。top-k 检索空集不能证明不存在。检索系统不负责推进世界；MemoryService 遇 PENDING/BLOCKED 将需求交给 WorldSchedulerService。

## 5. 检索流水线与成本边界

### 5.1 先权限和结构，再检索排序

```text
retrieve(task, query):
    grant = authorize_current_task(task)
    ref = validate_world_ref(task.world_ref)
    visible_scope = derive_view(grant, role, actor, story_time, reader_position)
    exact = structured_lookup_if_applicable(query, visible_scope)
    candidates = authorized_text_and_graph_candidates(query, visible_scope)
    verify_revision_and_projection_coverage(candidates)
    ranked = rank_only_within_authorized_candidates(candidates)
    evidence = expand_required_original_anchors(ranked)
    bundle = budget_and_pack(exact, evidence, unresolved_items)
    persist_read_receipt_and_dependency_fingerprint(bundle)
    return bundle
```

角色不能提交原始 SQL、任意图遍历表达式或绕过 scope 的数据库查询。图遍历在扩展边之前实施可见性过滤，不能通过不可见节点建立捷径后再只删节点。对有权返回的候选排名，也不能把隐藏资料的相似度或全局计数暴露出来。

### 5.2 MVP 检索组件

| 能力 | 首期实现 | 演进条件 |
|---|---|---|
| 精确状态/历史 | PostgreSQL 权威视图与版本化投影 | 先保证历史和权限，不用向量查库存 |
| 实体消歧 | work 内稳定ID、别名表、类型与上下文候选 | 有充分证据再合并；同名不是同实体 |
| 图检索 | 关系表＋有界邻域/递归查询＋边类型过滤 | 实测复杂分析瓶颈后才评估独立图数据库；不得成为第二真源 |
| 中文文本候选 | 标题/别名精确匹配、应用层可重复分词或字符片段索引、权威回源 | 对当前语料测召回；不假定默认语言配置适合中文 |
| 语义检索 | 首期可缺省；后续外部 embedding 或已允许的轻量组件 | 明确数据外发授权、模型版本、费用和召回收益后引入 |
| 重排 | 初期词项/实体/事件/原文锚点等透明启发式 | 只有难检索案例显示收益时用外部语义重排 |

图、全文、向量索引都由同一接受记录派生，记录所覆盖 WorldRef/内容版本和 projector 版本。索引故障时，精确查询回源，模糊召回如实降低覆盖；不能用静默空结果制造“此人无历史”。本地不部署大语言模型，确定性解析、排序、图查询和压缩调度可本地运行；语义摘要仍由外部 Agent 产候选。

图邻域深度、候选数、token上限都是配置。可以从小邻域和少量原文片段起步，但不可把“最多两跳”当作普遍充分性证明。高影响问题允许主动扩大检索，依然受预算和授权范围限制。

## 6. 上下文装配：硬约束先保证，文学材料有取舍

ContextBundle 中分为：任务与范围、必须保持的事实/规则、人物可知材料、事件与计划边界、文学与声音锚点、待定事项、来源清单。不同任务只加载相关层，不向每个 Agent投喂整个世界百科和所有技能。

| 任务模式 | 必需材料 | 按需材料 | 明确排除 |
|---|---|---|---|
| actor | 认知、当前目标、合法反馈、可用资源 | 近期经历与本人声音锚点 | 作者未来计划、他人私密、全知裁决结果 |
| volume plan | 接受历史、过程范围、卷目标、保护承诺 | 候选预演、文学档案、方法资料 | 把候选当已发生的混合摘要 |
| writer | SceneContract、事件后果、许可披露、声音与接缝 | 关键隐藏真相（需单独授权）、必要原文 | 与本场无关的全书秘密 |
| adjudication | 同一冲突组状态、意图、规则、时间资源 | 有依据的语义后果候选 | 文学期望作为胜负规则 |
| reviewer/editor | 精确稿件、相应世界/认知证据、创作约定 | 跨章原文、反例和阅读覆盖 | 未读全文却宣称整体已验收 |

token装配可采用优先队列或背包启发式，但优先级只影响是否进入上下文，不改变事实重要性。关键约束装不下时拆任务或增预算，不能静默截掉后继续宣称完整。对被省略材料记录范围与可按需读取入口；不要把详细秘密标题暴露给无权角色。

文风片段优先来自本作品已接受文本或原创校准样段；锚点应展示对不同对象的说话策略、注意选择和语域，不只是口头禅。人物成长可以改变声音；记忆服务保存依据，不要求新卷与首卷越相似越好。

## 7. 摘要生成、采纳与压缩

### 7.1 生成协议

1. 固定源清单、覆盖时窗/叙事范围和授权视图，保存 ContextBundle。
2. 由 evidence_maintainer 按摘要类型生成候选：事实用事件引用，认知明确主体，文学解释带原文与反证。
3. 本地检查引用存在、hash、字段范围、不可跨分支和未来边界；语义抽样或高影响复核检查漏掉/改写了什么。
4. 接受为 `SummaryArtifact`；记录生成方法、模型/技能版本、输入源以及审议结果。摘要不得调用世界写接口。
5. 更新派生索引；在索引尚未追上时保留 freshness，不把摘要接受误当索引可见性承诺。

允许用既有摘要做定位，但每个新摘要必须可追溯到原始事件或原文锚点，不形成无法还原的“摘要的摘要”链。重要关系转折、长期缺席人物重返、关键伏笔和争议解释必须回读原文；不是每章重复读全书。

### 7.2 压缩保留什么

事实摘要保留发生身份、时间/范围、人物所知与尚未完成过程；文学摘要保留关键选择及代价、未竟情感、关系不对称、重要声线锚点和未回应承诺。单一“他成熟了”“双方已和解”不能取代这些证据。

压缩质量检查采用问题集：能否还原 D20 的人物所知；能否找到未兑现承诺；是否误把乙的误解变成双方事实；关键原文是否仍可召回。流畅、简短或自报置信度不构成质量保证。

情感未竟后果允许回应、回避、转化或本场不表达。不因“发笑”关键词报悲伤清零，也不强制每次出场出现哀悼句。删除某次描写不自动撤销已接受私有决定。

## 8. 失效传播与缓存

### 8.1 失效源与处理

| 变化 | 必须复核的派生对象 | 不应发生的动作 |
|---|---|---|
| 世界 Retcon | 受影响状态、认知、摘要、场景/计划、批准 | 直接改旧摘要world_revision_id冒充新版本 |
| 正文改写 | 原文锚点、声音/解释记录、阅读覆盖、披露、文学批准 | 旧锚点静默指向新句子 |
| 叙述重排 | reader披露、场景功能、接缝及解释适用范围 | 按新章号反推故事时间 |
| 风格或方法变化 | 适用的新任务/未发布稿、方法对照 | 自动改全书事实、旧稿和已跑尝试 |
| 权限撤销 | ContextBundle可取用资格、角色会话和缓存 | 继续因旧token有效而提供秘密 |
| 索引重建 | coverage/freshness、索引版次 | 将重建当世界历史修改 |

正式提交在同一事务内同步写最小失效范围/版本戳；细粒度依赖展开可异步。受影响的新接受或发布必须检查该同步标记，不能在“修订已生效、异步还没标完”的窗口沿用旧 approved 状态。明确查询旧 WorldRef 仍可以使用其有效旧摘要。

### 8.2 缓存键与重新授权

缓存至少按 work_id、branch_id、world_revision_id、plane、actor/reader scope、SubjectTime、known_at、plan/literary manifest、narrative/arrangement/reader cut、查询参数、policy_version、permission_epoch、interpretation_ref、检索/编译方法与tokenizer版本分区。生成内容可按 hash 去重存储，但访问资格每次重新验证，不能因内容相同跨角色共享可见结果。

查询命中还要检查权威范围戳与索引coverage。负向读依赖同样登记，例如“此场景无其他持剑者”；新增相关实体后，旧0行结果使任务需要复核。缓存TTL不能替代权限与版本失效。

## 9. 文学研究资料与作品隔离

研究对象保存 bibliographic metadata、原文/官方链接、实际读取范围、来源类型、方法摘要、实验条件、限制、可复用机制、适用模块及复核日期。未复现的数据标为论文报告；未读原文只标二手线索。完整索引见[10](10_论文与技术资料库.md)。

MethodNote 提案采纳为作品StyleGuide/EditorialPolicy时记录选择理由、生效范围和样段对照；拒绝采用也保留原因。研究库升级只使相关方法需要复审，不自动生成作品世界修订。

Multi-Agent Character Simulation 提供先模拟发生层、再改写呈现层的机制参考；其场景及隐私假设不足以替代本系统的权限和长期历史。文学记忆、跨卷认知和版本隔离属于新增工程设计。[P-A，§3/§6](https://aclanthology.org/2025.in2writing-1.9.pdf)

## 10. 模块接口、错误与测试边界

| 服务/组件 | 端口语义 | 错误策略 | 关键验收 |
|---|---|---|---|
| MemoryService | search、get_anchor、propose_summary、propose_literary_memory | 明确候选/过期/缺证据；不能改世界 | T11、L01/L03/L05；摘要不抹认知差异 |
| ContextService | build_actor、build_writer、build_editor | 能力不足返回不泄密错误；必要材料不足可阻塞 | T02/T04、F06/F13/F19；历史时点与侧信道 |
| RetrievalPlanner | 精确/图/全文候选路由、授权内排序 | 权威查询回退；模糊检索如实降级 | F05/F14；索引陈旧不证明不存在 |
| EvidenceAnchorStore | 不可变来源与定位校验 | 源不可用则相关接受/发布暂停并恢复 | F10、L02；锚点hash与全文覆盖 |
| DependencyService | 登记源集合、负向范围、同步失效标记 | 不确定影响扩大复核，避免漏放 | F04/F17；异步展开窗口 |

确定性测试先采用合成原创秘密、明确句段、时间区间与版本，检查所有可见字段而不仅正文。语义评测测量事实遗漏、认知混淆、重要证据召回和解释锚定，保留误报/漏报案例；文学收益需在实际中文短卷上比较。

P2 MVP 已包含最小人物文学档案、一次长期后果接续和整卷原文覆盖；不等 P4 才开始验证文学记忆。P3再比较无文学档案/仅普通摘要/证据型文学档案，并控制总上下文预算。开放问题包括中文检索方案、档案厚度、压缩更新时机和不同题材中的锚定风险；这些无法仅靠纸面设计定论。

## 11. R1 ContextCompiler：一次输入准备，多次受控读取

ContextCompiler是ContextService内的确定性装配器，不新建记忆数据库，不在读请求中自行生成摘要、启动模拟或等待LLM。外部Agent可以用一次`context_compile`取得成包材料；超过同步成本预算返回编译任务，不通过几十次自由查询逐项拼凑上下文。

编译流程：

1. AdmissionController核对任务、代际、当前grant和资源预算；先限流，再申请数据库连接。
2. 读取版本化recipe和input_manifest；验证当前角色有权使用该recipe，不能因请求ADJUDICATOR获得私有意图。
3. 解析ReadContract并固定ResolvedReadCut。生产任务必须与该代TaskSpec.world_ref一致；缺context_bundle_id不表示可以换版。
4. 按recipe冻结主KnowledgeCut及辅助计划、读者、文学cut；所有世界读取采用同一WorldRef。辅助cut各自独立授权，不将PLAN/全知材料加入ACTOR。
5. 先批量获取强制前提：实体身份、适用规则、资源、过程覆盖、角色合法观察、场景承诺和负向条件；查询返回完整的求值/知识/覆盖状态。
6. 再查授权图邻域、全文候选、原文锚点和已存在摘要；每层限定扫描、边数、输出字节、token和时间。语义top-k只服务候选召回，不承担硬约束证明。
7. 为所有读依赖登记正向引用、负向谓词范围、规则、过程/通道及权限版本；遗漏风险必须显式阻塞或扩大复核。
8. 按预算装配必需段和可选段。硬材料装不下返回CONTEXT_INCOMPLETE或拆任务；不能静默截断后标COMPLETE_FOR_RECIPE。
9. 保存核心ContextBundle、CompiledContext/编译回执和实际源清单；回执指向同一个bundle ID，保留旧2.0工具可读的核心结构。
10. 返回前再次核验当代任务和权限epoch。若中途撤权，弃用缓存结果并返回安全错误；不能以开始时有权为理由交付秘密。

CompiledContext包括主read_cut、`auxiliary_knowledge_cuts`、recipe/input清单引用、已授权section内容、来源、编译/tokenizer版本及可选省略范围。它是交接包，不是新的世界权威。SECTION的FACT/BELIEF等说明仍须与来源一致，Schema通过不能证明内容合法。

| recipe | 主cut与必需材料 | 允许的辅助材料及边界 |
|---|---|---|
| ACTOR | BELIEF，服务端actor与known_at、所在地点/可用资源、目标、合法反馈 | 自身原文/声音证据；禁止PLAN、全知裁决段和他人私密；无辅助全知cut |
| WRITER | 场景WorldRef、事件切片、POV与叙述授权 | 精确READER cut、作品风格/计划摘录；由任务明确授权 |
| DIRECTOR | 已接受世界、局部覆盖和依赖 | 固定PLAN清单、分支比较引用、文学意图；候选单列 |
| ADJUDICATOR | 封闭冲突组、共同起点、相关意图、资源和规则 | 只含本组获准认知；无作者期望胜负作为规则 |
| REVIEWER | 精确草稿、相应事实/认知/披露cut | 独立原文回读、反证和阅读覆盖；不凭摘要自报通读 |
| EDITOR | 固定文本/编排、计划和文学档案 | 获准事实简报；不因角色名取得全世界查询权 |
| MAINTAINER | 本次维护范围的已接受源与状态 | 类型化摘要/证据；环境任务不能借此拿到密封角色意图 |

## 12. 增量读取、缓存层与索引水位

| 层 | 最小实现 | 键/一致性及失效 |
|---|---|---|
| 请求内去重 | 一次compiler/batch共享ResolvedReadCut与实体读取结果 | 请求结束释放，不跨actor或cut混用 |
| 进程内有界LRU | 缓存不可变WorldRef的精确投影片段、原文和编译模板 | 有容量/字节上限；每次返回前重新授权；进程死亡只丢缓存 |
| 派生持久数据 | 状态快照、关系投影、摘要、索引覆盖清单 | 带world/selection/projector/method版本；原文及旧revision不可覆盖 |
| 可选共享缓存 | 多进程重复计算已被压测证实为瓶颈后引入 | 仍是派生层；权限不只靠TTL；故障可回源/有界阻塞 |

固定历史世界的内容不会因HEAD前进而自动过期，但其访问权限可能变化。`LATEST_AT_START`缓存必须先解析HEAD再用固定键；不能缓存一个永久叫latest的世界。PLAN/READER/LITERARY则分别固定自己的清单或编排，单独WorldRef不足以构成其键。缓存失效广播仅加速；当前权限epoch、同步scope守卫及源版本仍是正确性依据。

快照不按“第一章到当前章”全量重算。先寻找与目标选择清单、历史epoch、规则和projector相容的检查点，再重放目标修订中有效且检查点尚未覆盖的事件。故事时间非单调的迟录/Retcon须从最早受影响的相容切面重建；不能仅凭commit_seq较小复用包含错误早期效果的快照。实体历史索引、时态关系索引与有界图扩展见[03](03_数据模型与知识图谱.md)。

索引水位描述“哪些源修订/范围已索引”，过程前沿描述“世界哪些范围已求值”，两者不互相替代。索引未追上时精确状态查询走权威投影/有界重放；模糊搜索可在显式ALLOW_STALE_SEARCH下返回STALE/PARTIAL。关键规则、裁决、资源、否定前提与提交资格不消费陈旧搜索作为充分证据。固定WorldRef可以等其物理投影追平，不能等成包含新事件的另一个修订。

一次批量读固定一个视图。跨WORLD/BELIEF/PLAN材料的编译由recipe组织多组各自授权的子查询，并共享世界切面及显式辅助cut；普通query_batch不能通过逐项换actor或branch越权。游标绑定principal/task/permission epoch、WorldRef、KnowledgeCut和规范化query hash；翻页不重新解析latest。

## 13. 一致性、成本与失败验收

ReadContract由revision选择、process_policy和index_policy三个正交维度组成，详见[14](14_高并发服务与一致性协议.md)。Read-your-writes读取回执所在分支的该修订或后代；canon发生修订推广时不能用另一分支的新HEAD冒充已读到自己的写入。WAIT_EXISTING_ADVANCE只观察已有授权推进任务，不隐式调用模型；超时返回PENDING/安全错误而非NONE。

编译必须记录DB查询次数、扫描行/边、缓存命中、强材料是否完整、原文读取量、token估计、等待/回源/排队时间。动态上下文不得把并行Agent数转成同数量长连接；数据库连接只覆盖短读取/写回阶段。多进程总池预算、背压、成本模型及10至1000逻辑Agent档位见[15](15_并发压测与端到端验收.md)。

重点新增反例：两个subquery之间HEAD前进仍得到一个cut；相同WorldRef而计划清单不同不可命中同键；同内容缓存遇撤权不得返回；硬约束超预算必须失败；历史FIXED未推进不能等待后自动当已推进；READER第80章不能按故事D80读取；未知/秘密错误、条数和游标行为不得泄露。

解释清单interpretation_ref固定reducer/projector/谓词/历法映射。改变事实解释的部署修复须受控推进INTERPRETATION守卫并复核旧资格；仅重新构建相同索引不触发世界修订。要求计划/编排仍被采用的任务还登记ARTIFACT_SELECTION；纯查询旧manifest无需因当前选择变化而失效。
