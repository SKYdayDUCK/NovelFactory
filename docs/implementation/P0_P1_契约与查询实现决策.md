# P0/P1 契约、领域与查询实施决策

状态：已实现并由契约、领域单元及真实 PostgreSQL 集成测试验证；完整阶段结果以总验收报告为准。

## 1. 公共契约只有一个维护源

原 `contracts/core.schema.json`、`literary.schema.json` 和 `temporal_concurrency.schema.json` 字节保持不变。与 `contracts/README.md` 建议的未来 Pydantic-first 路线相比，本轮明确选择 **JSON Schema 作为维护源，Pydantic 作为生成的运行适配层**：避免在未完成全部 R1 类型迁移前丢失 oneOf、条件必填和禁止字段约束。

`novel_factory.contracts.generate` 把维护源生成至 `_schema_bundle.py`，记录每份源文件 SHA-256。`model_for` 从 Schema 创建共享 Pydantic 字段，入口另外执行完整 Draft 2020-12/format 校验；不是用一个宽松字典代替边界。只生成 Python 类型无法表达的部分仍由同一源 Schema 验证，适配层没有第二份手写规则。`model_json_schema()` 返回维护源及其定义引用。构建后 wheel 不依赖仓库当前目录，也不会向 Schema 的示例域名发起网络请求。

门禁命令：

```bash
python -m novel_factory.contracts.generate --check
pytest tests/contracts -q
```

全部原有正反例同时经过生产 JSON Schema 校验入口和生成的 Pydantic 适配入口。反例的期望没有修改。`WorldRef`、`StoryPoint`、`ArtifactRef`、事件、KnowledgeCut 和 ReadContract 均从同一注册表导出，领域层不自行定义同名模型。未知版本显式拒绝；旧记录原文不经破坏性 upcast。

新增 `kernel.schema.json` 只包含本轮实现所需的闭合 payload：InputManifest、PlanManifest 和 CognitiveProposition。HTTP wrapper 与有限命令模板分别有独立、封闭的增量 Schema，通过 `$ref` 复用原公共类型；不存在另一套 WorldRef 或 Event。

## 2. 领域回放与投影

`domain.world.replay(genesis, selected_events, at=None)` 是无数据库、无文件、无网络、无外部模型调用的确定性函数。Genesis 保存正式初始化身份、关系、资源和初始认知；初始化关系引用真实 setup record 的 ArtifactRef，不伪造创世事件。

每个修订固定发生身份到事件版本的选择。借改赠等修订从相同 genesis 加新选择重新构造，旧修订与旧内容保持不变；绝不在已扣除资源的旧状态上再追加“修正效果”。关系段采用精确 tick/phase 半开区间，保留 OPEN/CLOSE 的完整发生来源；资源和生命周期另有历史段。普通查询读取已保存的不可变修订投影，不在每次读取时从创世重放。

首期约束包括：发生/效果身份去重、同效果组键唯一、单值关系排他、正确关闭前版本、关系身份不能关闭后复用、物理包含无环、独立精确数量和单位守恒、非负资源、毁坏不可无规则复活、所有权与持有权分离、同刻冲突不能由输入或数据库到达顺序决定胜负。纯转移资源模板必须按资源和单位总和为零；制造/转换配方没有借此假装完成。

资源余额的闭世界默认零只适用于已经登记、且在查询故事点已创建的账户与资源身份。未知资源返回 UNRESOLVED，已登记但尚未创建的资源返回 NONE；不能把任意 UUID 查询成确定的零余额。直接领域余额 helper 同样拒绝不存在或尚未创建的身份。

BOUNDED/UNSPECIFIED occurrence 原契约仍可读取。明确 RelationTransition.at 可与有界发生分开解释；无已证明生效边界的资源/权属效果保守返回 TIME_AMBIGUOUS，不把 earliest 当真实发生日。时间检查还验证有界区间与严格因果先后相容：无环但 A∈D22–D25 且 A before D20 也会拒绝。通用模糊效果联合求解不在本轮实现范围。

## 3. 角色认知的封闭编码

原 COGNITIVE_RECORD_ADD 只有 statement 字符串。本轮不向旧效果添加字段，而在已注册解释器 `nf-reducer-1` 中支持显式前缀 `NF-PROP-1:`，后接经新增 CognitiveProposition Schema 校验的精确 JSON：subject_id、predicate、object_value，以及可选 subject_time。普通文字 statement 不会被自动解析成结构化状态。

这个形式只表达已接受的认知记录。OBSERVATION 与 BELIEF 是不同记录；听到消息不自动相信，角色误信也不因此变成 WORLD 真相。没有明确 subject_time 时，新获知的当前状态不能追溯改写更早目标点；明确带过去 subject_time 的迟获知允许回答“D51 时知道 D31 的什么”。knowledge_cut.known_at 始终控制材料的获得时刻。外部调用不得修改 actor 绑定或未来时间上限。

动态认知须有合法来源、参与 actor、明确时点，经统一正式接受进入事件历史。此编码不是自然语言抽取器，也不替代角色对消息的语义理解。

## 4. 授权与控制面角色

原 `runtime/query_profiles.json` 的十个角色未改。运行查询从该文件实际读取角色上限，再与当前数据库 grant 的分支、plane、操作能力和时间范围求交；TIMELINE/批量容器不能绕过 PLAN_READ 或 GRAPH_READ。

本地作品初始化使用单独的 `control_operator` 角色。它明确代表作者控制面，要求当前 ADMIN grant；不把原本仅负责编审材料的 chief_editor 默认为全知世界管理员。普通 character_actor 仍仅访问本人 BELIEF，不能切换到 WORLD、PLAN、其他 actor 或超出任务/授权时点。

查询开始采样一次 WorldRef、KnowledgeCut、授权 epoch 和解释版本；返回前再次检查当前 grant 与任务代际。缓存键包括固定修订、完整请求、grant、权限 epoch、policy、解释版本及实际使用的索引水位，缓存命中不免除授权。角色的未知回答不带隐藏过程前沿、客观证据或隐藏计数。未对纳秒级时间、机器负载和网络层侧信道作信息论保证。

## 5. 查询和 Context Compiler

P1 实现 WORLD、BELIEF、PLAN、显式 SIMULATION 分支、POINT 状态、有界时间线、有限深度邻域与同一切面的批量读取。每个主体/谓词有独立 QueryAnswer。未知、已知无值、毁坏后不适用、相关过程尚未求值、派生索引滞后有不同状态。相关前沿采用严格排他边界，D42 前沿覆盖 D41，不覆盖 D42 或 D50。

未来计划是独立固定的 PlanManifest 产物；批准计划不产生世界效果。查询会说明不可恢复毁坏对原计划前提的影响，但不原地修改旧版 APPROVED 状态。P1 不执行计划，也不随意认证 FULFILLED。READ_YOUR_WRITES 的 ArtifactRef 可以指向保存的原始回执副本，但服务必须在权威 receipts 中精确找到同 principal 的 ACCEPT 回执，并验证其修订祖先关系；任意仿造 JSON 不取得读写一致性证明。

Context Compiler 使用绑定 TaskSpec 的 InputManifest，仅装配获准 primary plane。ACTOR 包不含 WORLD/PLAN/READER 辅助段。原 core ContextBundle 和完整 CompiledContext 均通过原 Schema；正文对象先持久化，再在一个短事务中保存 context、依赖、outbox，并绑定 task/generation。相同幂等键和同内容返回原结果，不同内容拒绝；同代不同上下文要求换代。任务输入 WorldRef、故事点和 policy 不会在编译中静默改绑。

预算采用明确的 UTF-8 字节保守估计，不声称已经使用某供应商 tokenizer 或实际计费。必需材料超预算时返回 CONTEXT_INCOMPLETE，不截断约束后声称完整。没有模型或文件写入等待占用采样事务。

## 6. 显式能力边界

- WAIT_EXISTING_ADVANCE 返回 CONSISTENCY_UNAVAILABLE：P1 尚无绑定完整推进范围的后台模拟任务，不能伪造“已有推进任务”句柄。封闭控制面 ADVANCE_SCOPE 是另一条经批准的正式变更路径。
- READER 与 LITERARY 返回明确不支持；正文披露/文学系统属于后续阶段，本轮没有提前实现 P2。
- STATE 与 graph path 仅接受精确 POINT。时间线支持 INTERVAL，复杂区间状态/任意时间逻辑查询留待后续。
- 允许陈旧搜索时，如果水位落后，返回 freshness=STALE 的显式部分候选缺口，不把旧索引事实改标成当前 WorldRef；AUTHORITATIVE 可以直接读取当前修订投影。未建设虚假的独立搜索/向量集群。
- 普通查询 dependency_handle 是按固定切面和请求派生的只读追溯标识；正式接受只使用 Context Compiler 已持久化的依赖句柄及服务端签发证书，普通查询句柄不能授予提交资格。
- 游标是完全不可信的选择器，不是授权凭据；固定原 WorldRef、请求签名和有界 offset，每次翻页重新校验全部授权和时间范围。canon 换枝后不会悄悄混合分页。

真实验证命令及原始结果位于阶段报告和 evidence；上述边界不能被解释为已完成 P2 文学生产或完整多 Agent 模拟。

## 7. R1-B 借改赠的最小端到端审查

`tests/integration/test_history_repair.py` 从真实 R1 青霜剑正式提交历史出发，使用 `fork(REPAIR)`、绑定任务/上下文、`REPAIR_EVENT` 提案、不同 principal 的内容绑定批准、prepare/accept 和 promotion。替换保留 occurrence_id 与 effect_group_id，创建新 event_version_id/representation_id，只增加 D20 的所有权转移；不会追加第二次交剑。测试通过服务查询比较同一 D25 在旧版的 P 所有与新版的 F 所有，同时断言 F 持有、D40 毁坏和资源历史没有重复变化。

旧认知不会因为产权变化而删除或改成全知。该案例的 BELIEF(holder=F) 仍保留原来源 WorldRef 和旧 loan EventRef；修订核验报告显式列出 `retained_cognition_sources`、新的 selected version 及 `HISTORICAL_PROVENANCE_ONLY`，不把旧证据重新认证为当前 WORLD 真相。新的正式认知提交如果仍引用已替换的旧 loan version，会被 `INVALID_EVIDENCE` 拒绝。P1 不宣称已经完成自然语言消息真假或文学台词复核。

其他用例实际推进旧 canon 或修订候选的 HEAD，分别证明 promotion 的两项 CAS 前提：canon 前移返回 HEAD_CONFLICT，候选 HEAD 前移返回 REPAIR_INCOMPLETE，两种情况都不生成推广记录、不丢已有推进。独立批准者撤权后推广返回 APPROVAL_STALE；提案人不能批准自己的修订。成功推广后 LATEST_AT_START 解析新 canon，FIXED 旧 WorldRef 继续返回旧所有权，重复推广请求只产生一次推广记录。

对应原 R1-B-01/02/03/04 的世界内核部分及批准有效性检查。旧发布、全文/摘要文学资格和复杂后继自动改写未纳入本轮实现，不以本测试冒充 R1-B 全部 P2 验收。
