# P4-01 跨卷连续性：统一历史之上的可审阅派生层

## 权威与范围

`ContinuityService` 管理系列的阅读顺序、跨卷记忆线索及其证据。世界事实仍来自原有 `WorldRef`、不可变事件版本、分支和解释器；跨卷服务不执行世界命令、不建立第二条时间线，也不把文学判断写入角色认知。每个返回值和持久化快照均明确标记 `world_effects_applied: 0`。

有限范围为单系列最多 100 个已接受内部发布卷、2000 条记忆条目、2 MB 请求以及一次完整审核最多 2 MB 原文。超限返回容量错误，不以截断原文或延长超时冒充完成审核。它支持人物成长、关系演化、资源历史、伏笔、世界事件继承、读者信息积累六类条目。各类条目共享原有时间类型与证据引用；它不是人物心理或文学质量自动判定器。

每条记忆包含稳定的 `thread_id`、唯一 `entry_id`、卷序号、故事有效区间、实体、解释、证据以及显式前驱。后续演化必须引用本线索最新条目；旧条目只能被后续条目替代其活动地位，不能被删除或改写。人物与资源身份必须存在于声明的世界版本中。条目可引用较早事件以表达长期因果，但来源事件必须有已解决的上界，且不晚于本条目的证据时间上界。

三种证据平面有不同含义：

| 平面 | 允许含义 | 必要来源 |
| --- | --- | --- |
| `WORLD_EVIDENCE` | 已接受事件的引用；解释文字仍非新增事实 | 精确选中的事件版本和来源世界切面 |
| `LITERARY` | 人物、关系、意象或伏笔的编辑解释 | 事件引用或已发布原文锚点 |
| `READER` | 正文曾向读者陈述的信息，可能有误导或不可靠叙述 | 已发布原文及精确 Unicode 范围 |

未来回收时间只允许出现在未解决的伏笔规划中；读者见过某段话不等于角色知道，也不等于世界真相。文学含义由显式审核负责，工程只验证来源、时态、权限、版本及流程完整性。

## 受控发布与恢复

一次系列发布遵循 `prepare → read_candidate → review → publish`：

1. `prepare(principal, payload)` 在当前正式世界切面验证候选、来源、预期系列指针和影响分析，并建立服务器产生的不可变候选。
2. `read_candidate(principal, work_id, candidate_ref, idempotency_key)` 实际交付候选涉及的完整原文。如果新版移除了旧卷，也交付被移除的旧版原文。阅读回执绑定候选、完整交付内容、主体、授权及代际；它不声称理解已经发生。
3. `review(principal, work_id, payload)` 要求与候选作者不同的身份、该审核者自己的完整阅读回执、仍有效的权限，以及逐卷确认受影响的后续卷。拒绝自批、借用他人的阅读回执和漏审影响范围。
4. `publish(principal, work_id, payload)` 在同一事务内再次验证候选与审核、比较系列选择指针、保存不可变快照、推进选择代际、登记失效和 outbox、保存幂等回执。审核身份的权限撤销或代际变化使发布失败。事务前故障不留下系列选择；提交后响应丢失可返回同一正式回执。

写入遵循先锁作品、再授权及分支的顺序，避免并发写入从共享作品锁升级产生死锁。同一系列并发发布只有预期指针仍匹配的一方成功。发布改变的是既有 `selections`、`artifacts`、`invalidations` 和 outbox，不修改世界事件。没有新增数据库表或迁移。

## 已发布前缀与 Retcon

`APPEND` 必须完整保留既有发布引用前缀和记忆条目前缀。纳入系列的卷同时登记 `SERIAL_PREFIX:<volume_id>` 保护指针。`ReleaseService.freeze` 拒绝原地重冻这些卷；原发布仍可按其精确引用导出。需要改文时建立经过正常写作、对账和整卷审核的新卷身份，再用明确原因的 `REVISE` 提交新的系列版本。旧系列与旧原文继续可追溯。这一保守机制不提供原卷身份下的静默替换入口。

Retcon 影响分析以**最近已经审核的系列世界切面**为基线，比较目标切面的事件选择、解释器和谱系。依赖范围同时包含每卷冻结世界中选择的事件，以及该卷记忆条目明确引用的事件；后者可能在该卷原文冻结后才被接受。最早受影响卷及其后所有卷必须重新审核。顺序或发布引用变化同样传播后续影响。

新证据必须绑定当前选择的事件版本。显式修订可以保留旧版原文和旧事件引用，但快照会把它们标记为 `HISTORICAL_SOURCE_ONLY`，不能伪装成当前事实。已审核的历史来源在下一次正常追加中继续保留；不会因为它们已明确被保留为历史而永久阻止后续卷。新的历史变化仍会再次触发影响分析。

`ReleaseService` 还修复了原有提升后的发布兼容问题：正式分支以 `works.canon_branch_id` 为权威。经过合法 `promote` 的修复分支保留创建时的 `REPAIR` 标签，不能因该标签而被误判为非正式分支；未提升分支仍不能发布。

## 权限与任务输入

系列控制与完整快照读取要求非角色身份以及 WORLD、PLAN 视图。目标世界、旧审核基线、每个原文发布和事件来源均检查作品、分支与故事时间授权。`inspect` 返回不可变快照及新影响，分别标记 `NO_NEW_IMPACT_SINCE_REVIEW` 或 `HISTORICAL_EDITION_REVIEW_REQUIRED`；前者只表示本次审阅基线之后未发现新的版本影响。

`read_for_task(principal, task_id, generation, snapshot_ref, budget_bytes=100000)` 提供面向写作/证据任务的受限输入：必须是已经编译上下文、处于当前代际的非角色 WORLD 任务，且该精确快照已经列入不可变任务输入。任务可以固定在快照世界，或采用同枝后代的固定版本。后者要求该快照仍是系列选定版，所有先前选定事件的版本以及世界解释器保持一致。交付保留原快照世界和后续任务世界两份标识。只交付活动线索条目，要求仍有效的事件选择、来源分支授权和不晚于任务的事件/正文时间。历史专用来源不能进入这个当前证据入口。未来 `planned_payoff_at` 字段不交付。总输出按实际 UTF-8 JSON 字节计费，超预算拒绝，任务取消后拒绝。通用原始 Artifact 读取不能用任务输入引用绕过这条受限路径。

## 复现与验收解释

```bash
uv run python -m pytest tests/unit/test_continuity_rules.py -q
uv run python -m pytest tests/integration/test_continuity.py -q
```

第二条命令需要真实 PostgreSQL 17 和 `NF_TEST_DATABASE_URL`；可用项目的 `scripts/with_postgres.py --migrate -- <command>` 包装。集成测试通过真实规划、写作、事实提取、对账、独立审核、内部发布与修复服务构造多卷，不直接插入事件或批准表。

确定性工程夹具不能证明真实模型写作效果，也不能证明人工阅读或文学质量。报告中的工程状态与这两项验收分别记录。
