# P2-05：原文覆盖、文学档案、分层审核与整卷编辑

本实现延续 P1 不可变产物、任务代际、固定 `WorldRef`、当前 grant 和短事务接受边界。依据为 [生产线](../07_剧情与文学生产系统.md) 第 8–10 节、[长期记忆](../09_长期记忆与检索.md) 第 2.2 节，以及 [研发任务卡](../11_研发路线与测试计划.md) 的 P2-05/06。核心 `2.0` 契约保持原样，新输入输出放在 `contracts/editorial.schema.json`，通过同一注册器完整验证。

实现入口是 `application/editorial.py::ReviewService`；`domain/editorial.py` 只做确定性的覆盖、分类、编辑顺序和审核矩阵检查。本模块不写世界事件、资源账、角色认知或 canon 指针；也不代替 `NarrativeService` 的正文硬对账和 `ReleaseService` 的内部冻结。

## 1. 交接与不可变绑定

`EditorialBinding` 固定以下精确输入：

| 维度 | 绑定内容 |
|---|---|
| 世界 | 一个完整 `WorldRef` |
| 计划 | `plan_ref`，场景涉及的节点与所选卷契约 |
| 原文与硬对账 | 有序 `ordered_draft_refs`、逐稿 `reconciliation_refs`、最终逐稿 `ordered_acceptance_refs` |
| 叙事与读者 | `narrative_revision_id`、字符串 `arrangement_version`、`disclosure_revision_id` |
| 风格与文学档案 | 精确 `style_refs` 和 `literary_refs` |

列表顺序、ArtifactRef 的三个字段、摘要哈希和版本必须一致。正文只改一个字、改编排或换披露切面都不能套用旧批准。场景计划可以在新的世界切面继续使用，但需要新的硬对账与审核；若采用新计划，该场景使用的节点、卷身份和卷契约必须保持相容。旧风格原文锚点可由新批准明确采用，不能因“最新技能”更新而自动改变旧稿。

文学档案进入最终批准时，必须针对本次世界与叙事修订及其精确源稿重新确认。当前实现保守要求最终文学档案的 `source_draft_refs` 是本次有序清单的子集；跨卷全文档案自动迁移仍需专门的采用机制。任务读取历史文学记忆允许同枝祖先来源，但原文仍须被当前任务的控制面阅读范围授权，事件证据也必须在采用切面仍被选中。

## 2. 真实原文交付与全文覆盖

调用序列：

1. 控制面创建并编译固定输入的阅读任务，将精确草稿引用列入 `TaskSpec.input_artifacts`。
2. 控制面调用 `NarrativeService.bind_reader_task` 签发不可变 `NARRATIVE_READ_SCOPE`。只知道草稿引用或自行把它列入任务输入不产生读取权。
3. 阅读者调用 `ReviewService.read_text(principal, task_id, generation, draft_ref, start, end, read_mode=..., idempotency_key=...)`。服务实际调用 `NarrativeService.read_text`，得到原文及服务器 `TEXT_DELIVERY`。
4. 服务复核当前角色、grant、代际、context、权限 epoch、准确世界切面及原文字节，记录 `READING_PROVENANCE` 和核心 `ReadingCoverage`，将正文与 `coverage_ref` 一同返回。

`ReadingCoverage.server_receipt_id` 指向本模块保存的 `READING_PROVENANCE` 产物修订 ID。该记录再绑定实际 `TEXT_DELIVERY`、精确草稿与 TEXT、task/generation、grant/epoch、WorldRef 和跨度。审核只接受这些服务器登记的产物 kind；客户端上传同样 JSON 不构成证明。

跨度使用 Unicode code point 半开区间 `[start,end)`，子串 SHA-256 来自未经 NFC、换行或空白规范化的 UTF-8 字节。分段 `FULL_TEXT` 阅读可重叠，服务合并区间后计算缺口。`EXCERPT` 可以支持具体引用，却对全文覆盖贡献零；核心 `SUMMARY` 记录同样贡献零，本服务不提供把摘要登记为原文的路径。另一 reader、另一 generation、另一 ArtifactRef 或另一文本哈希的覆盖不能移用。

幂等重试重新交付相同原文范围，复用已有 coverage 引用；请求内容改变则报 `IDEMPOTENCY_MISMATCH`。调用返回前仍有当前任务与权限复验。

**这些记录证明精确原文范围被提供给任务，不证明理解、审美水平或人类完整阅读。** 重要样卷的真实作者/读者通读报告仍是独立验收证据。

## 3. 分层、分尺度审核

`submit_review` 接受严格 `ReviewSubmission`。维度包括 `FACT / EPISTEMIC / CONTINUITY / LITERARY / STYLE`；尺度包括 `SCENE / CHAPTER / SEAM / VOLUME`。普通 `reviewer` 的 task kind 必须与维度相符；文学编辑不能借此提交全知事实审核。

每份报告先复验任务范围、context、计划资格和精确 binding，再要求 scope 中每篇原文都有本 reader、本 generation 的完整原文覆盖。场景审核只指向一个稿件；整卷审核必须采用完整有序原文清单；接缝审核指向有序稿件对。具体问题必须给原文跨度或同切面的事件/获准材料证据，不能引用未交付的文字。

最终审核矩阵要求：

- 所有稿件均有场景、章节、整卷尺度的覆盖；整卷报告本身覆盖完整顺序。
- 所有稿件均有事实、认知和文学维度的覆盖。
- 每个相邻稿件对均有接缝报告。
- `UNDETERMINED` 不能支持最终批准，未处理的问题不能由模型一句 `PASS` 覆盖。

若报告来自模型，`agent_output_ref` 必须指向该 task 当前 `task_results` 的 `AGENT_CANDIDATE`，且 `summary/issues/counterinterpretations` 与已保存候选完全一致。模型输出仍是候选；最终批准还要通过完整矩阵、编辑链、职责分离及 Narrative 硬对账。

`category` 表达问题主题，`issue_kind` 表达处置类别。`LITERARY_CHOICE` 不能伪装为 `HARD_CONSISTENCY`。系统不包含“悲伤不能笑”“每场必须成长”“相同句式必须删除”等规则，也不把多数票或统一分数当作客观文学真理。可保留反解释、合法不可靠叙述和不同人物的语域；其合理性仍需实际评审者判断。

## 4. 文学记忆与声线

`save_memory` 复用核心 `MemoryCandidate`。当前 P2-05 服务只保存 `memory_kind=LITERARY_MEMORY`、`plane=LITERARY`、面向 WRITER/EDITOR/CONTROL 的解释候选，拒绝把其变成世界摘要或角色信念更新。

支持的最小类别来自既有契约：弧线意图、编辑解释、未竟情绪后果、关系不对称、声音锚点、读者期待和编辑决定。记录包含精确源稿、原文/事件锚点、可选反证、适用范围说明及未决项。人物身份指向权威实体，不另建一份可写的年龄、库存或关系真值表。

`COMPLETE` 只表示这份明确源稿清单已完整交付；源稿缺一段即拒绝。`memory_dependency(candidate, source_draft_refs)` 是公开、确定性的依赖指纹算法，覆盖世界、源稿、证据、反证及方法修订。解释性 summary 是独立不可变 TEXT；不会替换原文。

`read_memory_for_task` 是 Agent 材料适配器使用的受信端口。它要求：当前 task/input/context 与 audience 合法；每个源稿均通过 `NarrativeService._reader_binding`；源事件在当前切面未被替换；summary 和引文哈希正确。返回摘要、证据、反证及未决项，并明确标记 `DERIVED_LITERARY_INTERPRETATION_NOT_WORLD_FACT_OR_ACTOR_BELIEF`。没有源稿阅读范围的任务不能靠猜到 memory 引用取得内容。

`save_style` 由持有明确 `APPROVE` 的编辑控制面采用 `StyleGuide`。每个声音保留 actor 或 narrator 身份、语域说明、至少一个精确原文锚点及允许变化。声音可以随关系和情境变化，不固定为不可突破的人格模板；少量不同声音可并存。方法引用固定版本，自动升级技能不会更新这些产物。

## 5. 整卷编辑与有限返工

`start_editing` 创建不可变 `EDITORIAL_SESSION`，固定初始 binding 与两个预算：`max_rounds`（3–30）及 `max_issue_decisions`。状态选择指针仅记录会话当前决定，不修改历史决定。

`record_decision` 使用 `expected_prior_decision_ref` 作 CAS。两个编辑同时处理同一前态只有一个推进成功，另一个收到 `EDIT_CONFLICT`。阶段依次是：

| 阶段 | 必需证据与决定 |
|---|---|
| STRUCTURE | 完整原文的整卷文学/风格报告；按顺序的场景功能与人物选择证据；至少两个候选方案、唯一所选方案、收益/损失与未采用理由 |
| SEAM | 每个相邻原文对的接缝审核及必要问题处理 |
| LANGUAGE | 结构和接缝已存在；整卷原文阅读报告；保留合法多声部的最终表达决定 |

每个场景功能必须引用该场自己的精确 TEXT。问题处理可为 `REVISE / RETAIN_WITH_REASON / DEFER / RESOLVED`；保留必须有具体理由，声称已解决必须有证据。硬冲突不能 `RETAIN_WITH_REASON` 或 `DEFER` 逃过最终门槛：需要修正及新的独立事实报告，旧的硬问题报告仍不能支持发布。

同阶段只有新正文或新问题/证据决定才能继续。重复同一问题、同一原文和同一决定证据，即使换 issue_id 也报 `EDITORIAL_NO_PROGRESS`；达到轮次或问题预算报 `EDITORIAL_BUDGET_EXHAUSTED`。语义上改写措辞来重开同一争议仍需编辑判断，但总预算始终有界。

最终编辑链必须对最终精确 binding 完成结构、接缝和语言阶段。语言修改若改变了早先批准对象，需要新一轮对正确版本的完整编辑链；不得拿旧结构报告给不同清单背书。旧候选、旧报告和未采用方案均保留。

## 6. 独立批准与发布交接

`approve_editorial` 保存独立 `EDITORIAL_APPROVAL`，嵌套字段 `approval` 为核心 `Approval`，另存精确 binding、审核与决定引用及审批 grant/epoch。不使用原有 world proposal 的 `nf_approvals` 表。

批准者须有明确 `APPROVE` 能力及编辑角色，不能批准自己的最终稿或自己的审核报告。此职责分离说明服务身份不同，不声称模型来源不同或形成独立人类判断。批准还复验所有 NarrativeAcceptance 与 `NarrativeService.validate_for_acceptance`，不得借文学判断豁免世界、认知或时间冲突。

`ReleaseService` 在短事务内调用 `validate_editorial_approval`，传入 world/drafts/reconciliation/narrative/arrangement/style/literary/plan/acceptance/disclosure 的全部精确值。服务复验审批权限、epoch、当前 policy、active 选择、审核任务代际/撤销状态、编辑链当前选择和硬对账。`revoke_editorial` 创建不可变撤销记录并切换 active 指针，旧批准不删除。

## 7. 复现与证据

单元规则：

```sh
.venv/bin/python -m pytest tests/unit/test_editorial_rules.py -q
```

真实 PostgreSQL 17：

```sh
PG_BIN=/path/to/postgresql/17/bin .venv/bin/python scripts/with_postgres.py \
  --data-dir /tmp/nf-p205-pg --log-dir evidence/p2/batch2/editorial --keep -- \
  .venv/bin/python -m pytest tests/unit/test_editorial_rules.py \
  tests/integration/test_editorial_service.py -q \
  --junitxml=evidence/p2/batch2/editorial/editorial_junit.xml \
  --json-report --json-report-file=evidence/p2/batch2/editorial/editorial_pytest.json
```

`tests/integration/editorial_helpers.py` 提供真实服务组成的审核/编辑流程，供 P2-06 测试复用；草稿、TEXT_DELIVERY、Coverage、ReviewReport、决定和批准都通过应用服务产生，没有直接插入批准表或伪造服务器产物。

主要反例覆盖缺口、EXCERPT 零全文覆盖、跨 reader 使用、维度越权、撤权/取消、自己审批自己的审核、硬冲突豁免、跳过结构、无进展审美循环、编辑预算与真实 PG CAS。兼容测试证明旧风格精确引用和原文字节可以在无关世界提交后重新对账、重新审阅与批准；旧批准保持不可复用。

实际结果以 `evidence/p2/batch2/editorial/` 的 JUnit、pytest JSON 和 PostgreSQL 会话日志为准。工程夹具明确不是真实模型或人类文学评测。没有真实作者完整阅读或独立文学金标准时，不报告文学质量提高。
