# P1 事务、对象与修订一致性实施决策

本文件记录相对 v2.0-R1 的具体落地选择，不替换原架构文档与公共契约。最终是否通过以开发报告和实际测试证据为准。

## 1. 单一权威与存储映射

使用 PostgreSQL 17 的模块化单体。SQLAlchemy Core Table/Repository 负责数据映射和 Unit of Work；领域层仅依赖共享契约与纯函数，不依赖 SQLAlchemy、HTTP、文件或模型 SDK。没有另建 ORM 对象作为第二套 WorldRef/Event 契约。

`nf_events` 保存不可变事件正文、内容哈希及持久对象引用；`nf_revisions` 固定选中事件版本、故事前沿、scope 版本、解释版本和状态投影；`nf_revision_events` 以复合外键确认作品/分支/修订/事件身份。`nf_commits`、原请求和回执提供接受追溯。关系、资源、生命周期和认知历史保存在确定性重放生成的版本化 JSONB 投影中，查询不会只读一个无历史的 latest 行。

第一版选择整份不可变修订投影，避免实现一套未经验证的增量更新/回滚算法。普通选择集限制为 2000 事件；受控 repair 逐前缀检查后继命令，限制为 200 个已确定时间、同步生效事件。超限明确失败。该策略不声称具有大历史容量；后续增量投影优化须继续对照同一确定性重放结果。

`0002` 迁移冻结成带 SHA-256 的 56 条 PostgreSQL DDL 快照，不在重建时导入可能已经变化的运行时 metadata。后续数据库演进必须增加迁移；禁止修改旧迁移或对权威历史执行破坏性 downgrade。

## 2. 原子提交与锁顺序

对象共享锁（需要对象时）→维护共享 advisory gate→作品/canon 与相关授权/批准→分支 HEAD→任务→有序 scope。所有公开变更由应用 Kernel 或同事务回调授权；HTTP 不直接写表。备份使用同一维护 gate 的排他会话锁，日常写入持共享锁，不把日常写入串行成全作品排他大锁。

正式接受在 READ COMMITTED 事务中锁住分支 HEAD，重新检查当前权限、批准、任务代际/租约/上下文、证书、故事前沿和不变量。事件、选择、投影、提交记录、实际 scope 递增、同步 invalidation、Outbox、幂等回执、HEAD CAS 与当前任务 ACCEPTED 在同一事务中完成。任何失败整体回滚。

固定初始化是明确的可信本地控制面动作，没有 HTTP 任意初始化/SQL 接口。数据库拥有者与超级用户是运维信任边界，不能把数据库连接凭据分配给外部 Agent。表触发器另外阻止直接 SQL 修改/删除不可变事件、修订、上下文、任务输入等；scope 禁止删除、改身份或回退版本，以防 ABA。

幂等作用域是 work + principal + command_type + idempotency_key，请求完整规范化哈希用于检测同键异内容；目标分支/提案/操作唯一约束另阻止换键重复效果。成功回执先按当前读取资格返回，任务已完成、后续批准撤回不会倒写历史提交。已接受任务再取消明确失败，原键重试仍返回第一次回执。

## 3. 有限依赖守卫

旧 2.0 接口始终 STRICT_HEAD。2.1 只有以下五个服务器登记模板允许 DEPENDENCY_GUARDED：TRANSFER_ITEM、DESTROY_ITEM、RESOURCE_TRANSFER、GUARD_LEAVE、PASS_CLEAR_ROUTE。SET_RELATION、RECORD_COGNITION、ADVANCE_SCOPE、REPAIR_EVENT 使用 strict；未证明完整的模板不会靠调用者声称独立而获得 guarded 资格。

模板由服务器根据正式状态生成 effects、正向依赖、负向范围、共享资源约束、世界覆盖和冲突组。每次实际写入都 bump 所有受影响范围；写守卫仅对确实读取的全局谓词范围冲突，使独立物品可接受，同时负向查询和跨行约束仍捕获 phantom/write skew。禁止接受客户端自填 scope 或任意 payload 作为可信证明。

prepare 在一个 REPEATABLE READ 采样事务中固定 validated WorldRef、授权、批准、规则/解释/历史代际、读写 token 和原依赖指纹。采样之后不刷新 token。服务持久化签发记录，接受只承认该记录匹配的证书；知道 Schema 形状或上传同形 JSON 不获得资格。证书有效期默认 300 秒，以数据库时间判断。

接受在实际 parent 上重建同一模板并核验全部 guard；允许 B≤V≤P 的同分支祖先关系，但不能只比较 branch_seq。原 ContextBundle/批准所绑定的依赖指纹不改写。规则/解释、grant、批准、覆盖或依赖变化导致失效后，必须重新核验；真实前提变化需要新提案。

历史 replacement 原子增加分支 history_epoch，同时写入不可变 revision provenance。旧证书会失效；旧 base 跨历史代际重新 prepare 也失败，不能给旧输入刷新一个当前代际的签名。fork 继承所选不可变 base 的 epoch，而非随便读取某条分支现在的 epoch。

这套 closure 证明仅针对显式封闭的作者控制面命令。P1 没有可任意注入的外部意图通道，也不声称处理完整后台过程、异步消息到达下界或多角色联合行动；这些原设计任务保留在 P2。

## 4. 修订与正式指针

REPAIR_EVENT 只能在独立 REPAIR 分支执行，保留 occurrence/effect_group、新建 event_version/representation，通过替换选择重放，绝不对现状再加一次“修正转移”。提案者不能批准自己的修订；批准绑定具体正文哈希、依赖和当前授权。

修订逐故事前缀重新构造状态并重跑原已登记后继模板：若原来“所有者借剑”的前提在修改后不成立，即使纯效果折叠仍合法，也拒绝该修订。未知命令来源、未证明时间或延迟效果返回不完整；不做任意复杂因果自动修复。

原认知记录与其精确历史来源保留。D20 借改赠不自动改变角色已经持有的信念，也不在编辑时刻给角色补一个获知事件。推广报告列出所引用旧事件版本不再被当前选择的认知来源，标记 HISTORICAL_PROVENANCE_ONLY、world_truth_recertified=false；不能把保留记录当新 WORLD 真相。拿旧选择版本再次提交新认知会被来源校验拒绝。

推广先产生具体重放/比较报告，再在事务中锁作品指针、当前批准资格和两个分支，要求原 canon HEAD 与候选 HEAD 均保持精确值，且候选确由该 canon 基线分叉。批准/批准者已撤销或过期时拒绝。旧分支、旧修订与旧正文继续存在；不实现一般语义合并或整卷发布。

## 5. 来源和正文持久性

只有 SHA-256 校验、文件/目录 fsync 和原子非覆盖发布完成后，数据库才能登记正文。复用已有同哈希文件也重新同步，避免“另一个进程 link 成功但目录尚未持久化便退出”的可见性窗口。正式引用与 GC 通过共享/排他文件锁互斥；孤儿对象可保留一段宽限期后清理，数据库不会为未确认对象先建权威引用。

事件 ruleset_ref/adjudication_ref 必须指向同作品、已登记的正确类型对象。认知 EVENT evidence 必须在其声明 WorldRef 与提案选择历史中真实存在，发生时刻不得晚于获得时刻；ARTIFACT/RULE 证据检查种类、哈希、UTF-8 span 边界和引用文字哈希。结构合法的 UUID 不能单独成为证据。输入/计划 manifest 在登记和读取时均走统一 Schema。

对象库为本机 POSIX 文件系统，不提供跨主机分布式锁或 S3 事务。进程崩溃、断续写入、孤儿清理和 DB 引用竞争已测试；物理断电、存储设备谎报 fsync、整个 PostgreSQL 集群断电重启不在本次执行环境实测范围。

## 6. 任务、调用与恢复

任务状态、每代不可变输入、执行尝试、结果与命令回执均持久化。claim 使用锁与代际，模型等待在事务外；取消/过期阻断旧结果。当前控制面封闭命令可在没有真实模型调用的情况下同步完成验证，世界接受和任务终态同事务；不伪造供应商调用记录。

预算按作品账户、任务金额及 token 同时校验；UNKNOWN 调用保留占用，不能为了重试释放可能已花费的预算。Outbox 至少一次投递，Inbox 在消费者数据库事务内去重；此保证不扩展为任意外部 HTTP/模型副作用的恰好一次。

逻辑备份保存 pg_dump、所有已登记对象、规则/解释、源代码、Schema、查询权限 profile、逐表摘要和对象哈希。隔离空库 pg_restore 后先比对冻结快照，再将未完成任务增加代际并 PAUSED、在途调用保留 UNKNOWN、在途 Outbox 重新排队。恢复会拒绝对象、解释或权限配置缺失；不会在恢复时重新询问模型。

备份不包括集群级角色、WAL/PITR 或生产 HA。应用之外的直接 SQL 运维必须遵守停写/备份安排，不能绕过维护 gate 后仍要求该逻辑快照保证成立。
