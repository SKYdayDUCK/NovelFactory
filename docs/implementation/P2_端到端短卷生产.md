# P2-07：持久化短卷生产编排

本轮提供 `orchestration/short_volume.py` 和 `scripts/run_short_volume.py`。它们实际组合 P1/P2 应用服务，完成一部六场原创工程样卷《潮闸余灯》。适配器、请求、响应和产物均标注 `TEST_FIXTURE`；本轮真实模型环境检查见 `evidence/p2/batch3/model_environment.json`。

## 1. 编排边界

编排器不直接写数据库表，不另建世界状态，也不复用测试目录的辅助函数。世界命令使用现有 `fixtures.run_command` 的真实 Task → Context → Proposal → Certificate → Kernel.accept 协议；这个辅助函数不绕开应用门禁。其他阶段分别调用 PlanningService、WorldSchedulerService、RuntimeTaskService、AgentGateway、NarrativeService、ReviewService 和 ReleaseService。

| 阶段 | 持久交接 | 实际检查 |
|---|---|---|
| 世界准备 | 正式初始设定、RULESET、WorldDossier、独立 DossierReview | 两岸、100 袋北仓、0 袋救济账及独立冬储；幕后人物和物品存在 |
| 卷契约及原计划 | VolumeContract、PlanRevision、当前计划选择、未来任务守卫 | 六节点；完好铜印是未来合作路线前提，清点线独立 |
| 角色行动 | 三个固定角色任务、各自 BELIEF Context、Gateway 调用账、密封 ActionProposal | 林澈知印已赠给自己，贺宁仍持旧信念，苏弦未获该知识；三者目标不同 |
| 交汇与裁决 | 南埠角色实际旅行事件、已登记过程、Interaction、SelectedOutcome | 先共同前态裁决，再 Kernel 原子接受；不按模型返回顺序决定输赢 |
| 合法意外 | 铜印毁坏与 30 袋交付的同一联合发生 | 库存守恒，毁坏物不能继续充作完好凭证；特殊铜楔因果为明确标记的语义夹具决定 |
| 局部重规划 | STALE_PLAN 拒绝、ReplanReport、新 PlanRevision 及采用收据 | 实际毁印引起 2 个节点失效，另外 4 个保持；原计划不修改 |
| 固定写作 | 同一 WorldRef、WritingBatch、ScenePlan、7 个 writer 任务 | 首两场在 barrier 上真实并行；后继需要正式前驱 acceptance；前驱原文实际交付 |
| 正文对账 | TEXT、DraftRecord、实际 TextDelivery、原文抽取 audit、AssertionExtraction、Reconciliation、NarrativeAcceptance | 从实际原文捕获数量、物品状态、持有人、认知、位置及成员关系，再核对世界查询与实际事件效果；未知关键句阻断 |
| 审核和修改 | 全文 Coverage、Gateway 审稿候选、ReviewReport、编辑决定、新稿来源链 | 确定性审稿器从实际原文发现重复；修订任务读取旧稿后删去一次重复 |
| 整卷编辑 | 结构、接缝、语言三个阶段的决定及独立批准 | 6 个场景事实报告、章节认知报告、整卷文学报告和 5 个接缝报告 |
| 文学记忆 | LITERARY_MEMORY、源文及反证、未决项 | 共同灯光可解释为合作起点，不能晋升为人物已完全信任的世界事实 |
| 内部冻结 | ReleaseManifest、ReleaseRecord、本地 outbox、精确原文导出 | 全部 6 场、精确最终批准；同键再试返回同一收据；外部交付 NOT_REQUESTED |

世界规则没有被故事文字扩大：资源非负与守恒、物品生命周期、关系版本、认知来源、作用域推进和权限仍由现有内核校验。通用水利物理或人物心理模拟未在本轮实现。木楔故障及牺牲铜印的因果选择属于显式 TEST_FIXTURE 语义裁决，服务验证它的可接受后果。

## 2. 版本与原文交接

所有写作任务固定同一个最终 `WorldRef`。两条起始线没有前驱，可以并行；第三场同时依赖前两场的正式正文接受，其后为明确的顺序依赖。编排器只在前驱 acceptance 可用后创建后继任务。前驱 draft 引用进入不可变 TaskSpec，控制面通过 `bind_reader_task` 授权读取，Gateway 再实际交付原文字节。

第一场的初稿有一句重复。文学审核任务收到实际全文并给出准确 Unicode span；编辑记录 REVISE 及具体理由；新 writer 的 TaskSpec 固定原稿引用，适配器在收到原文后执行删除。修改前后文本、审核报告和决定都保留。第三场只会使用已经修订并重新对账接受的第一场，不会先生成后继再把前驱文本悄悄替换。

正式成员关系使用已有 `member_of` 多值关系。其接受事件与最终关系列表均保留并被集成测试核对；不把多值关系冒充单值 StateCheck，也不为这部样卷增加临时心理谓词。

## 3. 审核层次及验收解释

独立审核发现初版短卷协调器直接复制了 ScenePlan 的预期检查，实际原文只用于创建 span，无法发现正文被改为“四十袋”或“仍完好”。该实现已经替换，初版证据保留在 `pre-audit-run/` 并显式标为 SUPERSEDED，不能作为最终对账通过证据。

`short_volume_extraction.py` 现在只接收实际交付原文、实体词典与已接受发生的真实 payload，不读取 ScenePlan 的预期数量、状态，也不读取黄金全文。有限中文语法从原文捕获数量和状态后生成 StateCheck，服务再对固定世界求值；交付数量另比对真实事件的双边 RESOURCE_DELTA，成员变化比对实际关系 OPEN 效果。每项都有局部 Unicode span、原句、解析值和事件效果匹配记录。意图、问题、条件规则和原计划引用单独处理，不被当成当前世界事实；未识别必需锚点、未知状态或未覆盖的关键物品/数量/关系句产生 UNCERTAIN，不能接受。

PostgreSQL 反例让真实 writer/Gateway 返回三种错误候选：三十袋改四十袋、已毁印改仍完好、追加“铜汛印焕然一新”。三者都实际存储原文、执行抽取和服务对账，再由正文接受门禁拒绝；拒绝记录保留，世界未变化。单元用例还验证普通修辞变更可通过，不使用整篇哈希匹配假装语义抽取。

这个抽取器只支持样卷公布的有限词汇和句法，未解决任意自然语言的语义完备性。确定性审核也只验证服务交接、原文覆盖与工程门禁，不证明审稿理解能力或文学质量。数据库中的 `semantic_completeness=REQUIRES_INDEPENDENT_REVIEW` 保持不变；真实模型与作者全文阅读分别保留独立门槛。

本轮固定样卷中有 15 次 fixture 调用：3 次角色行动，7 次写作（含一次修订），5 次审稿。Token 为 0、fixture 费用为 0，只说明未发生供应商调用。真实模型成本为 null，不能从 fixture 的 0 推断真实创作成本。

样卷冻结前后均为 7 个世界发生。重复描写三十袋交付仍然只引用同一 occurrence，库存一直为 70/30。修改正文、建立文学记忆、整卷编辑和内部发布不会增加资源事件、重放毁印或倒写认知。

## 4. 复现与证据

先 `uv sync --frozen`，再在安装 PostgreSQL 17 的环境执行：

```sh
uv run --no-sync python scripts/with_postgres.py \
  --pg-bin /path/to/postgresql/17/bin --migrate \
  --log-dir /tmp/nf-short-volume-pg -- \
  uv run --no-sync python scripts/run_short_volume.py \
  --execution-kind TEST_FIXTURE \
  --output /tmp/nf-short-volume-output \
  --object-root /tmp/nf-short-volume-objects
```

`--output` 必须是新目录或空目录，防止覆盖旧证据。完整测试：

```sh
uv run --no-sync python scripts/with_postgres.py \
  --pg-bin /path/to/postgresql/17/bin --log-dir /tmp/nf-short-volume-test -- \
  uv run --no-sync python -m pytest tests/unit/test_short_volume_extraction.py tests/integration/test_short_volume.py -q
```

审核修复后 CLI 原始结果位于 `evidence/p2/batch3/short-volume/final-audit-cli.json`、`final-audit-cli.log`；PostgreSQL 会话配置位于 `final-audit-cli-pg/`。最终完整产物位于 `run/`。此前 `cli.*` 与 `pre-audit-run/` 为保留的历史实验，存在上文说明的对账缺口，已被取代：

- `short_volume.md`：六场可直接阅读的样卷；`release.txt` 为精确冻结原文。
- `run_manifest.json`：三个独立验收状态、调用数量、各版本引用、代码文件摘要。
- `initial_plan.json`、`final_plan.json`、`world_receipts.json`、`events.json`、`final_world.json`。
- `contexts.json`：每个任务实际的权限切面及已编译材料，含三个不同角色视图。
- `process_trace.jsonl`：阶段交接，包括重规划报告、前驱绑定、修改和冻结收据。
- `artifact_index.json` 及 `artifacts/`：精确请求、响应、候选、草稿、覆盖、审核、记忆、编辑与发布对象。
- `checksums.json`：逐文件摘要；`author_feedback.md` 为尚未填写的作者全文评价模板。

反例原文、模型候选、抽取局部 span 与解析值、服务阻断报告位于 `final-audit/short_volume_rejections/`。测试可用 `NF_P2_ACCEPTANCE_EVIDENCE_DIR` 指定持久证据目录；未配置时写入测试临时目录。

不导出 grant 表、Bearer token、private_token、真实 API Key 或数据库连接串。独立检查者可以从源事件、对象哈希与版本清单核对运行结果。

## 5. 继续运行与停止边界

此入口是显式选择的单次工程实验，创建新作品；它不是持久调度守护进程。中断时保留已完成应用服务产物与阶段 trace，具体服务命令可按原身份取回或重试。自动恢复整个编排器的程序计数器不在本入口内；内核与各接受边界的故障/恢复由 P2-08 的独立测试覆盖。

本入口不自动发现凭据、不启用其他 Host、不发送外部消息或发表作品。当前 `BLOCKED_ENVIRONMENT` 结论对应本轮独立环境探测，不能用旧运行清单判断以后环境是否已可用。恢复真实模型实验前需要重新执行环境检查，再使用已有外部模型适配器及预算协议；作者反馈只能由实际阅读者填写。
