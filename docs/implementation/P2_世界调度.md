# P2-02：版本化过程、入站边界与共同前态裁决

## 1. 实现边界

本实现沿用 v2.0-R1 的世界/任务分工与单一 `Kernel.accept` 边界。`WorldSchedulerService` 只构造过程记录、封闭交互、密封意图和结果候选；注册、触发求值、世界效果、推进覆盖与 outbox 仍在内核同一短事务接受。数据库锁或模型返回顺序不选择故事胜者。

新增契约位于 `contracts/simulation.schema.json`，版本为 2.2；`core` 2.0 与 R1 2.1 原文保持可读。旧 `TemplateCommand` 仅增加新模板分支，旧命令字段及批准规则没有放宽。新增 `REGISTER_PROCESS`、`SCHEDULE_ADVANCE`、`JOINT_INTERACTION` 全部采用 `STRICT_HEAD`，未扩大 P1 的 guarded 命令集合。

## 2. 权威数据与恢复

已接受的过程选择保存在不可变 `nf_revisions.provenance.simulation_state` 中，内容含：过程定义的精确 ArtifactRef、触发窗口、世界阶段、计算状态、排他求值前沿、触发结果与已结算交互。该状态通过独立 SHA-256 校验，并纳入世界 revision manifest；它不是可变缓存。

不改变 P1 世界 reducer 的旧事件解释，也不把未来目标伪装成世界事件。普通 P1 命令在已有调度状态的世界中接受时，保留原过程选择；旧 revision 无此字段时沿用旧解释与 manifest。`fork` 复制来源固定版本的过程状态，候选分支此后的结算不污染主分支。数据库与对象恢复天然包含调度记录和对应证据对象。

历史修订触及带已注册过程的世界时，当前版本保守返回 `SCHEDULE_REPAIR_REQUIRED`。原因是旧调度结果和出站消息可能依赖被改写前缀；仅重放世界效果不能证明这些登记和触发仍正确。现有无调度记录的 P1 修订路径继续工作。本轮没有实现任意历史修订后的调度重建，不能沿用未经复核的旧 coverage。

三个新增数据库表只保存不可变编排候选：

| 表 | 内容 | 不表示什么 |
|---|---|---|
| `nf_simulation_interactions` | 固定 WorldRef、故事点、过程闭包、参与槽位、注册状态指纹 | 不表示任何角色已成功 |
| `nf_simulation_intents` | 当前 grant 绑定的 actor、task/generation/context、密封 ActionProposal | 不拥有世界接受资格 |
| `nf_simulation_outcomes` | 有具体依据的唯一已选结果及来源 | 不表示已接受，世界结果由 revision 中闭合交互确认 |

## 3. 过程登记与推进

过程支持旅行/运输、消息、库存生产或消耗、势力行动、交互与环境类型。类型名称只分类，不代表具有通用物理模拟能力。确定性过程使用有限、经 schema 约束的既有命令 recipe；开放语义由受约束外部任务产生候选，再由控制面选择。

`stage_process` 保存过程候选；`propose_registration` 形成待接受变化包。到期时间、期望地点和目标一直是待求值安排。只有内核接受注册后，该过程才进入对应 WorldRef 的登记集合。登记与新入站通道同时递增注册 scope，使旧负向依赖及已签证的相关资格失效。

`prepare_advance` 扫描已注册影响；所有旧 `ADVANCE_SCOPE` 与普通事件命令也经过同一个覆盖检查，不能从旧接口绕过新过程。地域登记同时约束处于该地域/容器中的实体。已知高影响过程不能因为没有进入工作队列就被跳过。

前沿为排他边界 H：入站影响最早到达 H，允许关闭严格早于 H 的前缀；不能在未纳入该影响时接受 H 的交互。未知时延、缺失通道完整性证据或更早未决触发均阻塞相关范围。无相关依赖的独立地区可以继续推进。

消息传播下界不等于实际送达，不自动给角色增加知识。实际观察/信念仍通过 `RECORD_COGNITION` 的已有证据与故事时间检查。消息 recipe 的求值点不能早于通道下界；事件证据也不能来自使用点之后。

## 4. 封闭交互与共同前态

`prepare_interaction` 根据已接受登记求出作用域耦合闭包，收集必要过程及 actor 槽位；调用者不能删掉竞争者来声称完整。相同起点、时间和闭包对应稳定交互身份。每个槽位绑定实际 grant 与 actor。

角色仅可提交本人的 `ActionProposal`，无 `PROPOSE`/`ACCEPT` 世界能力。服务器核验同一 WorldRef、故事点、context、generation、知识证据及当前资格。角色查询仅返回自己的提交状态，不返回他人意图、缺失人数或 actor ID。控制面可以查看完整封闭集合。

未齐备、取消、撤权、旧代或租约失效导致技术等待/拒绝；不会写成角色失败，不改变故事时间。结果选择及正式接受都会复验参与资格。已选结果不可重新抽样覆盖；不同候选必须保留新的审查路径。

`choose_outcome` 保存明确结果来源（规则、夹具或有引用的外部输出）及依据。意图按 actor ID 规范化只稳定输入字节，不赋予胜负优先级。每个原子命令都在同一前态计算，合计支出不能超过该前态库存，同时收到的入账不能替同刻支出融资；唯一物品或排他关系不能有两个结果。失败方的成本如确实发生，必须包含在同一受约束命令集合。

一次 `JOINT_INTERACTION` 可包含多个规则动作、条件不成立的触发以及新出站过程。所有必要过程必须有恰好一项触发决议。新出站影响不能回灌刚关闭的同一 phase；零时延后续反应必须有明确、更晚的因果 phase 或保持阻塞。

## 5. 确定性入口

`evaluate_due` 用注册的 `deterministic_commands` 在共同前态求值。没有必要角色的环境过程可以形成零 actor 槽位交互；存在角色的语义过程仍必须收齐所有注册槽位。

硬前提不成立会形成 `CONDITION_FALSE` 候选并保持零新效果，成功会形成 `FIRED` 候选；两者都需要正式接受。经接受的世界内暂停与模型尚未返回分开：前者有已审查触发结果，后者仍保持原世界阶段。多个确定性过程合计争用同一库存时，不按处理顺序淘汰某一方，而是报告资源冲突，等待显式裁决或修订规则。

首版 recipe 是有限单次触发。需要继续演化时登记有新身份的新过程，或让语义过程明确给出下一触发；不宣称通用连续经济模拟、任意多阶段零时延求解或宏微等效替换已经完成。

## 6. 实际验证

已在真实 PostgreSQL 17.11，`fsync=on`、`synchronous_commit=on` 下执行 `tests/unit/test_scheduling.py` 与 `tests/integration/test_simulation.py`，25 项通过（7 项纯规则、18 项真实数据库；本地最后一次耗时 13.25 秒）。覆盖：

- 入站下界等于 H 与越过 H、未知通道、相关域阻塞和独立域推进。
- 同刻闭包与有明确先后的更早触发不能被后来的组跳过。
- 合计资源超支、同刻收入不得支持支出、动作 phase 不可由数组顺序发明。
- 注册前旧版本无新过程，注册后到期仍不表示交付。
- 三角色密封输入的全部六种返回排列，固定选定裁决的世界余额及效果数相同。
- 参与身份伪造、密封意图覆盖、选定结果篡改与角色读取他人信息均拒绝。
- 接受前注入事务失败，世界效果、过程状态和触发关闭均不产生半成品；同 key 重试不重复效果。
- 缺少角色输入、选择后取消、旧 guarded 证书遭遇新登记时阻断。
- 过程/manifest 哈希、fork 固定状态、带过程历史修订保守阻塞。
- 无角色确定性运输实际接受；路径受阻产生 false trigger，世界库存不因到期而改变。

这些测试证明有限规则与工程边界，不证明开放语义过程识别完整或模型自然生成了夹具军事结果。真实模型实验及整卷产线另记。
