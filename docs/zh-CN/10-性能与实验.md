# 性能与实验

[English](../en/10-performance-and-evaluation.md) · [容量问题 #13](https://github.com/SKYdayDUCK/NovelFactory/issues/13)

## 测量对象

基线为 main `5e322e8af8ddb4465f68f8cab84c9685832461a9`。共享 Linux 主机运行 Python 3.12 和 PostgreSQL 17.11，数据库开启校验和、fsync 和同步提交。历史 AT-30 压测客户端与服务共享两颗可见 CPU。逻辑 Agent 是负载中的调用身份。HTTP 开始发送数、有效业务响应数、独立世界提交数和供应商调用数分别统计。

250 个对象、4 个世界版本的样本中，1、20、100 个查询主体的上下文编译中位耗时分别为 **47.34、60.99、131.92 ms**，每次执行 48 条 SQL。计时从准备好测试世界后开始，首次应用读取时文件系统和数据库缓冲区已经预热。在另一次带探针的 100 主体运行中，契约验证占 354.48 ms 总耗时中的 217.94 ms。单独采集的内存分配峰值为 4,886,725 字节。分析探针本身会影响耗时。

## 单独测量的修改

| 测量对象 | 基线 | 候选 | 条件 |
| --- | ---: | ---: | --- |
| 接受含 5 项的世界变更（附接受证书） | 39.60 ms | 37.39 ms | 12 组配对中位数，SQL 从 60 条降至 57 条 |
| 接受含 100 项的世界变更（附接受证书） | 72.40 ms | 68.35 ms | 同一事务边界，SQL 数同上 |
| 更新 64 个受影响范围 | 36.106 ms | 2.995 ms | 10 组配对中位数，SQL 从 66 条降至 3 条 |
| 更新 256 个受影响范围 | 145.909 ms | 6.984 ms | SQL 从 258 条降至 3 条 |
| 解析仓库随附的路由配置 | 20.501 µs | 14.883 µs | 纯 Python，ABBA 交替测量，P50 |
| 解析 256 条路由规则 | 942.809 µs | 616.548 µs | P50；单条规则的 P99 从 70.706 升至 79.319 µs |

范围更新在原事务内先排序、去重，再一次写入。配对实验在提交前停止计时，随后回滚到同一提案；另行实际提交并重放，核对持久回执。路由解析从匹配项中选出优先规则，省去全量排序。另一个实验在首个无效字段处停止验证，缩短了拒绝请求的耗时，却使单主体成功编译变慢。尝试省略复制也使完整编译变慢。这两种验证器改动均未引入。

## 容量与公平性

| 原始负载 | 结果 |
| --- | --- |
| 10、50、200、500 Agent 混合负载 | 已执行的混合场景均通过业务和对应容量检查。单任务行为由任务和恢复用例另行验证。 |
| 50、200 Agent 过载 | 容量未达标。200 Agent 原门槛按客户端调用开始率计算，最低 950 次/秒，基线为 41.01，候选为 35.39。另计传输层开始发送请求头的速率，分别为 40.08 和 27.80 次/秒。业务恢复通过。两次运行受不同 CPU 竞争影响。 |
| 500 Agent 持续读取 | 两次均以每秒 20 次运行 600 秒，各完成 12,000/12,000 次。P50/P95/P99 分别为 199.65/1071.38/1519.10 ms 和 130.08/649.23/996.15 ms。 |
| 1000 Agent 开放到达 | 每次发起 5,000 项。基线有 1,319 次有效响应、3,627 次 HTTP 429、54 次传输错误；候选分别为 1,434、3,534、32。两次容量均未达标。 |
| 四部作品共享一个模型槽位 | 每部提交 3 个等量任务，最终各完成 3 个。另以 1、2、4 部作品分别测试固定模型、混合模型和供应商故障。 |

200 Agent 基线中，鉴权限流拒绝 716 次，入口拒绝 80 次，业务准入拒绝 46 次，另有 7 次等待超时。数据库连接池峰值为 8/8，观测到事务 ID 锁等待的采样只有 2 次。同一客户端只接收 2,104 字节固定响应时，两次实发率为 140.59 和 153.94 次/秒。客户端和应用都会限制此环境中的速率。负载没有调用商业模型。原容量门槛仍为 **NOT_MET**。一小时及多小时持续测试为 **NOT_EXECUTED**。

## 复现实验

按快速开始准备 Linux 源码环境及 PostgreSQL 17。下面分别执行原版 200 Agent 过载、1000 Agent 开放到达和 500 Agent 持续读。每次使用新的输出目录，同时保留 JSON 与进程退出码，包括容量失败的非零退出。做配对实验时固定 CPU、输入和初始化条件。

```bash
export PATH="$PWD/.venv/bin:$PATH"
out=$(mktemp -d)
NF_POOL_SIZE=8 NF_POOL_OVERFLOW=0 NF_BENCH_DIAGNOSTICS=1 \
python scripts/with_postgres.py --log-dir "$out/pg-overload" -- \
  python -m benchmarks.p2_behavioral_load --agents 200 --profile overload \
    --hot-fraction .8 --arrival-rps 10 --open-loop-rps 1000 --rounds 5 \
    --max-attempts 5 --retry-budget-seconds 30 --gate-scope capacity \
    --service-mode isolated-process --api-processes 1 --output "$out/overload.json"
python scripts/with_postgres.py --log-dir "$out/pg-open" -- \
  python -m benchmarks.p3_open_arrival --agents 1000 --rounds 5 --arrival-rps 1000 \
    --hot-fraction .8 --api-processes 2 --output "$out/open.json"
python scripts/with_postgres.py --log-dir "$out/pg-soak" -- \
  python -m benchmarks.p3_stability --agents 500 --seconds 600 --read-rps 20 \
    --api-processes 2 --output "$out/soak.json"
```

本轮使用真实 Codex CLI 进程连接夹具上游，验证宿主协议。回环 HTTP 适配器实验覆盖发送、取消、供应商故障及用量记录。商业推理、公网供应商时延、已结算账单和真人文学评分需各自取证。[基准程序](../../benchmarks) · [快速开始](02-快速开始.md)
