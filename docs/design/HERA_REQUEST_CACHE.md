# HERA task status and cache scope

The authoritative read remains available with both optional flags off. NF_HTTP_FENCED_TASK_STATUS enables the candidate read that joins the exact task generation and work, locks the work and grant and applies the existing owner and policy checks. HERA-F separately compares optional in-flight task status coalescing enabled by NF_HERA_COALESCE_TASK_STATUS=1. Each process has its own coordinator scoped to one application kernel and one result contract.

The coordinator keys by authenticated principal and grant, installed work/branch binding, task ID and reader mode. A group closes before its own live database read starts. Every member was admitted before the authorization, owner, state and generation checks in that shared read. Requests arriving later start a new group. No successful or failed response is retained after completion. A full map bypasses coalescing; by construction at most 64 groups collect at a time and six admitted calls join a group. An error is propagated to all of its participants. This mechanism cannot cache a BELIEF response, bind context, charge a model, claim a lease or execute a write.

The synchronous gather window is 1 ms. Submitted calls retain bounded operation slots while waiting. The experiment showed why saving a few reads can still cost throughput. Leave the flag off to immediately bypass collecting groups. No persistent data or table migration is needed. Definitions in the tool catalog and their validators are static. Visible tools and knowledge slices depend on live authority and are computed separately. Task submit/cancel receipts remain in the established principal-scoped PostgreSQL ledger.
