# Delegation completion and Workshop wakeups

An authorized Workshop author or manager can subscribe one project wake request to a specific delegation using the existing `aw_resume_project` tool, with an idempotency key in `operation_id` and the previously created UUID in optional `after_delegation_id`. The work must belong to the active manager installation and organization. An ordinary wake without this argument retains its immediate behavior.

Workshop migration `w013` records the optional dependency on the existing `aw_resume_requests` row. Registration and normal receipt reconciliation lock the same delegation row. Registration sees an already settled operation immediately. A later transition to SETTLED makes the subscribed request PENDING within the receipt/hold transaction. An expired or operator-blocked delegation surfaces WAITING_OPERATOR through the manager's bounded sweep. A failed or cancelled task with known terminal accounting may wake the manager to handle its outcome. A changed idempotency key payload is rejected. Receipt replay cannot create another request.

Run the established `aw-manager-run --route <private-route>` worker or use the installed timer. It checks the original submitting grant, current organization ownership, tenure, recovery fence and worker lease before contacting NF. For a completion subscription the worker forwards only the expected installation, organization, work, branch, task, operation, generation, grant epoch and receipt references. No caller selects a launcher or supplies new privileges. NF compares the expected scope against the project-bound resume grant, live installation/role grants, terminal task and exact source receipt before applying the existing project DAG reconciliation. Unrelated delegation submissions are skipped. An old NF peer rejects the additive argument, leaving a recoverable wake in Workshop. Storage and reconciliation are asynchronous: without a running reconciler and manager worker, the persisted subscription waits.

The existing Workshop mailbox carries separately authorized addressed messages. `python -m agent_workshop.notifications publish --grouped` and the matching `receive --grouped` group only already-ready messages, up to 32 per chunk. Publishing commits the SQL outbox first, pipelines Redis hints, then marks the succeeded batch. The receiver validates each referenced message, commits its SQL inbox receipts and then ACKs Redis. A crash may duplicate hints; SQL uniqueness retains one receipt per subscriber/event, and the message body is never stored in Redis. To roll back disable `--grouped`. Keep the Workshop schema where subscriptions exist; rolling the schema back over a live subscription is rejected. Existing mail, cursors and commitments remain durable.
